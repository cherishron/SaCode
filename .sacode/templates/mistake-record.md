## 错误类型分类

### 类型错误 (type-errors)

TypeScript 类型相关的错误。

**常见模式**：
- 类型不匹配
- 类型推断错误
- 缺少类型定义
- 类型断言问题

**示例**：
```markdown
# TypeScript 类型断言导致运行时错误

## 基本信息
| 字段 | 内容 |
|------|------|
| 编号 | M-2026-02-16-001 |
| 时间 | 2026-02-16 14:30 |
| 阶段 | Implement |
| 任务 | T002 - 实现搜索 API |
| 技术栈 | TypeScript |

## 错误描述
### 现象
使用 `as` 类型断言后，运行时出现 undefined 错误

### 错误信息
```
TypeError: Cannot read property 'name' of undefined
```

## 根因分析
### 直接原因
使用 `as User` 强制类型断言，但实际数据可能为 null

### 根本原因
1. 对类型断言的风险认识不足
2. 缺少运行时类型验证

## 解决方案
### 即时修复
添加空值检查

### 根本解决
使用 Zod 进行运行时类型验证

## 预防措施
### 流程层面
- [ ] 使用类型守卫替代类型断言
- [ ] 添加运行时验证

### 文档层面
- [ ] 更新编码规范文档
```

### API 错误 (api-errors)

API 相关的错误。

**常见模式**：
- 接口调用失败
- 参数错误
- 响应格式问题
- 认证授权问题

### 逻辑错误 (logic-errors)

业务逻辑相关的错误。

**常见模式**：
- 条件判断错误
- 循环逻辑问题
- 状态管理问题
- 边界条件处理

### 配置错误 (config-errors)

配置相关的错误。

**常见模式**：
- 环境变量配置
- 数据库连接
- 服务配置
- 构建配置

### 性能问题 (performance-errors)

性能相关的问题。

**常见模式**：
- 查询性能
- 内存泄漏
- 渲染性能
- 资源加载

```
├── by-category/           # 按类型分类
│   ├── type-errors.md
│   ├── api-errors.md
│   ├── logic-errors.md
│   ├── config-errors.md
│   └── performance-errors.md

│   ├── nextjs.md
│   ├── react.md
│   └── ...

    └── YYYY-MM/

```

## 知识提炼流程

### 自动提炼

记录错题后，系统自动分析并建议提炼：

```markdown
### 知识提炼建议

检测到此错题可提炼为以下知识点：

**类型**: 经验教训
**标题**: 避免使用类型断言，优先使用类型守卫
**标签**: typescript, type-safety, best-practice

**摘要**:
类型断言会绕过 TypeScript 的类型检查，可能导致运行时错误。
应优先使用类型守卫（is、instanceof）进行类型收窄。

**详细内容**:
[自动生成的详细说明]

**预防措施**:
1. 避免 `as` 类型断言
2. 使用类型守卫函数
3. 添加运行时验证

---

是否添加到知识库？
[Y] 添加  [E] 编辑后添加  [N] 跳过
```

### 手动提炼

用户可手动将错题提炼为知识点：

```
/pciv-knowledge add [错题ID]
```

## 相关命令

- `/pciv-mistake` - 记录错题
- `/pciv-knowledge` - 查看知识库
- `/pciv-review` - 代码审查
