# Implement 阶段模板

## 阶段目标

按照计划逐步实现功能，确保每个步骤的质量。

## 实施原则

1. **渐进式实现** - 一次只做一个变更，完成后立即验证
2. **工具优先** - 使用代码编辑工具而非直接输出代码
3. **上下文保持** - 每步完成后更新任务状态
4. **并行优化** - 合理并行工具调用提高效率
5. **Server Components 优先** - 优先使用 Server Components，需要交互时使用 Client Components
6. **Tailwind CSS 优先** - 优先使用 Tailwind CSS 类名，避免自定义 CSS

## 组件选择策略

### 核心原则

Tailwind CSS + React 原生组件优先，必要时使用第三方库

### 组件类型决策树

```
需要实现一个 UI 功能
    ↓
能否用 Tailwind CSS + 原生 React 实现？
    ├─ 是 → 使用 Tailwind CSS + React
    └─ 否 → 是否有成熟的第三方库？
        ├─ 是 → 使用第三方库（如 lucide-react, sonner）
        └─ 否 → 创建自定义组件
```

### 组件优先级

| 组件类型 | 使用优先级 | 适用场景 | 示例 |
|---------|----------|---------|------|
| Tailwind CSS + 原生 React | **优先使用** | 基础 UI（按钮、表单、布局） | `<button className="...">` |
| 第三方 UI 库 | 补充使用 | 复杂交互组件（日期选择器、富文本） | lucide-react, sonner |
| 自定义组件 | 特殊场景 | 特定业务逻辑和复用性需求 | PostCard, SearchInput |

## 代码变更规范

### 修改前
1. 使用 Read 工具确认当前内容
2. 理解代码结构和依赖关系
3. 确认修改范围和影响

### 修改中
1. 使用代码编辑工具进行精确修改
2. 每次修改后立即检查语法错误
3. 修改 `src/lib/` 下的工具函数需特别谨慎
4. 修改 API 路由时需确保向后兼容性
5. 修改数据库相关代码时需考虑数据迁移

### 修改后
1. 运行类型检查
2. 运行代码格式化
3. 运行测试验证
4. 更新相关文档

## 常见问题

### Q: 如何处理复杂的任务？

A: 处理复杂任务的建议：
1. 分解任务 - 将复杂任务分解为多个小任务
2. 优先级排序 - 按优先级排序任务
3. 分步实施 - 逐步实施每个小任务
4. 及时验证 - 每步完成后立即验证
5. 调整计划 - 根据实际情况调整计划

### Q: 如何处理阻塞问题？

A: 处理阻塞问题的步骤：
1. 识别阻塞原因
2. 评估阻塞影响
3. 寻找解决方案
4. 调整任务优先级
5. 记录阻塞状态

### Q: 何时更新文档？

A: 文档更新的时机：
- 功能开发完成后 - 立即更新相关文档
- API 变更时 - 同步更新 API 文档
- 架构变更时 - 更新架构文档
- 发布前 - 更新 README 和版本信息
