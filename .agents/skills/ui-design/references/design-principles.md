# 设计原则与项目映射

本文件是独立编写的操作性检查清单，不是任何品牌的官方规范。项目明确需求与设计标准优先；不要把这里的建议变成无条件禁令。

## 先做令牌映射

从真实源码记录以下语义及其现有变量/组件：页面与次级表面、正文与辅助文字、边框、主强调、成功/警告/错误、间距、字号/行高、圆角、控件高度、内容列宽、浮层深度、焦点和动画。没有找到的写“未发现”，不得编造已经存在的变量。

推荐输出表：语义 → 项目实际令牌/组件 → 使用位置 → 亮暗主题差异 → 缺口。不要求项目使用特定变量名或固定像素值。

## 十项原则

1. **语义单一真源**：优先引用项目令牌，不散落颜色、字号和圆角。既有项目没有令牌时只建立目标范围内最小映射，避免借机全局换肤。
2. **层级克制**：正文、辅助信息、表面与分隔承担主要层级；避免所有内容都加卡片、粗边框或重阴影。阴影优先表达浮动和遮挡，不强制删掉已有品牌效果。
3. **强调有主次**：主操作、焦点和链接使用项目强调语义；成功/警告/危险使用状态语义，不仅靠颜色区分状态。多品牌色以产品标准为准。
4. **间距成体系**：复用项目尺度；无尺度时可建议 4px 基础步进，但要标注为建议，不能覆盖已批准系统。相关元素更近，不相关分组留出层级。
5. **内容边界一致**：消息、工具卡、提问卡、错误反馈即使是不同 DOM 同级节点，也应核对共享列宽与对齐。长代码、表格在自身区域滚动，不撑宽整页。
6. **文字稳定易读**：正文与辅助字阶清晰，代码使用项目等宽栈；中文回退字体、行高、长文本换行都需检查。不默认下载专有字体。
7. **几何一致**：圆角、图标、控件高度复用已有分档；hover、等待、错误不让按钮跳动。圆形、pill 等现有设计不是天然错误。
8. **信息密度服务任务**：减少重复角色标签与过度留白，保留必要层级。折叠只减少展示，不删除数据或改变执行；展开详情占满可用宽度，不制造横向溢出。
9. **动效表达状态**：等待、进度与反馈可适量动画；减少动画设置下静止或简化，但保留文字状态。不要以动画掩盖真实错误或无限等待。
10. **可访问且可操作**：可见焦点、可读名称、键盘顺序、状态通知齐备。图标按钮用合适的 aria-label，折叠关联 aria-expanded/aria-controls；不能只用 tooltip 或颜色表达关键语义。控件触达尺寸与对比度按项目目标标准实际检查，不仅凭观感判断合规。

## 组件状态检查

| 组件 | 至少考虑 | 不能发生 |
|---|---|---|
| 消息/结果 | 空、等待、流式、完成、错误、长文 | 等待无反馈、结束重复正文、错误当成功 |
| 工具详情 | 收起、展开、长参数、只读 | 图标无名称、展开区溢出、查看即执行 |
| 提问/表单 | 未答、提交中、成功、失败、取消、失效 | 重复提交、失败自动收起成成功、已答仍可重复执行 |
| 弹窗/浮层 | 打开、焦点进入、关闭、恢复焦点 | 键盘陷死、Escape 意外执行、窄窗关闭键不可见 |
| 操作按钮 | 默认、hover、focus-visible、disabled、busy | 尺寸跳变、禁用仍触发、仅前端回显即称保存 |

已答问题默认摘要收起、工具使用 chevron、内容列居中等均是可选模式：先确认当前产品要求，不能强加给所有界面。

## 技术适配

- Vue runtime/h()、React、静态 HTML 等按项目现状处理，不擅自更换框架。
- Electron/file:// 项目先确认 CSP、模块加载方式、预加载桥和构建期打包约束；不要引入 unsafe-eval 或远程脚本来绕过限制。
- Web 项目沿用现有 bundler 与资源策略；不将某个 Electron 项目的“禁 ESM”误推广到普通 Web。
- 主题可能来自系统媒体查询、class、属性或用户配置，必须找真实入口，不假定 prefers-color-scheme 就代表产品实际主题。
