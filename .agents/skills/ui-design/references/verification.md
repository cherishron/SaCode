# 验证与证据

## 执行前

从项目 manifest、测试文档、CI 与相关测试源码确认实际命令和工作目录。命令不存在时说明，不盲目套用 npm test。不默认安装依赖、请求收费服务、修改用户真实数据、安装应用或发布产品。仅用隔离测试数据，禁止日志或截图暴露凭据及私人内容。

## 按变化选择检查

| 变化 | 自动检查（条件允许） | GUI 检查 |
|---|---|---|
| 间距/列宽/排版 | 样式/构建检查，既有布局断言 | 宽窄容器、长中文/英文/代码、横向溢出 |
| 颜色/令牌 | 引用与主题覆盖检查 | 产品实际亮暗主题、文字/焦点可辨识 |
| 折叠/表单 | 状态转换和失败分支测试 | 鼠标、键盘、只读重开、重复提交 |
| 等待/进度 | 空正文/流式/结束/失败/取消状态测试 | 反馈出现与结束、减少动画、读屏状态 |
| 弹窗/浮层 | 已有焦点/关闭回归 | Tab、Shift+Tab、Escape、焦点归还、窄窗边界 |

不要只测默认成功路径。按照实际组件至少覆盖相关的空态、忙碌、失败、长内容、主题与尺寸变化；与任务无关的场景标不适用，不无限扩展。

## 证据等级不可互换

- 静态检查：只能说明规则、链接或语法等已检查，不能证明实际交互。
- 单元/组件测试：说明所列输入与断言通过，不能证明真实应用入口或后端副作用。
- 隔离页面：说明该测试页面，不自动推广到完整外壳。
- 真实应用：记录入口、版本/源码身份、操作步骤、结果及截图条件。
- 打包态：仅实际运行对应包后才能声称该产物通过。
- 用户视觉认可：只能由实际用户确认；不能从自动截图或检查脚本推断。

读屏、色彩对比或标准合规需要对应实际验证；未做就标“未验证”。GUI 不可用或安全启动失败记录阻塞，不加 --no-sandbox 或关闭 CSP 来冒充通过。

## 只读审查输出

每个问题包含：严重度、文件及位置（有源码时）、证据、用户影响、最小建议、验证方法。严重度建议：阻断使用/危险误导为高；明显交互或无障碍缺陷为中；一致性和可读性问题为低。无法复现的判断写“疑似”，不要列为已证实缺陷。

没有问题时写“本次检查范围内未发现问题”，不宣称整个系统无缺陷。

## 实现/方案输出

1. 范围与模式：方案、实现或审查。
2. 设计依据：真实规范路径和令牌/组件映射；缺失的资料及假设。
3. 结果：已修改文件或拟议方案，不混用完成时态。
4. 验证表：实际命令/入口、结果、失败或跳过原因、证据路径。
5. 剩余边界：GUI、主题、交互、打包态、用户验收哪些未做。

不要填虚构测试数字、截图链接、文件路径或审批结果。审查只读时不为了“验证”修改业务数据。
