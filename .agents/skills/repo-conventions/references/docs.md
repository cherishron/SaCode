# B. docs 规范

目标：文档**可发现、可追溯、不冲突**——同一个事实只有一个权威出处。

## 检查项

- **唯一入口索引**：有一个总入口（如 `docs/README.md`），能导航到所有分类。
- **分类索引**：每类文档有索引页；**新增文档必须同批登记索引**（不许"只加文件不改索引"）。
- **权威顺序**：明确"谁是需求权威、谁是状态真源、谁是历史快照"；带日期的进度/快照不当实时真源。
- **单一真源**：同一事实不在多处各写一份；引用而非复制。
- **存放位置**：规范文档在 `docs/`；一次性产物、运行报告、私有副本**不进** `docs/`（放临时区）。
- **命名**：带日期用 `YYYY-MM-DD`，术语一致。

## 常见问题

- 无总索引或索引与文件不一致（断链、漏登记）。
- 同一事实多处重复，冲突时不知以哪为准。
- 过期快照被当"当前状态"使用。
- 文档散落到仓库根或源码目录。
- 链接断链（文件改名/移动后未同批重写引用）。

## 输出

- **文档地图**：分类 → 入口 → 状态（活跃/历史/冻结）。
- **缺索引 / 冲突 / 断链**清单。
- **建议**：补索引、合并重复真源、迁移散落文档（须授权）、重写引用。

## 边界

- 不擅自移动历史/冻结区文档；改动须先核引用面。
- 历史取证类文档**保持原文**，只可加"冻结说明"或修失效链接（须授权）。
