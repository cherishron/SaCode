# C. 测试规范

目标：测试**可发现、可复现、可区分真伪**——不把"跑不了"当"通过"，不把产物当源码。

## 检查项

- **位置**：测试按所属模块放在该模块的 `test/<功能>/`（或语言惯例的 `*_test.*` 同包）；跨模块的协议/集成测试按被测面归属，不堆在无关模块。
- **命名**：统一后缀（如 `*.test.mjs`、`*_test.cj`）；测试名描述行为而非编号。
- **可入库 vs 一次性产物**：
  - **可入库**：测试源码、可复用驱动、假提供方、**合成脱敏**夹具、静态样例。
  - **不入库**：一次性运行输出、私有副本、日志、快照、二进制、下载数据集 → 统一放临时根（如 `target/tmp/<用途>-<日期>/`）。
- **fixture**：测试数据必须脱敏，禁止真实凭据 / 个人数据；
- **口径**：通过/失败/跳过/取消分别报告；**跳过与阻塞不得记为通过**；不写死随源码变化的总数。

## 常见问题

- 一次性产物（日志、转储、私有目录）混进源码树。
- 夹具含真实凭据或隐私。
- "总体通过数"漂移、把跳过算通过。
- 全量测试**跑不起来**（编译/超时/环境）却按通过宣称——**必须如实标注**。

## 输出

- 测试布局与命名问题清单。
- 产物 / 源码边界违规项（附路径）。
- 口径建议：显式区分 pass / fail / skip / blocked。

## 边界

- 迁移测试文件须先验证测试发现机制与可见性，不机械搬迁造成漏跑。
- 不因为要"清零失败"而删除或跳过测试。
