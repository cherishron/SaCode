# J. 文档维护（生命周期）

目的：文档不是"写完就完"——不维护就会**腐烂**：断链、过期、与现状不符、索引漂移。本领域管"持续维护"，与 B（静态摆放）互补。

## 机制

- **新增即登记**：加任何文档，**同批**登记进分类索引（禁止"只加文件不改索引"）。
- **变更即同步**：完成功能 / 闭合缺陷 / 改口径时，**同批**更新受影响的文档——需求口径→需求文档，进度→台账，取证→证据区，迭代→变更记录。
- **迭代记录**：持续追加变更记录（如 CHANGELOG），保持产品迭代连续。
- **过期处理**：内容过期→标注"历史 / 冻结"或归档，**不删**；快照明确标注"非现行"。
- **权威顺序**：每个领域写明"冲突时以谁为准"。
- **一致性校验**：定期跑一次——断链、漏登记索引、过期未标注、同一事实多处冲突。
- **定期体检**：作为一次可复跑的只读动作（与项目体检同入口）。

## 输出

- **文档维护清单**：新增/更新/过期/归档待办。
- **健康检查**：断链 / 漏登记 / 过期未标 / 索引漂移。

## 边界

- 不擅自动历史 / 冻结区文档；改动前先核**引用面**（谁引用了它）。
- 移动或改名文档时，必须**同批重写引用**并跑断链校验。
