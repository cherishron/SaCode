# I. PRD / 需求管理

目的：让需求文档成为**唯一需求权威**，可追踪、可演进，且不与实现 / 验收脱节。

## 检查项

- **唯一权威**：需求范围与验收口径**只有一处出处**（PRD 或同级需求文档）；其他文档**引用**它，不另抄一份。
- **结构**：需求项**可编号**、可标状态（未开始 / 部分 / 通过 / 阻塞 / 不适用）；并有**唯一跟进台账**记录"推进到哪一步 + 证据"。
- **变更流程**：需求变更**显式**——谁批、何时、影响哪些实现与验收；**不静默改口径**。
- **可追踪**：需求 ↔ 实现 ↔ 验收/证据 能对上（"这条需求在哪实现、拿什么证明"）。
- **快照 vs 现行**：带日期的进度表 / 快照**不是**现行权威；现行口径以需求文档 + 台账为准。
- **验收口径**：明确"什么算完成"——例如四要素（提交 / 入口 / 平台 / 真实运行证据）齐全才算；**测试通过、页面接线、接口宣告各自不足**。

## 常见问题

- 无跟进台账，或台账过期、与实际脱节。
- 同一需求多处口径不一致，冲突时不知以哪为准。
- 拿带日期的快照当"当前状态"。
- 用"测试通过"当需求完成。

## 输出

**PRD 健康检查**：权威性 / 结构 / 追踪 / 变更 / 口径 五个面的缺口清单 + 建议。

## 边界

- 不替用户改需求范围或验收标准；需求变更须用户授权。
- 不把历史快照改写成现行，也不删历史。
