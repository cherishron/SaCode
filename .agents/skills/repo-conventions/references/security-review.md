# L. 安全审查（Security Review）

目的：**专项**安全评审，逐威胁面排查。与 K（综合评审）互补：K 覆盖代码/架构/质量/治理，L 专攻安全。

## 检查清单（逐面）

- **凭据 / 密钥**：真实 API Key、Token、密码、私钥、Cookie、认证头、数据库连接串是否**入库**；测试/夹具/文档/截图里有没有带真值；是否有**明文存储**；凭据注入是否走**环境变量 / 专用本地存储**而非写日志。
- **授权 / 审批**：敏感操作是否**逐次授权**；审批凭据是否**不可伪造**（只能是工单号，不能由调用方自报字符串）；有没有"发任意方法"的旁路通道。
- **沙箱 / 隔离**：执行隔离是否 **fail-closed**（不支持时**拒绝**而非静默降级）；浏览器/子进程有没有用 `--no-sandbox` 之类削弱防护的开关。
- **注入**：命令注入、路径穿越、模板/表达式注入；外部输入是否逐字段校验。
- **进程 / 资源**：子进程边界、超时、取消、背压是否可控。
- **网络 / 出口（egress）**：外部请求是否有白名单/上限；是否可能把敏感数据外发。
- **供应链**：依赖来源是否可信、版本是否固定、构建产物是否可复现。

## 分级

- **P0**：可直接利用的高危（泄露、越权、任意执行）。
- **P1**：重要安全缺口（需要特定前提才可利用）。
- **P2**：硬化项（纵深防御、降低风险面）。

## 红线

- 仅做**授权范围内**的**防御性**审查；不破坏、不越权、不做未授权测试。
- 一旦发现**真实凭据**：立即停止、**不回显其值**，提示用户撤销 / 轮换；不改写历史。

## 输出

**威胁面清单 + 分级发现 + 硬化建议 + 未覆盖项**。发现即附证据路径。
