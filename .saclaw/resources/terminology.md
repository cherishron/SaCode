# 术语表

## PIV 工作流术语

### PIV
**Prime, Implement, Validate** - PIV 工作流的三个阶段。

### Prime 阶段
**准备阶段** - 充分理解项目上下文和需求，制定清晰的实施计划。

### Implement 阶段
**实施阶段** - 按照计划逐步实现功能，确保每个步骤的质量。

### Validate 阶段
**验证阶段** - 全面验证实现质量，确保符合标准和需求。

## 技术术语

### TypeScript
**类型安全的 JavaScript 超集** - 为 JavaScript 添加静态类型。

### React
**JavaScript 库** - 用于构建用户界面的 JavaScript 库。

### Next.js
**React 框架** - 基于 React 的全栈框架。

### Tailwind CSS
**实用优先的 CSS 框架** - 通过类名快速构建用户界面。

### Prisma
**ORM 工具** - 数据库 ORM 工具，用于类型安全的数据库访问。

### API Routes
**API 路由** - Next.js 中用于构建 API 的功能。

### Server Components
**服务器组件** - 在服务器端渲染的 React 组件。

### Client Components
**客户端组件** - 在客户端渲染的 React 组件，支持交互。

## 开发概念

### 渐进式实现
**逐步开发** - 一次只做一个变更，完成后立即验证。

### 工具优先
**使用工具** - 使用代码编辑工具而非直接输出代码。

### 上下文保持
**维护上下文** - 每步完成后更新任务状态，保持上下文清晰。

### 质量优先
**质量第一** - AI 生成的代码必须经过严格审查和测试。

### 人机协同
**协作开发** - AI 作为智能助手，辅助而非替代人类开发者。

## 验证概念

### 类型检查
**类型验证** - 使用 TypeScript 编译器检查代码类型。

### 代码风格检查
**风格验证** - 使用 ESLint 检查代码风格。

### 功能测试
**功能验证** - 测试功能是否正常工作。

### 构建验证
**构建检查** - 验证构建是否成功。

### 性能测试
**性能验证** - 测试性能是否满足要求。

## 项目结构

### src/app/
**应用目录** - 包含页面和 API 路由。

### src/components/
**组件目录** - 包含 React 组件。

### src/lib/
**工具目录** - 包含工具函数和配置。

### prisma/
**数据库目录** - 包含数据库模型和迁移。

## 命令术语

### @文件引用
**文件引用** - 在 iFlow CLI 中引用文件内容。

### !命令执行
**命令执行** - 在 iFlow CLI 中执行命令。

### 自然语言
**自然语言交互** - 使用自然语言描述需求和任务。

## 错误处理

### 类型错误
**TypeScript 错误** - 类型不匹配或类型定义错误。

### 构建错误
**Build 错误** - 构建过程中出现的错误。

### 运行时错误
**Runtime 错误** - 代码运行时出现的错误。

### 逻辑错误
**Logic 错误** - 代码逻辑错误，导致功能不正确。

## 最佳实践

### 单一职责
**SRP 原则** - 每个组件/函数只负责一个功能。

### DRY 原则
**Don't Repeat Yourself** - 避免重复代码。

### SOLID 原则
**面向对象设计原则** - 单一职责、开闭原则、里氏替换、接口隔离、依赖倒置。

### 测试驱动开发
**TDD** - 先编写测试，再编写代码。
