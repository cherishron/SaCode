# 最佳实践

## 概述

本文档提供了使用 PIV 工作流的最佳实践，帮助您提高开发效率和代码质量。

## Prime 阶段最佳实践

### 1. 充分理解需求

**原则**：不要急于开始编码，先充分理解需求

**实践**：
- 与利益相关者充分沟通
- 明确业务目标和技术约束
- 确认验收标准
- 识别潜在风险

### 2. 详细计划

**原则**：制定详细的实施计划，包括风险评估

**实践**：
- 将大任务分解为小任务
- 为每个任务估算时间
- 设置里程碑
- 预留缓冲时间（20-30%）

### 3. 技术选型

**原则**：选择合适的技术方案，考虑性能和可维护性

**实践**：
- 评估多个技术方案
- 考虑技术成熟度和社区支持
- 评估学习成本
- 考虑长期维护成本

### 4. 明确验收标准

**原则**：明确验收标准，便于后续验证

**实践**：
- 使用可测量的标准
- 定义成功指标
- 确认测试方法
- 记录验收标准

## Implement 阶段最佳实践

### 1. 渐进式实现

**原则**：一次只做一个变更，完成后立即验证

**实践**：
- 将功能分解为小步骤
- 每步完成后立即验证
- 保持代码可运行状态
- 频繁提交代码

### 2. 工具优先

**原则**：使用代码编辑工具而非直接输出代码

**实践**：
- 使用 Read 工具确认当前内容
- 使用 Edit 工具进行精确修改
- 避免直接覆盖整个文件
- 每次修改后立即验证

### 3. 上下文保持

**原则**：每步完成后更新任务状态

**实践**：
- 使用 @文件引用保持上下文清晰
- 及时更新任务状态
- 记录完成时间
- 标记阻塞问题

### 4. 并行优化

**原则**：合理并行工具调用提高效率

**实践**：
- 识别可以并行的任务
- 使用并行命令
- 合理安排任务顺序
- 避免依赖冲突

### 5. Server Components 优先

**原则**：优先使用 Server Components，需要交互时使用 Client Components

**实践**：
- 默认使用 Server Components
- 仅在需要交互时使用 Client Components
- 最小化 Client Components 的使用
- 优化组件边界

### 6. Tailwind CSS 优先

**原则**：优先使用 Tailwind CSS 类名，避免自定义 CSS

**实践**：
- 使用 Tailwind CSS 类名
- 避免自定义 CSS
- 使用 @apply 复用样式
- 保持样式一致性

### 5. 持续改进

## 代码质量最佳实践

### TypeScript

- 启用严格模式（strict: true）
- 避免使用 any 类型
- 使用类型注解
- 使用类型守卫
- 定义清晰的接口

### React

- 组件单一职责
- 优先使用 Server Components
- 需要交互时使用 Client Components
- 使用 React.memo、useMemo、useCallback 优化性能
- 避免不必要的重新渲染

### Tailwind CSS

- 优先使用 Tailwind CSS 类名
- 使用 @apply 复用样式
- 响应式设计（grid-cols-1 md:grid-cols-2 lg:grid-cols-3）
- 避免自定义 CSS
- 保持样式一致性

### API 路由

- 使用 TypeScript 类型定义请求和响应
- 完善的错误处理
- 输入验证
- 权限控制
- 适当的 HTTP 状态码
