# 自我验证模板

本文档定义了 PCIV 工作流的自我验证机制，包括即时验证和手动验证两种模式。

## 概述

自我验证是 PCIV 工作流的质量保障机制，在代码变更后自动或手动触发质量检查，形成持续改进的反馈循环。

## 双模式验证

### 模式一：即时验证（自动触发）

**触发时机**：每次代码变更后

**执行内容**：
- TypeScript 类型检查（如项目使用 TS）
- ESLint 检查（如配置了 ESLint）
- 基础语法验证

**输出格式**：
```markdown
### 即时验证
✅ TypeScript 类型检查通过
✅ ESLint 检查通过

变更已验证，可继续开发。
```

或

```markdown
### 即时验证
❌ 发现问题

#### 类型错误
- src/api/search.ts:42 - 参数类型不匹配

建议修复后再继续开发。
```

### 模式二：手动触发

**触发命令**：`/pciv-check [type]`

**检查类型**：

| 参数 | 检查内容 |
|------|----------|
| `all` | 完整质量检查（默认） |
| `type` | 仅 TypeScript 类型检查 |
| `lint` | 仅 ESLint 代码风格检查 |
| `test` | 仅运行测试 |
| `security` | 安全漏洞扫描 |
| `quick` | 快速检查（类型 + lint） |

## 验证项详细说明

### 1. 类型检查

**目的**：确保类型安全

**执行命令**：
```bash
npx tsc --noEmit
```

**检查内容**：
- 类型推断是否正确
- 类型定义是否完整
- 类型是否匹配

**常见问题**：
| 问题 | 说明 | 解决方案 |
|------|------|----------|
| 隐式 any | 参数/变量缺少类型注解 | 添加显式类型 |
| 类型不匹配 | 赋值类型与声明类型不符 | 调整类型定义 |
| 缺少属性 | 对象缺少必需属性 | 添加缺失属性 |

### 2. 代码风格检查

**目的**：保持代码一致性

**执行命令**：
```bash
npx eslint . --ext .ts,.tsx,.js,.jsx
```

**检查内容**：
- 代码格式
- 命名规范
- 最佳实践

**常见问题**：
| 问题 | 说明 | 解决方案 |
|------|------|----------|
| 未使用变量 | 定义但未使用的变量 | 删除或使用 |
| 缺少分号 | 语句缺少分号 | 添加分号 |
| 导入排序 | 导入语句顺序不规范 | 重新排序 |

### 3. 功能测试

**目的**：验证功能正确性

**执行命令**：
```bash
npm test
```

**检查内容**：
- 单元测试
- 集成测试
- 边界测试

### 4. 安全扫描

**目的**：发现安全漏洞

**执行命令**：
```bash
npm audit
```

**检查内容**：
- 依赖漏洞
- 代码安全问题

## 反馈循环机制

### 即时反馈

```markdown
### 代码变更验证

文件: src/api/search.ts
变更: 添加搜索 API 实现

#### 验证结果
| 检查项 | 状态 | 耗时 |
|--------|------|------|
| 类型检查 | ✅ 通过 | 2s |
| ESLint | ⚠️ 警告 | 1s |

#### 警告详情
- 第 42 行: 缺少函数返回类型注解

#### 建议
添加返回类型注解以提高类型安全性：
```typescript
async function search(query: string): Promise<SearchResult[]>
```

是否自动修复？(Y/n)
```

### 问题修复建议

当验证发现问题时，自动生成修复建议：

```markdown
### 修复建议

#### 问题 1: 类型不匹配
- 文件: src/api/search.ts:42
- 当前: `query: string`
- 期望: `query: SearchQuery`
- 建议: 使用 SearchQuery 接口包装参数

#### 修复代码
```typescript
// 修改前
async function search(query: string) { ... }

// 修改后
async function search(query: SearchQuery) { ... }
```

[应用修复] [跳过] [记录错题]
```

## 验证配置

### 项目级配置

在 `.iflow/settings.json` 中配置：

```json
{
  "pciv": {
    "validation": {
      "autoValidate": true,
      "checks": {
        "type": true,
        "lint": true,
        "test": false,
        "security": false
      },
      "ignorePatterns": [
        "**/*.test.ts",
        "**/*.spec.ts"
      ]
    }
  }
}
```

### 阶段级配置

不同阶段可配置不同的验证严格程度：

| 阶段 | 类型检查 | 代码风格 | 测试 |
|------|----------|----------|------|
| Prime | - | - | - |
| Clarify | - | - | - |
| Implement | ✅ 即时 | ✅ 即时 | ⏳ 可选 |
| Validate | ✅ 完整 | ✅ 完整 | ✅ 完整 |

## 与错题本联动

当验证发现问题时：

1. **自动记录建议**：建议将问题记录到错题本
2. **历史问题匹配**：检查是否有类似的历史错题
3. **预防措施提醒**：提醒之前总结的预防措施

```markdown
### 验证失败

检测到类似的历史问题：
- M-2026-02-15-002: TypeScript 类型断言风险

建议参考该错题的解决方案。
```

## 相关命令

- `/pciv-check` - 手动触发验证
- `/pciv-fix` - 自动修复问题
- `/pciv-mistake` - 记录错题
