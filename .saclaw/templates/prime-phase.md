# Prime 阶段模板

## 阶段目标

理解项目上下文、自动识别技术栈、定义功能范围、制定初步计划。

## 工作流程

### 1. 加载项目上下文

```bash
# 加载项目核心文档
@IFLOW.md
@README.md

# 如果存在以下文档，也一并加载
@docs/architecture.md
@docs/api.md
@docs/development.md
```

**检查清单**：
- [ ] 已加载 IFLOW.md 或 README.md
- [ ] 已理解项目整体架构
- [ ] 已了解项目主要功能

### 2. 技术栈自动识别 ⭐

**自动检测项目配置文件**：

```bash
# 使用技术栈检测命令
/pciv-tech-check

# 或手动触发检测
"请检测项目的技术栈"
```

**检测规则**：

| 类型 | 检测文件 | 识别内容 |
|------|----------|----------|
| **前端框架** | package.json | React, Vue, Angular, Svelte, Solid.js |
| **元框架** | package.json | Next.js, Nuxt, SvelteKit, Remix, Astro |
| **后端框架** | package.json / requirements.txt / go.mod | Express, FastAPI, Django, Gin |
| **数据库** | schema 文件 / 配置文件 | PostgreSQL, MySQL, MongoDB, SQLite |
| **ORM** | prisma/schema.prisma / models/ | Prisma, TypeORM, SQLAlchemy, GORM |
| **样式方案** | 配置文件 / package.json | Tailwind CSS, CSS-in-JS, Sass, UnoCSS |
| **类型系统** | tsconfig.json | TypeScript 版本和配置 |
| **测试框架** | 配置文件 | Jest, Vitest, Playwright, Cypress |
| **构建工具** | 配置文件 | Vite, Webpack, esbuild, Rollup |

**技术栈识别报告模板**：

```markdown
## 技术栈识别报告

| 层级 | 技术 | 版本 | 来源文件 |

| 前端框架 | [框架名] | [版本] | package.json |
| 元框架 | [框架名] | [版本] | package.json |
| 后端框架 | [框架名] | [版本] | [配置文件] |
| 数据库 | [数据库类型] | - | [schema文件] |
| ORM | [ORM名称] | [版本] | [配置文件] |
| 样式方案 | [方案名称] | [版本] | [配置文件] |
| 类型系统 | TypeScript | [版本] | tsconfig.json |
| 测试框架 | [框架名称] | [版本] | [配置文件] |

### 已加载技术栈参考模板
- resources/tech-stack-templates/[技术栈].md

### 技术栈特点
- [特点1]
- [特点2]
- [特点3]

```

**检查清单**：
- [ ] 已检测项目配置文件
- [ ] 已识别主要技术栈

### 4. 定义功能范围

**功能点粒度定义**：

| 粒度 | 预计时间 | 涉及文件数 | 特征 |
|------|----------|------------|------|
| **小** | 1-4 小时 | ≤ 5 个 | 单一功能点，改动范围小 |
| **中** | 1-3 天 | 5-15 个 | 功能模块，包含若干子功能 |
| **大** | 3-7 天 | > 15 个 | 复杂功能，涉及多个模块 |

```bash
# 确定功能范围
"请帮我定义这个功能点的范围和粒度"
```

**功能范围定义模板**：
```markdown

[小/中/大]

- [模块1]：[影响描述]
- [模块2]：[影响描述]

### 预计工作量

```

**检查清单**：

## 常见问题

### Q: 技术栈检测失败怎么办？

A: 手动指定技术栈：
```
"本项目使用 [技术栈列表]，请加载对应的参考模板"
```

### Q: 如何处理多技术栈项目？

A: 系统会自动识别多个技术栈并分别加载参考模板。在 Clarify 阶段会确认每个功能使用的技术栈。

### Q: 功能范围如何调整？

A: 在 Prime 阶段可以初步定义，在 Clarify 阶段会进一步细化。如果范围过大，建议拆分为多个功能点。
