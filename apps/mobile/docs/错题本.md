# Kuikly 开发错题本

## 错误 1: KSP 缓存导致页面注册不完整

### 问题描述
KSP (Kotlin Symbol Processing) 生成的 `KuiklyCoreEntry.kt` 只注册了部分页面，导致应用启动时找不到 `LoginPage` 而出现白屏。

### 现象
- 应用启动后白屏
- `KuiklyCoreEntry.kt` 中 `triggerRegisterPages()` 只注册了部分页面
- 缺少 `LoginPage`、`MainPage`、`ChatDetailPage`、`ProfilePage` 等页面注册

### 根本原因
KSP 使用了过期的缓存，导致增量编译时没有重新扫描所有 `@Page` 注解的类。

### 解决方案
```bash
# 1. 清理 KSP 缓存
Remove-Item -Recurse -Force "shared/build/generated/ksp"
Remove-Item -Recurse -Force ".gradle"

# 2. 重新运行 KSP（无缓存）
./gradlew :shared:kspDebugKotlinAndroid --no-build-cache

# 3. 重新编译安装
./gradlew :androidApp:installDebug
```

### 预防措施
- 当添加新的 `@Page` 注解页面后，如果发现页面无法加载，先清理 KSP 缓存
- 使用 `--no-build-cache` 参数强制重新生成

## 错误 2: Kuikly API 导入路径错误

### 问题描述
多个文件使用了错误的 Kuikly API 导入路径，导致编译失败。

### 错误导入与正确导入对照

| 错误导入 | 正确导入 |
|---------|---------|
| `com.tencent.kuikly.core.modules.router.RouterModule` | `com.tencent.kuikly.core.module.RouterModule` |
| 无导入 `vfor` | `com.tencent.kuikly.core.directives.vfor` |
| 无导入 `ObservableList` | `com.tencent.kuikly.core.reactive.collection.ObservableList` |
| `org.json.JSONObject` (用于 openPage) | `com.tencent.kuikly.core.nvi.serialization.json.JSONObject` |
| 无导入 `List` 组件 | `com.tencent.kuikly.core.views.List as KuiklyList` (使用别名避免冲突) |

### 解决方案
确保所有 Kuikly 相关导入使用正确路径，参考 Kuikly 官方文档。

## 错误 3: observableList 类型声明问题

### 问题描述
`observableList` 返回类型推断不正确，导致 `diffUpdate` 方法找不到。

### 错误写法
```kotlin
var messages by observableList<ChatMessage>()
```

### 正确写法
```kotlin
var messages: ObservableList<ChatMessage> by observableList()
```

### 原因
显式指定类型可以让编译器正确识别 `ObservableList` 类型，从而访问其 `diffUpdate` 方法。

## 错误 4: Input 组件不支持 padding 属性

### 问题描述
`Input` 组件没有 `padding` 属性，使用会导致编译错误。

### 解决方案
使用 `margin` 替代 `padding`：
```kotlin
Input {
    attr {
        margin(all = Spacing.Medium.toFloat())  // 使用 margin
        // padding(all = Spacing.Medium)  // 错误！Input 不支持 padding
    }
}
```

## 错误 5: ViewBuilder 扩展函数调用问题

### 问题描述
在 `Column`/`Row` 闭包内调用 `ViewBuilder` 扩展函数时，接收器类型不匹配。

### 错误写法
```kotlin
private fun ViewBuilder.buildSettingItem(...) { ... }

// 在 Column 闭包内调用
Column {
    buildSettingItem(...)  // 错误！接收器类型不匹配
}
```

### 正确写法
```kotlin
// 方式1: 返回 ViewBuilder 的函数
private fun buildSettingItem(...): ViewBuilder = { ... }

// 调用时使用显式接收器
Column {
    this@PageClass.buildSettingItem(...)(this)
}

// 方式2: 直接内联定义
Column {
    Row { ... }  // 直接写内容
}
```

## 错误 6: Kotlin List 与 Kuikly List 冲突

### 问题描述
`com.tencent.kuikly.core.views.List` 与 Kotlin 标准库 `kotlin.collections.List` 名称冲突。

### 解决方案
使用类型别名导入：
```kotlin
import com.tencent.kuikly.core.views.List as KuiklyList

// 使用时
KuiklyList {
    attr { flex(1f) }
    vfor({ ctx.items }) { item -> ... }
}
```

## 错误 7: Row/Column 块缺少闭合大括号

### 问题描述
在复杂的嵌套布局中，`Row` 或 `Column` 块缺少闭合的 `}`，导致编译错误。

### 现象
- 编译错误提示 "Missing '}'" 在文件末尾
- 实际错误位置可能在几十行之前

### 解决方案
- 使用 IDE 的代码折叠功能检查每个块的闭合
- 确保 `vfor` 闭包内只有一个根节点
- 注意 `if` 语句的分支都要正确闭合

---

## 最佳实践总结

1. **KSP 缓存问题**：添加新页面后，清理 KSP 缓存重新生成
2. **导入路径**：参考 Kuikly 官方文档，使用正确的导入路径
3. **类型声明**：`observableList` 需要显式指定 `ObservableList<T>` 类型
4. **组件属性**：不同组件支持的属性不同，查看官方文档确认
5. **扩展函数**：注意接收器类型，必要时使用显式接收器
6. **名称冲突**：使用类型别名解决命名冲突
7. **代码结构**：保持良好的代码缩进，确保所有块正确闭合
