# review-pr

Description: 审查当前改动并输出风险与建议

## Prompt

从代码审查视角分析当前变更，优先输出 bug、风险、回归点和测试缺口。

## 结构化输出格式

审查结果必须包含以下 5 个部分，按严重级别从高到低排列：

### 1. 影响面分析
- **变更文件**：列出所有变更文件（路径 + 变更类型：新增/修改/删除）
- **影响模块**：分析变更影响的模块/子系统
- **调用链**：变更可能影响的上下游调用链
- **数据流**：变更是否影响数据读写、状态持久化

### 2. Bug 风险（P0/P1）
- **正确性风险**：逻辑错误、边界条件遗漏、空值处理缺失
- **回归风险**：可能破坏已有功能或兼容性
- **并发风险**：数据竞争、死锁、竞态条件
- **每项标注**：严重级别（P0=阻塞 / P1=严重）、所在文件、行号范围

### 3. 安全风险
- **注入风险**：SQL 注入、命令注入、XSS 等
- **访问控制**：权限绕过、敏感信息泄露
- **依赖安全**：引入的第三方库风险
- **每项标注**：OWASP 分类 + 严重级别

### 4. 测试缺口
- **缺失测试类型**：缺少哪些测试覆盖（单元/集成/端到端/回归）
- **边界用例**：未覆盖的边界条件和异常场景
- **Mock 覆盖**：外部依赖的 mock 是否充分
- **建议新增**：具体建议新增的测试用例

### 5. 改进建议
- **代码质量**：命名、复杂度、可维护性
- **性能**：可能的性能瓶颈和优化方向
- **文档**：需要同步更新的文档或注释
- **优先级**：每条建议标注 P0/P1/P2 优先级

### 审查结论

```
审查结论：<通过 / 有条件通过 / 需修改后重新审查>
主要问题：<一句总结>
</code>
```

## 使用说明

- 在 TUI 中使用：`/skills run review-pr` 或直接输入 `/review-pr`
- 会自动获取当前工作目录的 Git diff 进行分析
- 如果只想审查特定文件，使用 `/review-pr <file-path>`
- 如果只想审查特定分支/PR，使用 `/review-pr <branch-or-pr>`
