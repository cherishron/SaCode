# SaCode 品牌体系完整性审计报告

> 审计范围：覆盖 SaCode 全部品牌触达面 —— CLI/TUI、桌面端（Tauri）、VSCode 扩展、npm 包（`@cherishron/sacode`）、README/CHANGELOG/架构与产品文档、界面文案。
> 审计方法：品牌资产枚举（图标/配色/命名）+ 多端文案一致性比对 + 设计文档交叉验证。所有结论附 `文件:行号` 证据，未修改任何源码。
> 审计日期：2026-10-01

---

## 一、审计结论速览

**核心判断：品牌体系「骨架已立、细节失序」。**

- 产品主名 **SaCode** 在文档与代码中高度一致；组织→产品→变体的三层命名结构（Cherishron → SaCode → SaCode Desktop）清晰。
- 但存在 **4 类需收敛的问题**：① 主题配色三套互相矛盾、无单一真源；② 设计文档方向漂移（蓝版 vs 暖版并存）；③ 面向用户的 UI 同时暴露 `SaCode` 与 `灵枢` 双品牌、关系未定义；④ 缺失正式品牌标语与主品牌矢量 Logo 母版。
- 亮点：桌面端已有较完整的 CSS 令牌体系；About 页规范呈现版本/许可/源码；图标资产已具备。

## 二、品牌要素逐维核查

### 2.1 项目名称（Naming）
**现状（三层结构已成型）：**
- `Cherishron` = 组织/厂商：npm scope `@cherishron`、GitHub org `github.com/cherishron/SaCode`、App identifier `com.cherishron.sacode.desktop`（`tauri.conf.json:5`）。
- `SaCode` = 产品名：CLI 二进制、`@cherishron/sacode` 包名、README/CHANGELOG 一致（`README.md:1`、`CHANGELOG.md:1`）。
- `SaCode Desktop` = 桌面变体：`productName` / 窗口标题 / `preferences.ts` 一致（`tauri.conf.json:3,16`；`preferences.ts:71-72`）。
- `灵枢 (LingShu)` = 内部技术架构品牌：`architecture.md:1103` 明确定义为「核心技术品牌名称」，源自《黄帝内经》。

**一致性评价：** 产品主名 `SaCode` 跨 README / CHANGELOG / 桌面代码 / preferences 高度一致 ✓。

**问题：**
- ⚠️ **双品牌并现、层级模糊**：`灵枢` 作为「技术品牌」被同时用于代码注释、架构文档与**面向用户的 UI 文案** —— `ChatCard.vue:92` 显示「灵枢 · 角色编排」、`turn-events.ts:68` 的「灵枢四类事件」、`ChatCard.vue:394` 的「灵枢四卡」。用户在同一界面同时看到 `SaCode`（品牌名、TaskColumn 品牌名 `TaskColumn.vue:332`）与 `灵枢`，但二者关系从未在用户可见处说明。
- ⚠️ **缺品牌圣经**：无文档定义「Cherishron / SaCode / 灵枢」三层关系与各自适用场景。

### 2.2 标识 / Logo
**现状：**
- VSCode 图标：`interfaces/vscode/media/icon.svg` —— 蓝底圆角方块 `#366CFF` + 白色抽象折线标记。
- 桌面端：`sa-logo.png` / `sa-logo-dark.png`（`public/`）、Tauri icons（`32x32.png` / `128x128.png` / `icon.png` / `icon.ico`）。
- CLI/TUI：无图形 Logo（终端工具，合理）。

**问题：**
- ⚠️ **缺主品牌矢量母版**：仅有 PNG 与 VSCode 专用 SVG，无 SaCode 主品牌的矢量源文件，多尺寸/多场景延展缺乏统一基准。
- ⚠️ **图标颜色不统一**：VSCode 图标蓝 `#366CFF`，与桌面设计文档两套配色（`#2f81f7` / `#d97757`）均不一致。
- ⚠️ **无 Logo 使用规范**（留白、最小尺寸、禁用组合）。

### 2.3 视觉风格（Visual Style）
**现状：**
- TUI：`github` / `vscode` / `idea` 三套深色主题（`tui/theme.rs`）—— 含蓝系 GitHub 风。
- 桌面端：TDesign + 自定义 CSS 令牌，四段式布局，「克制的深色开发者工具」（`desktop-ui-design-v1.md:14`）。
- VSCode 扩展：独立视觉。

**问题：**
- ⚠️ **跨端视觉语言不统一**：TUI 三主题（蓝系）与桌面端「暖色克制深色」气质不一致，无统一 Design Language 把 CLI / TUI / Desktop / VSCode 串成一体。
- ⚠️ **设计方向漂移（严重）**：`desktop-ui-design-v1.md` 定为「中性灰 + 单一蓝强调（GitHub 风，accent `#2f81f7`）」，但 `compose/spec/desktop-ui-refresh.md` 与**实际落地 CSS**（`shell.css:18` 默认 `--bg-base:#1b1a18`、warm accent `#d97757`）走的是**暖色陶土**方向。两版文档并存，无「以何为准」。

### 2.4 品牌标语（Tagline）
**现状：** README 仅有描述句「终端优先的 Rust AI 编程工具」（`README.md:3`），非正式标语；About 页只列名称/版本/许可/源码（`AboutView.vue:18-57`），无使命陈述；UI 各处均无标语。

**结论：❌ 缺失。** 无统一、可复用的一句话价值主张。

### 2.5 主题配色（Brand Colors）
**现状（三套互相矛盾）：**
| 来源 | 主色 / 背景 | 性质 |
|---|---|---|
| VSCode 图标 | `#366CFF` | 图标蓝 |
| 桌面 v1 设计文档 | accent `#2f81f7` / bg `#0d1117` | GitHub 蓝 |
| 桌面 refresh 规范 + **实际实现** | accent `#d97757`（深）/ `#c45c26`（浅） | 暖色陶土 |

**结论：⚠️ 冲突未决。** 既无单一主色 source-of-truth，且落地值与文档不一。
**注**：用户偏好「低调深色系暗黑风格」，暖色陶土方案与之更契合 —— 建议以暖色方案为唯一真源，并明确废弃 v1 蓝版。

### 2.6 文档与界面文案中的品牌表述
- README / CHANGELOG：`SaCode` 一致 ✓
- 架构/参考文档：`灵枢` 作为技术品牌贯穿（`architecture.md`、`AGENTS.md`、`comparison-with-deepseek-harness.md`）—— 对内一致 ✓
- 桌面 UI：`SaCode`（品牌名/默认昵称 `preferences.ts:85` / 窗口标题 / TaskColumn）+ `灵枢`（灵枢四卡/事件）**双品牌并现** ⚠️
- 缺失：无品牌规范文档（Glob 未发现 `brand`/`identity`/`design-system` 类文件）。

## 四、已完整 vs 仍需补充

### ✅ 已完整 / 较好
1. 产品主名 `SaCode` 跨文档与代码一致。
2. 组织→产品→变体三层命名结构清晰（Cherishron → SaCode → SaCode Desktop）。
3. 已有图标资产（PNG 系列 + VSCode SVG）。
4. 桌面端有较完整的设计令牌体系（CSS 变量驱动，深浅双 theme 预留）。
5. About 页规范呈现版本 / 许可 / 源码位。

### 🔧 仍需补充
1. **品牌圣经文档**：定义三层命名关系、`灵枢` 定位与适用场景、禁用情形。
2. **主品牌矢量 Logo 母版 + 使用规范**（留白 / 最小尺寸 / 禁用组合）。
3. **统一主色**：解决 `#366CFF` / `#2f81f7` / `#d97757` 冲突，定暖色为唯一真源并同步图标。
4. **跨端统一视觉语言**：把 TUI / Desktop / VSCode 的 Design Language 对齐。
5. **品牌标语 / 一句话价值主张**（含中英文版本）。
6. **`灵枢` 在用户界面的品牌处理策略**：明确它是「引擎代号（不应暴露给用户）」还是「功能品牌（保留）」并据此收敛 UI 文案。
7. **设计文档方向收敛**：合并或明确废弃 v1 蓝版与 refresh 暖版，指定唯一规范。
