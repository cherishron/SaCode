# 模型图片能力门控与即时补充附件（2026-10-05）

## 产品行为

模型注册表已有 `ModelSpec.image`，此前未传给请求装配器。现在宿主从选定提供商和模型读取声明，传给首次请求及整个模型工具循环。共享核心 `modelRequestJson` 默认不支持图片，遇到历史图片引用返回 `model-image-not-supported`，在读取图片字节及创建网络请求之前拒绝；不会静默删图、按模型名称猜能力或将文件误作图片。纯文字和通用文件路径仍可用。

没有注册表能力声明的旧单路设置/环境变量也按未声明处理。需要在模型设置中明确声明图片能力；只改 API 地址或模型名称不能自动启用。首次请求装配移入宿主现有异常结算边界，拒绝后落盘并释放租约，宿主继续响应，用户可切换图片模型重试已保存的会话。

桌面模型目录保留 `image` 声明，发送和入队前检查草稿。未声明图片能力或模型目录未就绪时显示中文说明并保留草稿、附件，不提交用户消息。历史已经存在图片时，由宿主再检查并给出对应中文起轮错误，前端检查不能替代后端门控。

另外补齐步边界即时补充：带附件的 inbox 条目通过同一个 `AttachmentStore.commitMessage` 写入引用与用户消息，避免 `steer` 后仅写正文、续跑丢图。能力声明贯穿续跑；不支持图片时，保留已送达的引用事实并拒绝下一次提供商请求。
