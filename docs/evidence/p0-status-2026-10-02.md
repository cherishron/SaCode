7. **Ctrl+C / SIGINT —— PARTIAL（本机无法对「系统真的调起处理器」取证）**：
   std 没有信号 API，故 `core/src/sigwin.cj` 用 CFFI 绑 `SetConsoleCtrlHandler`，
   处理器体把「在册的在途 turn 令牌」逐个 `cancel()`——与桌面 stop、与 `turn/cancel`
   走的是同一条协作式取消，不是就地终止进程。两条设计约束来自实测与文档：
   CFunc **不能捕获环境**，所以被取消对象只能经一张进程级在册表交接；
   注册**只做一次**（`install()` 幂等），否则一次中断会把同一批令牌取消多次，
   就说不清这一轮是被第几次中断取消的。
   CLI 新增 `sig` 模式：注册 → 拿写租约 → 挂令牌 → 起一轮 turn → 打印握手行
   （stdout 被重定向时是块缓冲，**必须 `getStdOut().flush()`**，否则外部驱动等不到）→
   等中断 → 结算 → 归还租约 → 退 **130**（128+SIGINT）。
   **已取证（core `cjpm test` 85/85，其中中断 5 条）**：`install()` 在真进程里返回成功且幂等；
   处理器体确实取消在册令牌；摘牌后的令牌不再被后续中断误伤；未知句柄 `detach` 明确返回 false
   （不假装成功，在册表不会单调变大）；`CTRL_CLOSE` 的类型被如实记账。
   **两个变异体都被抓**（同时留在位时 core 85 条里恰好红 2 条，指定用例名可对上）：
   处理器体改成「只记账不取消在册令牌」→ `signalCancelsAttachedToken` 转红；
   `install()` 去掉幂等守卫 → `installSucceedsOnceAndIsIdempotent` 转红（计数变成 +2）。
   `sig` 模式在无中断环境里的实测输出（剥 PATH 的包内 `dsh.exe`，rc=1）：
   `PASS 中断处理器注册成功` / `PASS 写入前拿到写租约` / `FAIL 中断确实送达处理器` /
   `PASS 未落盘的写入就地结算` / `PASS 写租约归还` / `PASS 在册表清空`，
   且**不会挂死**——等不到中断时主动取消在途 turn 再收束
   （早先会挂住三十几秒：provider 在帧间自旋 `sleep(1ms)`×3000，本运行时该 sleep 粒度远大于 1ms）。
   两条曾经说谎的断言已加前提：`cancelled=true` 与 `turn/cancelled` 只有在
   **真的收到过中断**时才报 PASS，否则把我自己的兜底取消报成中断的功劳。
   **未能取证的那一条**：`GenerateConsoleCtrlEvent` 合成中断**在本机投递不到任何附属进程**。
   两轮尝试（`FreeConsole+AttachConsole(目标pid)` 与「驱动与目标共用一个新控制台」）、
   三种参数（`(CTRL_C,0)`、`(CTRL_C,目标pid)`、`(CTRL_BREAK,目标pid)`）全部 `ret=True err=0`，
   而目标侧处理器计数恒为 0。**对照实验定责**：同一驱动、同一控制台下改测 `node`
   （`process.on('SIGINT')`）同样 `hits=0` ——
   所以缺的是本机交互式控制台的投递能力（非交互会话 / ConPTY），**不是仓颉侧没接**。
   解锁条件：在真人可交互的控制台窗口里跑 `dsh sig` 并按 Ctrl+C，期望
   无 FAIL 行且退出码 130；驱动已随包留在 `scripts/sigwin-e2e.ps1`（判决只认
   `hits=1`、`kind=0`、`cancelled=true`、`code=130` 与 OS 退出码四件齐全）。

## 明确不许做的 shortcut

不得用「删掉动态扩展」或「删掉 npm CLI」的方式让 P0 变绿；不得把 `TOTAL: 0` 的测试命令当绿灯
（`cjpm test` 对空测试集返回成功，见用户记忆「空测试集是假绿」）；结论只用 PASS / FAIL / BLOCKED。
