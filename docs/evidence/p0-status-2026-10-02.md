## 不变量 7 的第五类 developer/message（2026-10-03，提交 `cd9c8a7`）

起点事实：总体方案第 7 条冻的是 **5 类**进模型历史（`system/`、`developer/`、`user/`、`assistant/` 四种

## CLI 的 headless 与结构化交付面（2026-10-03，提交 `343ccd7`）

起点事实：方案冻的是「CLI 有交互/headless/结构化模式；stdout JSON 与 stderr 诊断分离；
非交互无审批应答者则拒绝，不等 GUI」，但 `apps/cli` 当时只有断言式自测子命令
（`seed|projection|all|stream|tool|ext|cancel|extjs|sig`），npm 那个入口没有可交付的产品面；
审批工单只有桌面 IPC 在用（`toolCall` 只收 `approvalId`）。

本批加三个子命令，全部只调 core，不新增真源：

- `dsh tools [--json]`：清单出自 `ToolRegistry` 这一份真源，标出 `approval`/`free`；
- `dsh call <tool> [args...] [--json]`：`ApprovalDesk.ask` 发号 → 标准输入读**一行**应答 →
  `executeWithApproval` 消费一次性凭据；写入前拿 `WriteLease`、结束后 `flush` 再归还；
  退出码按失败族分开（0 放行 / 3 审批没过 / 4 工具不存在 / 8 执行期失败）；

1. **「读不到应答」不等于「答了不批」**。`decideAnswer(None)` 返回空串＝不作答，工单停在 `pending`，
   执行照样被拒，但日志里**不留** `approval/decided`；答 `n` 才留 `decided:denied`。

   先要号再拒等于让用户回答一个根本跑不了的动作，还会在日志里留下一条指向不存在工具的 `approval/asked`。
   这条是本批自己写出的缺陷：第一版按 `requiresApproval("nosuch")`（fail-closed 恒真）去要号，

## 工单号跨进程不复用（2026-10-03，提交 `8289788`）

起点事实：上一批（`343ccd7`）的 CLI headless 证据节末尾写明「**本批仍未证明**：工单号只在
单进程内唯一，跨进程会在日志里重号（`approval/asked 1:write` 出现多次），审计答不出
『是哪一次』，收口要把号持久化」。原因：`ApprovalDesk.nextId` 是进程内计数器，CLI 每次
`dsh call` 都是一个新进程，计数器从 0 起，日志里连着出现两条 1 号工单。

改法：`askWithTtl` 发号前先读 `log.snapshotEvents()` 里 `approval/asked` 事件的最大号，
把 `nextId` 抬到已落盘最大号之上再 `+1`。与 `TokenMeter` 每次接手日志都 `rebuild`
同一个理由——内存计数不是第二真源。新增包级函数 `approvalIdFromData` 剥 `<id>:<tool>`
数据里的号；测试侧自留 `askedIdOf`/`apDupAskedIds` 做对账。

两条核心红用例：
- `ticketIdsContinueAcrossProcesses`：first desk 发 1、2 → flush → 换 `SessionLog`
  对象回放 → second desk 发号必须 = 3（不是 1），且 first 的号在 second 上既不能
  应答也不能消费（不能隔空改判别人那一次）；
- `secondDeskOnSameLogDoesNotReuseIds`：同一份日志对象上换一张新桌子，号必须接在
  最大号之后。

CLI 的 headless 块在同一条不变量上钉了三条断言（`desk2`/`t6`/`seenIds`）：重启后发号
接在最大号之后、日志里每条 asked 的号互不相同、上一进程发过的号在新桌子上既不能
应答也不能消费——在产品入口上把这条钉死，不只是核心层。

变异反证：把 `highestAskedId` 改成读 `approval/decided`（而非 `approval/asked`），
两条独占受害用例转红（`second.ask("write")` left=1 right=3），其余 151+1 全绿；
用 `cp` 备份还原，`diff` 空输出证逐字一致，回绿 156+1。

`core/src/sse.cj`，不需 stdx DLL）：

7. **Ctrl+C / SIGINT —— PARTIAL（本机无法对「系统真的调起处理器」取证）**：
