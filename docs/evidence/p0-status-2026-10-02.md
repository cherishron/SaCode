## 未完成项与解锁条件

推进顺序（第 4 项 `extjs/` 本轮已落地，保留在清单里只为留下证据与剩余缺口）：
**取消与背压 → 写租约接管 → 渲染层 → 真模型烟测 → Electron（等官方源）**。

1. **Electron 桌面安装包 —— BLOCKED（根因已钉准）**
   实测：`apps/desktop/node_modules` 里 **electron@33.4.11 已装**；`registry.npmjs.org` → **200**；
   但 `node_modules/electron/` **无 `dist/`**（只剩 `index.js`/`cli.js`/`electron.d.ts`），`github.com` → **000**。
   结论：卡的不是 npm，而是安装后脚本从 GitHub Releases 拉二进制那一步。
   解锁路径（**用户已定：只用官方 GitHub Releases，不用 `ELECTRON_MIRROR` 等第三方镜像**，见方案 §8 决策 9）：
   等 `github.com` 可达后重跑 `npm i`，或手工从官方 Release 放置 `dist/`。证据细节见 `docs/evidence/desktop-electron-blocker.md`。
   在此之前 C10 固定记 **BLOCKED**，不得因此把桌面包从验收范围里删掉。
   解锁后第一步：`cd apps/desktop && npx electron . --smoke` 期望打印 `SMOKE PASS`、退出码 0，
   且退出后无孤儿 `dsh-host.exe`（`tasklist | grep dsh-host`）。再谈打包（electron-builder 需另行授权）。
2. **渲染层 —— FAIL**：`apps/desktop/renderer/` 仍是占位页，Vue 3 / TinyVue / TinyRobot / Next SDK 未接入。
   不依赖 Electron 的最小起步：先在纯 Node 里加载 `host-bridge.cjs` 对宿主做 `session/subscribe` 分页拉取，
   把投影渲染逻辑做成独立可测模块，接到 Electron 之前就能用 `node --test` 验。
3. **取消与背压 —— FAIL**：Ctrl+C、桌面 stop、慢消费者三条路径都没实现；
   前置是引入线程或字节级流（`std.sync`/`std.process` 已在 std 内，可直接用）。
4. **JS 扩展宿主 `extjs/` —— PARTIAL（本轮已落地）**：
   `core/src/ext.cj`（`ToolRegistry`/`ListenerRegistry`，未登记即拒、重名拒绝、监听 handle 一次性）
   + `extjs/host.cjs`/`server.cjs`（NDJSON JSON-RPC，`extension/load|list|call|dispose`，退出结算在途调用 `-32002 host-exiting`）
   + 两个入口各接一次：CLI `dsh ext` 8 项断言、桌面 `extension/*` 3 条用例。
   实测计数：core `cjpm test` 24/24、`extjs` `node --test` 10/10、`bridge` 12/12、npm 产物 `dsh.exe ext` 裸 PATH rc=0。
   **剩余**：仓颉侧尚未 spawn `extjs` 进程（需 `std.sync` 并发读子进程 stdout），故 JS 动态工具目前是独立验收，未由 core 驱动。
