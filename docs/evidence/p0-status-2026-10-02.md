   ② 宿主侧 `jsonStr` 不解转义，桌面传路径参数须用正斜杠形式（已在测试注释里钉住）；
   ③ 优雅退出依赖宿主自己的 `host/shutdown`——core 侧只拿得到 `OutputStream` 接口，std 无文档化 `close()`，
   没法靠关写端造 EOF。这是真实的 API 缺口，不是风格选择，已在方案 §8 记为决策 14。
   桌面入口本批已接上：`apps/host` 暴露 `extension/host/spawn|load|list|call|dispose|close`，
   转调同一个 `ExtProcess`，桥接测试断言「能力表/工具结果只能来自子进程应答」。
5. **写租约 —— PASS（TOCTOU 与崩溃接管两条都已闭）**：
   原实现是 `exists` + `File.writeTo`，两者之间有竞态窗口，且 `release()` 无条件
   `removeIfExists`——**抢写失败的一方也能删掉持有者的租约**。本批两条都改掉了：
   获取改为「`File.createTemp` 独占落盘 + `rename(..., overwrite: false)`」，
   目标已存在时 rename 直接抛异常，不再有检查-再行动窗口（std.fs 无 O_EXCL，
   这是文档化 API 里唯一在 Windows 上也算原子的独占落位手段）；盘上写的是归属凭据
   （`writer=<唯一临时文件名>`）而不是裸标志 `held`，`release()` 只认自己那份，
   凭据不符就返回 false；失败的获取自己清掉中转文件（`stagingArtifact()` 供断言）。
   实测：core `cjpm test` **61/61** rc=0（新增 5 条租约用例），双入口回归全绿
   （CLI `all/tool/cancel` ALL PASS；宿主重打 89 文件后 `bridge` 20/20、`npm test` 23/23、
   安装包两种形态重打后打包态 `--ui-smoke` 仍 PASS）。
   **探针教训**：头 4 条用例在「跳过归属核对」的变异体下**全部照样绿**——它们都在
   空凭据那关就返回了，根本没走到归属比较。补的第 5 条（拿到过、之后盘上归属已易主）
   才把变异体打红；没有这一步，「修好了」只是自称。
   **崩溃接管本批已落地**（上一条的「仍欠」就地作废）：凭据升级为
   `writer=<持有者 pid>-<唯一临时文件名>`，新增 `core/src/procwin.cj` 用 CFFI 绑
   `GetCurrentProcessId` / `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` /
   `GetExitCodeProcess`（+ `CloseHandle`）判活，`takeoverIfStale()` 只在
   「有租约 + 认得出 pid + 确认已死」三条同时成立时清旧重取，其余一律 false。
   CFFI 三条实测坑记在方案 §8 决策 23（`inout` 只属于调用点、Win32 `BOOL` 须映 `Int32`、
   kernel32 这四个符号无需额外 `link-option`）。
   实测计数：core **80/80** rc=0（新增 5 条：自身 pid 合理、探针认自己为活/认三个假 pid 为死、
   租约带自己的 pid、死者残留被接管而活者残留被拒且凭据不变、旧格式凭据永不接管）；
   桌面入口 `bridge.test.mjs` **28/28**（新增 1 条：死者残留 → `session/append` 成功且
   `events=durable=5`；活者残留 → `-32001 already-owned` 且盘上凭据逐字节未变）；
   CLI 入口在剥掉编译器 PATH 下三条分向：`writer=4294967000-stale` → `ok seeded 6` 且租约已归还、
   `held`（无 pid 旧格式）→ `err already-owned` rc=1 且不写日志、
   `writer=<真实 explorer pid>-live` → `err already-owned` rc=1 且凭据原样。
   **两个变异体都被抓**：`takeoverIfStale` 一律拒绝 → 死者那条在桌面入口转红 `-32001`；
   去掉判活一律接管 → 活者那条转红 `Missing expected rejection`。
   **未做（记为边界而非待办）**：跨机共享目录下的租约接管——pid 只在单机内有意义，
   跨机需要带 `fcntl`/锁服务的手段；pid 被系统回收复用的误判按「偏向不接管」收敛
   （死者 pid 恰好被活进程占用时留着手清，不抢）。
6. **真模型 HTTPS+SSE 烟测 —— 待授权凭证**（假 provider 只覆盖协议语义，不能替代）。

## 明确不许做的 shortcut

不得用「删掉动态扩展」或「删掉 npm CLI」的方式让 P0 变绿；不得把 `TOTAL: 0` 的测试命令当绿灯
（`cjpm test` 对空测试集返回成功，见用户记忆「空测试集是假绿」）；结论只用 PASS / FAIL / BLOCKED。
