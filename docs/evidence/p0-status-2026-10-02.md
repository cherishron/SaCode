## 未完成项与解锁条件

推进顺序（第 3 项「取消与背压」本批落到 PARTIAL，第 4 项 `extjs/` 已在清单里留着剩余缺口）：
**core 驱动 `extjs`（spawn + 并发读子进程 stdout，前置已就位）→ Ctrl+C/SIGINT（CFFI）→ 流式期日志并发读写进锁 → 写租约接管 → 渲染层 → 真模型烟测 → Electron（等官方源）**。

1. **Electron 桌面安装包 —— BLOCKED（根因已钉准）**
   实测：`apps/desktop/node_modules` 里 **electron@33.4.11 已装**；`registry.npmjs.org` → **200**；
   但 `node_modules/electron/` **无 `dist/`**（只剩 `index.js`/`cli.js`/`electron.d.ts`），`github.com` → **000**。
   结论：卡的不是 npm，而是安装后脚本从 GitHub Releases 拉二进制那一步。
   解锁路径（**用户已定：只用官方 GitHub Releases，不用 `ELECTRON_MIRROR` 等第三方镜像**，见方案 §8 决策 9）：
   等 `github.com` 可达后重跑 `npm i`，或手工从官方 Release 放置 `dist/`。证据细节见 `docs/evidence/desktop-electron-blocker.md`。
   在此之前 C10 固定记 **BLOCKED**，不得因此把桌面包从验收范围里删掉。
   解锁后第一步：`cd apps/desktop && npx electron . --smoke` 期望打印 `SMOKE PASS`、退出码 0，
   且退出后无孤儿 `dsh-host.exe`（`tasklist | grep dsh-host`）。再谈打包（electron-builder 需另行授权）。
2. **渲染层 —— FAIL**：`apps/desktop/renderer/` 仍是占位页，Vue 3 / TinyVue / TinyRobot / Next SDK 未接入。
   不依赖 Electron 的最小起步：先在纯 Node 里加载 `host-bridge.cjs` 对宿主做 `session/subscribe` 分页拉取，
   把投影渲染逻辑做成独立可测模块，接到 Electron 之前就能用 `node --test` 验。
3. **取消与背压 —— PARTIAL（本批已落地两条）**：
   `core/src/cancel.cj` 提供 `TurnToken`（协作式取消，`child()` 跟随父、`detached()` 不跟随）、
   `DeliveryQueue`/`ThreadSafeDeliveryQueue`（有界投递，投不满只报 `overflow()`，`dropped()` 恒 0）、
   `TurnRunner`（turn 跑在 `spawn` 出的仓颉线程）与 `CancellableStreamProvider`。
   实测：core `cjpm test` **42/42**（含 9 条取消/背压新用例；变异探针——把 `TurnHandle.cancel()` 里的
   `token.cancel()` 摘掉只留 `Future.cancel()`，`cancelFromAnotherThreadStopsTheRunningTurn` 与
   `resultIsAvailableOnlyAfterTheThreadFinishes` 双双失败并各卡满 3.2s 忙等上限，还原后回绿——
   证明「取消靠令牌、`Future.cancel()` 只发请求」是被测出来的而不是写出来的）；
   CLI `dsh cancel` **9 项断言 ALL PASS**，裸 PATH（`env -i PATH=/c/Windows/System32`）rc=0；
   桌面入口 `bridge` **16/16**（新增 4 条：能力表声明 turn/*、全新会话第一个 turn 流中取消并结算、
   无在途 turn 时不得编造终态、宿主退出前取消并结算在途 turn）。
   **剩余**：① Ctrl+C/SIGINT 仍未接——已查的 std 无信号 API，需 CFFI 绑 `sigaction`/`SetConsoleCtrlHandler`；
   ② 流式期间日志靠 Host 串行（turn 在途时其他读写回 `-32001 turn-in-flight`），
   `SessionLog` 的并发读写尚未收进锁——这是串行化不是并发安全，不许当已交付。
   **本批顺带钉掉一个真缺陷**：`SessionLog.load()` 原先把「日志文件不存在」判成 `replay-rejected`，
   导致全新会话的第一次写入与第一个 turn 都进不去（桌面黄金路径直接堵死）；
   现按「零事件是合法回放」处理，`missingLogFileIsAnEmptySessionNotARejection` 先行红后行绿。
4. **JS 扩展宿主 `extjs/` —— PARTIAL**：
   `core/src/ext.cj`（`ToolRegistry`/`ListenerRegistry`，未登记即拒、重名拒绝、监听 handle 一次性）
   + `extjs/host.cjs`/`server.cjs`（NDJSON JSON-RPC，`extension/load|list|call|dispose`，退出结算在途调用 `-32002 host-exiting`）
   + 两个入口各接一次：CLI `dsh ext` 8 项断言、桌面 `extension/*` 3 条用例。
   实测计数：core `cjpm test` 42/42、`extjs` `node --test` 10/10、`bridge` 16/16、npm 产物 `dsh.exe ext` 裸 PATH rc=0。
   **剩余**：仓颉侧尚未 spawn `extjs` 进程。原报的前置「需 `std.sync` 并发读子进程 stdout」本批已就位
   （`spawn` + `ThreadSafeDeliveryQueue.await()` 有界等待已实测），接线仍欠：子进程句柄、退出结算与取消联动。
5. **写租约残留与 TOCTOU —— FAIL**：进程崩溃后 `.lease` 无人接管；`std.fs` 无 O_EXCL，
   需 CFFI 绑 `CreateFileW` 或改原子 rename（参照插件 `cangjie-lang-features/cffi`）。
