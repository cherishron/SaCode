## 三、统一命名规范

1. **目录名**：全小写、复数、按主题（guides / product / architecture / design / specs / plans / decisions / release / verification）。
2. **文件名格式**：`<type>-<topic>.md`
   - 类型前缀：`guide-`（指南）、`prd-`（产品需求）、`plan-`（实施计划）、`spec-`（技术方案/规格）、`design-`（设计规范）、`ref-`（参考文档）、`adr-`（决策记录）、`report-`（背景报告）、`release-`（发布记录）、`verification-`（验收）、`schema-`（SQL/DDL）。
3. **去除冗余后缀**：`-implementation-plan` → `plan-`；`-upgrade-plan` → `plan-`；避免在同一文件名里重复「plan」。
4. **版本/阶段**：阶段或版本放进 topic（如 `plan-desktop-multi-agent`、`release-1.1.1`），不在前缀里区分。
5. **JSON/SQL**：同目录放置，`schema-` 前缀用于 SQL。
6. **中文文档**：标题与一级标题统一；废弃文档在文首加「状态：已废弃 / 被 X 取代」声明，不物理删除（保留历史）。

## 六、交叉引用修正方案

移动/重命名后，以下相对路径引用会失效，执行时将统一重写：

1. `docs/README.md` → 重写为全量导航索引（按新结构）。
2. `docs/product/roadmap.md` 中 `../report.md`、`../report-plan.md`、`desktop-multi-agent-prd.md` 等 → 指向 `product/reports/report-feasibility.md`、`product/reports/report-improvement-plan.md`、`product/prd-desktop-multi-agent.md`。
3. `docs/product/prd-*.md` 间相互引用（如 `desktop-ga-release-prd.md` 引用两份审计报告）→ 更新为稳定文件名（审计报告建议也纳入本整理或保持根级并固定名）。
4. `docs/compose/spec/*` 被多处引用（`../compose/spec/...`）→ 改为 `../specs/spec-...`。
5. `docs/design/*`、`docs/reference/*` 引用 → 相应更新。
6. 执行后跑一遍 Markdown 链接检查（相对路径 404 扫描）并修复残留。
