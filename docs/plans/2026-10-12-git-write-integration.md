# Git 写操作完整接入方案（待用户批准）

## 1. 目标与当前事实

承接用户“进行 Git 写操作等功能接入”。本轮主项为 F08 的暂存、取消暂存、提交、历史与推送，保留文件/hunk选择、既有暂存保护、hooks/签名和失败恢复要求；不将“等功能”扩展成对数据库/SSH/扫描等全部领域的无限实施授权。

当前只有 `workspace/git-status`、`workspace/git-diff` 只读链：GitWorkbench → preload → main → Host → `queryWorkspaceGit`。页面明示写操作未开放。`core/src/git_workbench.cj` 为其他会话未跟踪文件；main、preload、Host、approval及桥接测试存在其他会话改动，不能覆盖或代为提交。

本文件仅为设计，未执行任何Git写命令、未修改公共接线、未跑构建或测试。

## 2. 授权边界

- 实现产品能力不等于批准对当前开发仓库执行暂存、提交或推送。主仓仅允许status/diff/log等只读核对。
- 验证只使用 `apps/desktop/.tmp-test/git-write-<独立标识>/` 下自有仓库及本地bare远端，夹具命令限于这些精确路径；不使用真实远端、密钥或用户Git身份。
- 提交/推送每次先展示实际范围、提交信息或目标远端/ref/commit，再消费绑定不可变提案的一次性工单。模式、计划批准、旧审批不能替代本动作批准。
- 无 `add .` / 无路径的 `add -A`、reset --hard、clean、amend、force push、自动stash、改Git配置、跳hooks或关闭签名的入口。
- 安装新工具、收费模型调用、修改当前仓库Git登记均不在本批范围。

## 3. 技术决策

### ADR-GIT-01：共享核心唯一派发，禁止壳层自行执行Git

新增独立核心Git写服务和有限协议解析模块；argv由动作类型构造，不接收客户端命令/任意argv。Host和CLI复用；Electron只适配具名动作。保持原只读实现，不改其他会话未跟踪文件。

代价：新增核心契约和两入口接线；收益：同审批、观察、审计和失败语义，不造第二业务真源。

### ADR-GIT-02：提案→精确审批→复核→执行→实际回读

提案绑定会话、工作区修订、canonical仓库/git-dir/common-dir、HEAD、索引版本、选中路径及内容、动作参数。采用既有 `ApprovalDesk.consumeExactForCall`（实施前复核最新签名）；副作用前落准入事实并通过既有持久屏障，失败则不执行。

Git实体状态通过Git本身和实际文件读取核验，动作归属/审批/结果进session.log。持久失败、超时或崩溃不自动重发；“可能执行但无法结算”显式unknown，不伪造回滚。

### ADR-GIT-03：保护索引，不用检查后直接覆盖掩盖竞态

选择文件为literal pathspec，禁止目录级展开、.git路径、越界/链接越界和隐式全选。若更新同一文件会替换原有部分暂存，必须显示原索引与将写入内容并单独确认，不把用户既有暂存偷偷吞入。

核心需在实际索引锁保护下复核提案，并使用可核验的事务/私有索引计算改动；最终发布前验证索引身份和字节版本。不直接用两个相隔的Git命令冒充CAS，不强删其他进程index.lock。linked worktree、无HEAD、split/sparse index与冲突索引分别明确支持或拒绝；不能假定.git是目录。

实现前须完成Windows原子发布与Git锁交互验证。部分暂存采用绑定基线的受控patch提案；不接受未经解析的客户端任意patch或用户可控Git选项。

### ADR-GIT-04：Git能运行外部代码，授权与隔离不可绕过

add可能触发clean/process过滤器；commit/push可能触发hooks、签名工具、credential/helper或外部传输。不能将Git视为纯文件API，也不能使用shell工具已授权来替代这些步骤的授权。

保留hooks和签名配置，拒绝自动跳过或弱化。凡需执行仓库/外部代码的路径必须经既有受控执行与隔离准入；当前产品provider未通过时保持明确BLOCKED。预检只能提供风险信息，不能靠只扫描配置宣称强隔离已成立。审批描述包含这些依赖及可能副作用。

## 4. 拟议有限动作（名称为提案，非当前已有API）

| 域 | 操作 | 结果与保护 |
| --- | --- | --- |
| 查询 | history、staged-review、remote-targets | 分页/限额、无外部diff/textconv；URL脱敏，不输出凭据 |
| 提案 | stage-propose、unstage-propose、commit-propose、push-propose | 返回固定动作身份、不可变摘要与审查内容，不执行副作用 |
| 执行 | action-apply | 只收动作ID、预期修订和approvalId；不接任意命令，不允许票据移用 |
| 观察 | action-describe | applied/failed/unknown/blocked，实际Git状态和审计关联 |

提交默认审查整个实际索引，不能承诺“只提交本轮AI修改”却暗带用户暂存。若提供选中内容提交，需要独立说明索引保持方式及hooks消费的真实索引，不随意借--only绕过提案。

推送只开放单一已展示的remote与明确refspec，无force/mirror/all/tags自动扩展。远端状态验证与命令返回分别登记；断连/超时结果unknown，不自动重试。hook失败或签名失败保留索引，不显示已提交。若HEAD已改变但结算失败，展示实际commit而非再提交一次。

## 5. 实施顺序（全部需求保留）

1. **独立核心与契约**：新增Git动作/提案/守卫/索引事务模块及专属测试；历史查询；精确审批、持久屏障、失败模型。避开既有dirty文件，不接公开入口前不声称产品可用。
2. **暂存与取消暂存闭环**：文件及hunk范围、无HEAD、索引并发、工作区不变及既有暂存保护；页面审查和真实回读。
3. **提交与历史闭环**：索引审阅、消息、hooks/签名、实际HEAD结果、失败/unknown和恢复；不自动写用户身份配置。
4. **推送闭环**：目标审查、单refspec授权、冲突/拒绝、hooks/凭据边界与不确定结果；仅自有本地bare夹具验收，不实际推公网。
5. **公共入口与交付**：与其他会话确认Host/CLI/main/preload/app.js/桥接测试的写入窗口，按当前内容做最小接线；同步能力表与有限IPC集合，构建隔离产物后做真实页面与双入口复验。未取得窗口时交付独立模块和接口单，不覆盖其他会话改动。

## 6. 验收与风险

- 正向：选中路径/hunk暂存、取消暂存不改工作区；空仓首次提交；中文/空格/路径spec字符；既有暂存不丢；历史分页；自有远端推送实际ref一致。
- 拒绝：无票/错票/重复票/过期票、会话/目录/HEAD/index/选中文件陈旧、.git/越界/目录路径、非Git、冲突索引、在途切工作区、隔离未就绪。
- 失败：index锁占用、只读存储、短写/持久失败、hook拒绝、签名失败、Git缺失、输出截断、超时、执行后回读失败；不能以exit0替代结果核验。
- 恢复：副作用前后崩溃、审批后外部修改、两个入口同时写、结果迟到，未知动作不自动重做。
- 证据分别标核心/受控夹具/真实Host/真实页面/打包态。现有全套绿色不是新增Git能力验收。

参考需求：PRD F08、DV05/DV06。Git官方文档已通过Context7 `/git/htmldocs` 核对literal pathspec、add范围、restore --staged、无HEAD差异、hooks/签名和push；具体命令/API实施时按所用Git版本继续核验。

## 7. 待用户批准与协调

建议批准以上Git专项范围，并允许第一步在全新模块与自有临时仓库开展。公共dirty文件仍需协调写入窗口；不因批准专项就推定已有修改归属。执行隔离无法满足的动作保持拒绝，不以解除disabled或硬改providerAvailable完成接入。
