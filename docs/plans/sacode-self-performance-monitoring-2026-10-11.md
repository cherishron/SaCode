# SaCode 自身性能监控方案

- 日期：2026-10-11
- 状态：设计方案，尚未实现、未运行验收。
- 用户已确定范围：先监控 SaCode 自身，不监控用户开发的目标应用。
- 本轮交付：保存方案；不修改业务代码、不安装依赖、不提交或发布。

## 1. 目标与范围

为 SaCode 提供本地性能诊断能力，覆盖 Electron 主进程、渲染进程及由 SaCode 管理的仓颉 Host；daemon 仅在具有明确实例身份与采集连接时纳入。指标必须注明采集来源、单位、时间、进程身份和支持状态，不能将缺失数据填零，也不能把估算值标为平台实测值。

完整保留图示中的 CPU、内存、FPS、掉帧、卡顿、交互响应延迟、存储、流量、崩溃、异常退出及耗电指标。当前 Windows/Electron 接入与未来 Linux、OpenHarmony 平台适配分别验证；图中的平台监控结构仅作能力参考，不证明本工程具有对应平台接口。

不包含：目标应用性能分析、整机监控、自动优化、自动重启、远程云端监控和诊断数据上传。

## 2. 当前源码依据

- `apps/desktop/renderer/pages/general-settings.ts` 的 `SaCodePerformanceSetting` 目前只展示“用量统计由模型中心管理”，不提供性能采集。
- `apps/desktop/renderer/pages/workbench-tabs.ts` 已提供右侧资源标签入口，可在该结构中接入监控页。
- `apps/desktop/package.json` 定义 Electron、页面构建与打包清单；新增运行时模块必须纳入载荷检查。
- `core/` 是共享业务核心；`apps/host/` 为桌面管理的仓颉进程。Electron 资源读数与页面帧采样属于平台诊断，不应伪装为会话业务事件。

以上是本轮静态观察，不证明采集接口、产品入口或运行效果已经实现。实施前应按符号重新核对源码，不依赖固定行号。

## 3. 架构与职责

```text
Electron 进程采集 ────────┐
渲染端帧与交互采样 ──────┤
Host/daemon 进程适配 ────┼→ 本地监控聚合 → 有限 IPC → 右侧性能监控页
存储与请求计量 ─────────┤         │
崩溃与退出生命周期 ─────┘         └→ 有界趋势、异常记录与显式导出
```

| 部分 | 职责 | 禁止职责 |
| --- | --- | --- |
| 平台采集器 | 读取所管理进程资源、生命周期及平台支持信息 | 扫描无关进程、按名称绑定别的会话进程、执行用户任意命令 |
| 渲染采样器 | 前台帧间隔、事件循环停顿、已定义交互的时间点 | 将后台节流算作掉帧、上传页面正文 |
| 请求计量 | 在真实请求生命周期记录允许的耗时与字节数 | 读取或保存密钥、请求正文、响应正文 |
| 本地聚合 | 单位规范化、进程身份、支持状态、保留窗口与异常分类 | 维护第二份会话业务真源、缺值填零 |
| UI | 展示实时值、趋势、异常和指标口径 | 自行推算耗电、将不支持项展示为正常 |

建议按现有插件装配边界贡献页面；采集器不能通过插件绕开有限 IPC、授权或隐私约束。不新增“调用任意监控方法”或任意路径访问通道。是否需要共享仓颉采集接口，应在实施时根据真实可用 API 核实，不为了统一接口强行把 Electron 指标搬入 core。

## 4. 指标与口径

| 指标 | 采集方向 | 展示及限制 |
| --- | --- | --- |
| CPU | Electron 进程指标；Host/daemon 使用平台进程采集适配 | 显示每进程占用及趋势，明确百分比归一化口径与采样间隔；不混加不同口径 |
| 内存 | 每进程工作集/驻留量及可获得的私有内存 | 明确内存类型；共享内存不能简单相加后称为实际总物理占用 |
| FPS | 渲染端前台 requestAnimationFrame 帧间隔 | 仅反映页面回调节奏，不代表 GPU 呈现帧率；闲置页面不直接判性能差 |
| 掉帧 | 基于帧预算和实际帧间隔估算 | 标注“估算”；显示采样窗口与预算，不能默认所有屏幕为 60Hz |
| freeze / 卡顿 | 主进程事件循环延迟、渲染端停顿、Host 有界心跳 | 分别显示事件循环停顿与宿主无响应；慢工具或慢模型不直接归为卡死 |
| 交互延迟 | 指定用户交互到首次可见反馈 | 定义起止事件；与 IPC 往返、工具耗时、模型首字耗时分列，不用单值混称响应速度 |
| 存储 | SaCode 管理的日志、附件、缓存目录占用 | 显示统计范围和更新时间；文件大小不是磁盘 I/O 速率，不扫描用户工作区 |
| 流量 | 已接入计量的 SaCode 请求上下行字节 | 标明应用层统计范围；编码、压缩、TLS 与协议开销不混称线上实际流量；未覆盖子进程显式列出 |
| crash | Electron 崩溃事件及可用平台崩溃记录 | 区分异常事件与实际 dump 可用性；崩溃记录默认不上传 |
| 异常退出 | 受管理进程退出码、信号、停止意图及生命周期 | 区分正常退出、非零退出、主动终止、崩溃和原因未知，不凭退出码单独推断崩溃 |
| 耗电率 | 平台可靠功耗接口或专项测量 | 未取得可靠接口时显示“不支持”；CPU 占用、电池电量变化不是进程实际功耗 |

Host/daemon 指标不能假定 Electron 的进程指标自动覆盖。绑定以启动时持有的进程对象和实例身份为准，考虑 PID 复用；远程 daemon 与本地实例分开标识。进程退出后终止该实例采样，旧样本不得串给新实例。

## 5. 采样与数据模型

建议资源采样周期为 1 秒，内存趋势保留最近 10 分钟；存储统计默认每 60 秒刷新且禁止扫描任务重叠。周期和保留量是设计默认值，不是已验证的性能保证。指标关闭或应用退出后必须撤销定时器、观察器和监听器。

每条样本包含：指标名、进程角色、实例身份、采样时间、采样窗口、数值、单位、数据来源、质量状态及缺失原因。支持状态至少区分“可用、估算、不支持、暂不可用、采样失败”；尚未采集与真实零值不同。

耗时使用单调时钟；人类可读的记录时间使用墙上时钟。计数器复位或实例切换时不产生负速率。后台窗口、最小化和休眠恢复时停止或重置帧窗口，不把跨越休眠的间隔记为掉帧。冻结检测阈值须注明并通过可控停顿实验验证，不将初始阈值视为行业通用标准。

趋势默认只在内存中有界保留；异常元数据本地持久化，建议上限 200 条、最长 7 天，两项同时约束。异常写入必须限频，不为每次正常采样写盘。崩溃 dump 由独立机制生成和管理，不假定本进程崩溃后仍能写入记录；下次启动只能将未正常关闭标为“上次非正常结束，原因未知”，不能自动判 crash。

## 6. 产品界面

右侧新增“性能监控”资源标签，不将监控塞入中央 Agent 主流程。

- 概览：CPU、内存、帧节奏、卡顿、交互延迟及支持状态。
- 进程：角色、实例、资源趋势与最近采样时间。
- 存储与流量：范围、累计值、速率和更新时间。
- 异常记录：时间、角色、类型、退出信息和诊断数据是否可用。
- 口径说明：明确估算指标、未覆盖对象与平台不支持项。

关闭标签后停止页面专属采样与刷新；低频资源和异常监听是否继续由监控开关控制。停用监控不关闭或终止 Host/daemon。设置页提供监控开关、保留策略及清理诊断记录入口；清理诊断记录不得删除会话日志、附件或业务数据。

导出必须由用户显式操作，经受控保存流程输出有限指标和异常元数据，不包含请求内容、凭据、完整环境变量或用户源码。导出取消不报成功。

## 7. 安全、隐私与故障隔离

- 默认本地处理，无遥测上传、第三方服务或收费依赖。
- 不收集模型正文、请求头、API Key、命令参数及会话内容。平台 crash dump 可能含敏感内存，查看和导出前必须明确提示，不自动附加到普通诊断导出。
- 渲染端上报限定字段、大小与频率，主进程验证有限数值和允许的指标，拒绝越界或伪造进程身份。
- 主进程只接受固定监控动作，不接受任意路径、PID、命令或脚本。
- 单个采集器失败只影响对应指标，明确显示原因，不阻塞发送消息、审批、工具执行或关闭窗口。
- 诊断存储不写入 session.log，不影响其唯一业务真源规则。

## 8. 实施顺序与接入点

完整范围不删项，下列只是依赖顺序，不将某个切片交付称为整个监控完成。

1. 核实 Electron 与平台官方 API，冻结各项单位、支持范围和进程归属；为 Host/daemon 指标确认实际采集路径。
2. 定义有界样本、缺值与异常模型，完成纯数据处理测试；建立可注入时钟与可控采集输入。
3. 接入主进程资源、进程生命周期和异常记录，补启动、退出及监听清理测试。
4. 接入渲染帧节奏、停顿、交互与有限 IPC，验证隐藏、休眠、重开和实例切换。
5. 接入受控存储扫描与实际请求计量，逐项标记覆盖范围，不以计数模型 tokens 代替网络流量。
6. 注册右侧页面、设置开关、清理与导出，同步 preload、桥接测试、页面构建和打包依赖清单。
7. 运行真实 Electron 和新打包产物，验证资源读数、异常路径、隐私及监控开销。

候选源码接入点：`apps/desktop/main.cjs`、`preload.cjs`、`host-bridge.cjs`、`renderer/pages/workbench-tabs.ts`、`renderer/pages/general-settings.ts` 及相关测试。新模块的具体路径在实施前按现有装配机制确定；本方案不声称这些文件已有监控实现。

## 9. 验收标准

| 门槛 | 必须验证的结果 |
| --- | --- |
| 真实资源 | 正常和可控负载下显示实际 CPU、内存变化；注明进程身份与口径，未知进程不冒认 |
| 帧与后台 | 可控渲染停顿出现对应读数；最小化、隐藏、休眠不制造掉帧记录，恢复后窗口重新开始 |
| 卡顿归因 | 主进程停顿、渲染停顿、Host 无响应分别可辨认；慢网络不误判成 UI 冻结 |
| 延迟 | 已定义交互与 IPC 的起止可验证；失败或超时另计，不填正常耗时 |
| 存储与流量 | 受控夹具增删反映占用；本地 HTTP 夹具核请求/响应字节口径，未覆盖对象明确标注 |
| 退出与崩溃 | 正常关闭、主动停止、非零退出及专用测试进程崩溃分类正确；不破坏用户运行中的实例 |
| 缺失与不支持 | 耗电及无采集接口指标显示原因，不用 0 或静态模拟值冒充实测 |
| 生命周期 | 多次开关、开关标签、切换实例和退出后，采样器、监听器及自有测试进程无残留 |
| 隐私与边界 | 故意放入凭据标记的夹具不出现在持久记录或导出中；畸形上报、任意路径/PID 请求被拒绝 |
| 有界数据 | 时间窗、条数、容量与扫描并发受限；计数复位不产生负速率 |
| 开销 | 同一构建、同一受控负载比较开关前后 CPU、内存、写盘及交互延迟，保存实际差值；目标预算实施前确定，不编造已达标结论 |
| 打包态 | 新产物确含采集与页面模块，并实际打开监控页验证；单测全绿不能替代运行验收 |

测试按采集计算、IPC、页面状态、真实进程与打包态分层。对关键不变量做变异反证：缺值改成零、窗口隐藏仍累计帧、实例切换保留旧计数或异常退出一律判 crash，必须让指定断言失败。所有结果记录实际测试数和退出码，跳过与取消逐项说明。

## 10. 本轮结论

可以为 SaCode 接入自身性能监控，但当前没有该采集链路的运行证据。Windows/Electron 的可采集指标、Host/daemon 覆盖及耗电支持须按上述规则核实；本文件只保存设计，不宣称已实现或验收通过。
