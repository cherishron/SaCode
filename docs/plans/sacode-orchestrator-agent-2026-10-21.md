# SaCode 调度者 Agent 与团队方案

- 日期：2026-10-21
- 状态：设计提案，未实现、未验收。
- 定位更正：取代 `sacode-local-agent-presets-2026-10-11.md` 的"标准/PTC/极简/创造"四模式方向；原方案的存储/作用域/修订/导入导出与生命周期约束仍可复用，但"模式=给当前 Agent 选工具集"的核心定位废弃，改为"本地 Agent 是调度者，委派 subagent 团队执行"。
- 本轮授权：保存方案，不修改业务代码、不提交或发布。
- 关联：[原预设方案](sacode-local-agent-presets-2026-10-11.md)、[扩展市场方案](sacode-extension-market-2026-10-11.md)、F10 ACP 协作、F06 编排与扩展。

## 0. 比喻与角色

| 层 | 比喻 | 职责 |
| --- | --- | --- |
| 用户 | 老板 | 设定团队、授权、审批、验收 |
| 本地主 Agent | 管理层 / 调度者 | 接任务、按 subagent 能力调度、汇总结果；不亲自干重活 |
| subagent | 员工 | 独立 context、角色边界内执行；可调本地工具，可调 ACP 能力（角色给了就能调） |
| 外部 ACP Agent | 外部供应商 | 被 subagent 通过 ACP 调用；权限边界继承委派它的 subagent |

核心原则：**委派原语唯一 = subagent**。主 Agent 不直接做重活，只调度；ACP 是 subagent 可持有的一个**能力/工具**，不是顶层第二条委派通道。

## 1. 委派与能力模型

```
用户任务
   ↓
本地主 Agent（调度者）
   └─ 委派 subagent（独立 context、角色工具集、独立审批）
         │
         ├─ 自己执行（本地工具集，走核心授权/审批/日志）
         └─ 通过 ACP 调用外部 Agent（角色工具集授予了 ACP 能力才能调）
              ↑ 外部 Agent 在 SaCode 侧的权限边界 = 委派它的 subagent 的边界
```

- 主 Agent 直调 ACP：**默认关闭**，需用户在设置里单独勾选；仅用于短查询。重活走带 ACP 能力的 subagent，避免外部输出污染主 context。
- subagent 调 ACP：**默认开启**（仍受三层门控：全局 ACP 开关 + 外部 Agent 已认证 + 角色工具集勾选了 ACP 能力）。

## 2. ACP 作为能力的开关与策略

开关在**设置里预先配好**，不是运行时现问。分三层：

| 层 | 控制内容 |
| --- | --- |
| 全局 | 是否允许本会话使用 ACP（总开关） |
| 每个外部 Agent | 是否启用、是否已配置+已认证、优先级、额度耗尽/限流时的降级行为 |
| 每个 agent/角色 | 主 Agent / 每个 subagent 角色是否被授予 ACP 能力 |

### 多个外部 Agent 启用时的调度策略

- **默认：顺序按优先级**——优先用排在前面的，额度耗尽或限流（429/配额错误）再降级到下一个。符合"先用别人的额度省自己 token"动机。
- **可选：轮询**——把并行 fan-out 的不同 subagent 分散到不同外部 Agent，降低单家限流概率。
- 策略在设置里选；默认顺序。具体配额错误判定与降级规则实施前按 ACP 协议错误码与各厂商返回核实，不臆测。

### 已配置/已认证检测与 LLM 协助登录

- 设置页实时检测每个外部 Agent 的认证状态；未认证显示"需配置"，不能假装可用。
- 提供"让 Agent 帮我配置"入口：用 LLM 引导用户走该外部 Agent 的登录/授权流程（如 CodeBuddy OAuth）。
- 这是 **onboarding/设置流程**，不是运行时能力；不进调度链；不自动存储凭据，凭据走 SaCode 现有独立凭证通道（不写入日志/预设/导出）。

## 3. 权限一致性（"什么人干什么事情"）

外部 Agent **继承委派它的 subagent 的权限边界**，在 SaCode 侧执行：

- 工具集：subagent 角色允许的工具，才是外部 Agent 在 SaCode 工作区内可触达的（explorer 调 ACP，外部 Agent 也不能在 SaCode 工作区写文件）。
- 审批策略：沿用该 subagent 角色的审批策略（plan/build/auto/yolo 四档与 F20 一致）。
- 预算：外部调用消耗计入该 subagent 的预算上限。

外部 Agent 自己进程内的推理/工具是黑盒，但任何触及 SaCode 文件/终端/工作区的动作仍过 SaCode 审批门（F10 已有"委派面板与精确审批操作"，不丢）。**能力 = 可以申请，不是自动同意**：启用 ACP 能力只代表"可以请求调用"，每次实际 `session/prompt` 到外部 Agent 仍需审批。

这条原则把"能否调 ACP"问题降维成"该 subagent 角色有什么权限"，主 Agent 据此调度即可，不需要每次分析外部 Agent 能干什么。

## 4. subagent（员工）定义与团队

### 4.1 员工定义字段

| 字段组 | 内容 |
| --- | --- |
| 身份 | schemaVersion、稳定 id、名称、说明、定义修订 |
| 来源与范围 | 内置/用户自建/项目自建；用户级或项目级 |
| 角色描述 | description（主 Agent 据此决定何时委派）、职责、system prompt 正文 |
| 本地工具集 | 勾选 SaCode 既有能力：读/写/跑命令/浏览器/ssh/数据库/MCP/skill…（对齐 F02/F14/F15/F16） |
| ACP 能力 | 是否授予、可调哪些外部 Agent（继承角色权限边界） |
| Skill 引用 | 稳定身份及作用域；运行时记录实际解析版本 |
| 模型 | 沿用当前选择或引用模型配置（可指定快模型，如 explorer 用快模型）；不含密钥 |
| 预算 | 轮次、token、工具调用、时间限制；不允许扩大用户授权上限 |
| 权限申请 | 希望使用的能力，不是自动批准记录 |

有效权限取系统策略、用户授权、会话策略与角色工具集的交集；system prompt 与权限申请不能放宽该交集。缺依赖、工具未知、模型不可用或 Schema 非法时返回明确诊断，不自行更换模型或降级工作方式。

### 4.2 预设团队

内置一个小默认团队，可复制后自定义：

| 角色 | 本地工具 | ACP 能力 | 模型 | 典型场景 |
| --- | --- | --- | --- | --- |
| explorer | 只读（grep/read/glob） | 默认开（但 explorer 只读，外部 Agent 也只读） | 快模型 | 并行搜索、读代码、不污染主 context |
| planner | 只读 | 默认开 | 默认 | 出方案、出计划，不改文件 |
| implementer | 读写+跑命令 | 默认开（可调外部 Agent 处理陌生生态） | 默认 | 落地修改、跑测试、需审批 |
| reviewer | 只读+扫描 | 默认开（可调外部 Agent 做对照审查） | 默认 | 代码审查、安全扫描 |

内置员工不可直接覆写，可复制后自定义。新任务默认由主 Agent 按各员工 description 自动调度；用户可在任务入口指定偏好员工或团队。

### 4.3 创建、编辑与使用

1. 用户从内置员工复制，手动编辑，或点"让 Agent 帮我创建员工"。
2. AI 生成候选定义，说明工具、依赖、权限；生成结果是未信任草稿，不自动保存启用。
3. 校验定义、依赖、模型、平台支持与工具集合，展示与原修订差异。
4. 用户确认保存范围和内容；默认团队/员工变更单独显式选择。
5. 创建新任务时解析团队与员工，冻结修订、工具集合及依赖版本，进入共享运行时。
6. 工具调用（含 ACP 调用）继续走核心授权、参数校验、审计和结果归一化。

员工编辑器用 checkbox 快捷勾选 SaCode 既有能力（读/写/跑命令/ACP/skill/MCP/浏览器/ssh/数据库…），勾选项映射到角色工具集；不允许手写逃逸工具或越权组合。

### 4.4 跨会话与作用域

- **定义持久化**：用户级与项目级同名员工在 UI 保留来源区分，引用使用作用域与稳定 id。项目级定义首次使用需信任确认，不因打开仓库自动生效；项目默认团队只对可信项目生效，不覆写全局默认。
- **运行实例 session 内**：subagent 运行实例不跨会话泄漏中间态。任务恢复优先使用记录的快照修订；依赖撤销或授权收紧时立即遵守新限制，不以旧快照绕过撤权。
- **跨会话 Teams 协作**（Cline 那种 P2P task board/mailbox/mission log）列为后续阶段，不在本轮；本轮先把"单会话内调度者+员工"做实。

## 5. 用量与额度记账

F06 的 ContextMeter / usage 增加一个**来源维度**：

- 本次调用走**本地 token**（用户供应商凭据）还是**外部 Agent 额度**（CodeBuddy/OpenCode 自己的账）。
- 调的是哪个外部 Agent、消耗多少（若对方协议返回）。
- 顺序降级时的"耗尽→降级"事件记入会话日志，可回放。

否则用户看不到"省了多少 token"，ACP 能力等于白给。具体字段名实施前按现有日志协议与 usage RPC 冻结，不臆造 API。

## 6. 主 Agent 直调 ACP 的边界

- **默认关闭**，需用户在设置→Agent 功能里单独勾选。
- 勾选后仅用于**短查询**；重活交给带 ACP 能力的 subagent，避免外部输出污染主 context。
- subagent 调 ACP **默认开**，但仍受三层门控（全局开关 + 外部 Agent 已认证 + 角色工具集勾选 ACP）。

这个默认（主关、子开）形成自然分工：主 Agent 用本地工具+本地 token；要省 token 或要隔离外部噪音时走 subagent。

## 7. 系统接入

共享核心负责团队/员工定义解析、作用域、修订、依赖解析与有效工具集（含 ACP 能力映射），桌面和 CLI 使用同一权威。UI 不自行拼接另一套系统提示或绕开核心工具过滤。

```text
团队/员工定义 → 校验与依赖解析（含 ACP 能力） → 启动快照
                                              ↓
                              共享 Agent 运行时与工具目录
                                              ↓
            主 Agent 调度 → subagent 执行（本地工具 / ACP 调用）
                                              ↓
                         权限 / 审批 / 执行 / 会话日志（含额度来源）
```

候选接入域：共享 Agent、系统提示、工具注册、Skill、MCP、ACP 委派面板、模型中心额度记账、F20 设置页（ACP 开关与认证）、F06 用量面；需逐项核现有实现，避免重复开发。现有目录和类名存在不证明调度者模型已闭环。

按日志唯一业务真源原则：影响模型行为的最终指令、工具目录、团队/员工选择、ACP 调用与额度来源必须由可重建的会话记录表达，并排除密钥。格式与事件名称实施前按现有日志协议冻结。

## 8. 安全与失败处理

- 员工 system prompt 不能修改审批策略、获取凭据或逃逸工具集。
- ACP 能力不等于免审批；每次外部 `session/prompt` 仍需审批，沿用 F10 精确审批操作。
- 外部 Agent 继承 subagent 权限边界；explorer 调 ACP 也不能让外部 Agent 在 SaCode 工作区写文件。
- MCP/Skill 引用不隐式安装、启动服务或触发认证，依赖缺失时显示待配置。
- 删除、禁用或更新员工定义不擅自杀死正在执行的任务；必要的停止操作另获用户授权。
- 员工/团队导出不包含密钥、运行中的工单、会话内容或用户环境变量。
- 创建模式生成的员工与团队仍属待审内容，不自动成为可信扩展。
- 多外部 Agent 顺序降级失败不静默重放未知副作用；限流/耗尽如实记录。

## 10. 实施顺序与验收

依赖顺序：冻结团队/员工定义与 ACP 能力语义 → 设置页 ACP 开关与认证检测（含 LLM 协助登录） → 共享运行时 subagent 委派原语 → 内置团队四角色真实执行路径 → ACP 能力映射与权限继承 → 额度来源记账 → 主 Agent 直调（可选）→ 管理界面与 CLI → 打包态验收。依赖顺序不是范围裁剪，全部能力与自定义完整保留。

| 验收面 | 必须结果 |
| --- | --- |
| 定义与持久化 | 手写、复制和生成的员工定义均校验；重启后保留；非法定义不污染旧版本 |
| 并发编辑 | 旧 expectedRevision 被拒绝，桌面/CLI 不互相静默覆盖 |
| explorer | 真实并行搜索、只读、用快模型；不污染主 context |
| planner | 真实出方案、不改文件、只读工具生效 |
| implementer | 真实写文件/跑命令、需审批、预算生效 |
| reviewer | 真实代码审查/扫描；可调外部 Agent 做对照审查且权限继承 |
| ACP 能力 | subagent 调 ACP 走审批；外部 Agent 继承 subagent 权限边界；explorer 调 ACP 不能写文件 |
| 主 Agent 直调 | 默认关闭；勾选后仅短查询；重活仍走 subagent |
| 多外部 Agent 策略 | 顺序降级正确触发并记账；轮询模式可选 |
| 额度记账 | 本地 token 与外部额度分列；降级事件可回放 |
| 生命周期 | 修改不污染在途快照；撤权生效；删除员工不删除会话和依赖 |
| 本地范围 | 用户/项目同名不串用；未信任项目不自动启用团队 |
| LLM 协助登录 | 引导流程不自动存凭据；未认证显示"需配置" |
| 双入口与恢复 | 桌面、CLI 对同一员工修订一致，任务恢复可重建实际选择 |
| 交付 | 新构建的桌面与 CLI 真实验证，不用单测或静态 UI 代替 |

关键反证：故意让 explorer 调 ACP 写文件、让主 Agent 在未勾选时直调 ACP、让外部 Agent 绕过审批、让修改在途任务读最新定义或让项目自动启用团队，指定测试必须转红。测试报告带真实计数、退出码及凭据/环境前提，不用旧 PASS 推定当前完成。

## 11. 本轮结论

调度者+员工团队模型可行，取代原"四模式"预设方向。ACP 作为能力的定位把"省自己 token"的真实用户诉求显性化。本轮仅保存设计，不修改业务代码、不提交或发布；实施前需逐项核 ACP 协议错误码、各外部 Agent 认证流程与现有运行时契约，不臆测 API。
