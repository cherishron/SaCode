# SaCode 扩展市场方案

- 日期：2026-10-11
- 状态：设计提案，未实现、未验收。
- 本轮授权：保存方案，不安装扩展、不修改业务代码、不提交或发布。
- 用户裁决：扩展市场与 Agent 分开设计；市场包含 Skill、MCP、Plugin，Agent 采用本地预设，见 [Agent 方案](sacode-local-agent-presets-2026-10-11.md)。

## 1. 目标与边界

提供统一的扩展发现、详情、安装、配置、启用、更新、停用和卸载入口。用户既可从社区选择，也可导入本地目录、包或指定仓库，不依赖 SaCode 官方账号或发布服务。

市场是能力发现与管理入口，不是执行授权。浏览、安装、配置、启用和具体工具执行分别处理。社区支持某种客户端不证明兼容 SaCode，必须完成格式与运行契约核验。

## 2. 三类扩展

| 类型 | 安装对象 | 使用方式 |
| --- | --- | --- |
| Skill | 含 SKILL.md 与必要参考资源的目录 | Agent 按需读取说明；附带脚本不在安装时自动执行 |
| MCP | 服务连接定义或本地服务安装包 | 用户确认启动/连接后动态发现工具，再通过核心工具流水线调用 |
| Plugin | 声明能力与依赖的组合包 | 按既有插件边界贡献工具、Skill、MCP 配置或页面，卸载时撤销贡献 |

MCP 工具不是逐个下载安装的商品；它们归属于已连接的服务。展示完整工具 Schema、服务身份及连接状态，不能把服务列出工具等同于实际调用成功。

## 3. 来源接入策略

采用“精选来源 + 用户添加来源 + 社区发现”的组合。每个来源适配器分别声明发现、下载和版本解析能力，不假设所有网站具有公共 API。

| 候选来源 | 本轮证据 | 设计处理 |
| --- | --- | --- |
| skills.sh | 网站与固定版本 CLI 的只读查询可用 | 可研究检索适配；公开接口、使用条款及 SaCode 安装目标仍须核实 |
| SkillsMP | 页面提供 GitHub 技能聚合目录 | 公共接口与访问条件核实前仅作浏览/仓库发现入口 |
| SkillHub | 页面简介可获取，完整安装机制未核实 | 候选来源，不宣称可直接安装 |
| Awesome Skills、tool.lu | 技能目录及仓库发现入口 | 回到上游仓库校验，不能据目录描述自动执行命令 |
| CangjieSkills | 用户指定 GitCode 仓库，目录与版本兼容尚未核验 | 作为仓颉精选候选，先核许可证、目录、固定版本与资源完整性 |
| Qoder 市场 | 本会话搜索接口可用，找到 Cangjie-SIG 的 Cangjie 1.0.0 插件，含 6 个 Skill | 仅为参考证据；不复用 Qoder 私有安装接口、账号、凭据或安装引用 |

Agent Skills 是格式规范，不是市场。GitCode 仓库与 Qoder 市场包的版本对应关系尚未确认，不能因同名就视为同一产物。

MCP 来源另行核对允许使用的公共注册目录或服务作者仓库；本轮没有完成 MCP 市场来源调研，不编造可接入清单。未经验证的来源保留为候选，不因此删减 MCP 市场范围。

## 4. 架构与数据

```text
来源适配 → 分类检索与详情 → 安装计划与用户确认
                              ↓
                  下载/导入 → 校验 → 本地扩展存储
                              ↓
           Skill 加载 / MCP 连接 / Plugin 装配
                              ↓
                    核心授权、工具执行与审计
```

共享核心管理扩展身份、版本、依赖、启用状态与授权边界。CLI 与桌面消费同一管理契约；桌面不另存第二套业务状态。平台下载、凭据与进程启动按既有边界接入，不能以实现方便为由把业务权威放到渲染层。

每个条目记录类型、来源标识、发布者、稳定身份、版本或提交、许可证、内容摘要、平台要求、运行时要求、依赖和请求权限。展示名不作为身份；不同来源同名条目不自动合并。安装记录与来源元数据分开，记录实际固定版本而非只保存漂移分支。

生命周期至少区分：未安装、安装中、已安装未配置、可启用、已启用、运行失败、待更新。更新失败保留原版本，启用失败不显示成功；格式有效不等于安全可信。

## 5. 安装与安全

1. 先展示实际版本、文件、依赖、许可证和权限变化，用户确认后下载或导入。
2. 使用独立暂存目录校验，不覆盖未知文件；拒绝绝对路径、路径穿越、越界符号链接和异常膨胀归档。
3. 校验来源重定向、下载大小与内容摘要；访问本地或内网地址需明确来源授权，防止隐式网络探测。
4. 安装阶段不执行仓库脚本、包管理生命周期钩子或自动启动 MCP；有必要的运行时安装另行确认。
5. 通过校验后原子切换版本；中断、失败和重启可恢复，不遗留半安装状态。
6. 所有更新先提示版本、内容、依赖与权限变化，用户确认后安装；权限或启动命令变化须明确展示，不静默扩权。运行中任务不强行切版，权限撤销立即限制后续执行，不能因保留旧版本而绕过撤权。
7. 卸载前检查正在运行的调用和依赖，说明影响；不得顺带删除其他扩展、业务数据或用户手写文件。

第三方描述、Skill 指令和 MCP 工具返回均是外部不可信数据，不得覆盖系统授权策略。来源标签不代表安全审计通过。

## 6. Skill 与 MCP 执行契约

Skill：核验 SKILL.md 元数据、名称、资源相对路径和大小限制；分离发现元数据与按需加载正文。用户级和项目级作用域明确显示，同名遮蔽可追溯，项目来源的启用须经信任确认。脚本执行进入现有工具授权流程。

MCP：完整处理连接配置、协议初始化、能力协商、工具发现与分页、Schema 保真、参数校验、调用结果、isError、超时、取消、断连和卸载清理。本地 stdio 与远程 Streamable HTTP 分别验证；其他传输只有完成适配才显示支持。认证要求按实际协议处理，不用客户端 token 冒充服务端授权。

工具身份包含服务器命名空间，重名不串服务。重连刷新工具目录，对可能已经产生副作用的调用不自动重放。工具权限声明和服务提示仅作为信息，不能自行授予写入或执行权。

密钥只保存到既有凭据设施，配置保存引用。日志、详情、安装记录及导出均不得含明文密钥。

## 7. 页面与双入口

桌面“扩展”管理页分为市场、已安装、本地导入和来源管理；类型筛选为 Skill/MCP/Plugin。详情显示来源、版本、兼容状态、依赖、权限及安装范围。MCP 详情附连接测试和工具目录，状态区分已配置、已连接、已发现和实际调用结果。

CLI 提供对称的检索、详情、导入、安装、配置、启停、更新与卸载能力。具体命令与 IPC 名称实施前冻结，不将设计名称当作现存接口。离线时已安装内容和本地导入仍可管理，社区失败按来源分别报告。

## 8. 实施与验收

依赖顺序：核现有插件/Skill/MCP 链路 → 定格式与来源契约 → 实现安装事务 → 接 Skill 加载与 MCP 工具运行 → 接 Plugin 装配 → 双入口 UI/CLI → 新产物验收。保留完整范围，不将检索页面完成称为市场完成。

| 验收面 | 标准 |
| --- | --- |
| 来源 | 各来源分别报告成功/失败，稳定身份与实际版本可追溯；无接口来源不假报安装支持 |
| 安装事务 | 正常、离线、中断、错误摘要、恶意路径与冲突都有确定结果；旧可用版本不丢失 |
| Skill | 安装后可发现并真实加载，资源引用完整；停用/卸载后不可继续加载 |
| MCP | 本地与远程分别验证真实工具读写、Schema、参数错误、业务错误、取消、超时和断连 |
| Plugin | 实际贡献随生命周期装配/撤销，不冒充外部插件源码全面兼容 |
| 授权 | 安装不执行、启用不扩权、更新权限重新确认；项目配置不能静默启动程序 |
| 凭据 | 有标记密钥的夹具不进入响应、日志、索引与导出 |
| 双入口 | 桌面与 CLI 对同一安装记录和状态一致，实例重启后可重建 |
| 交付 | 从新构建产物完成安装、使用、停用和卸载，不能用旧宿主或静态页面代替 |

实施前补做上游契约和当前源码审计；已有 SkillRegistry 登记、MCP 类或插件页面不证明市场生命周期闭环。本方案未运行实现验收。
