# OpenCode ACP：用户控制、诊断与后台修复

本文件承接用户本轮完整需求；不将协议探针、认证记录或单测当模型任务验收。仓颉共享核心是判据，Host/CLI 与桌面共用；修复必须复用现有任务、审批、执行与结算，不增加独立修复 Agent 或队列。

## 实施边界

协议已连接时普通配置风险只作警告，不阻断 OpenCode 委派。只有启动或协议等确定连接故障令该连接不可用。真实模型探测是独立用户操作，须明确数据与潜在费用；免费也不豁免确认。认证要求只取实际 ACP 错误，不运行自动登录，不另配 SaCode 模型池。

诊断不能只读取一个文件并宣称生效配置；无法验证插件动态路由、价格或端点时报告未确认。默认不做模型或网络请求。重启只在确认且无在途任务后进行；配置保存不等于已生效。

修复任务需要的目标配置若超出现有执行授权范围，先补契约与明确授权，不能通过任意 shell 命令绕过核心路径限制。安装、升级、额外网络验证分别授权。

## 必须通过的场景

关闭零启动；空认证仍连通；主模型正常但插件模型风险分列；保留现状不影响主任务；重复修复仅一个任务；并发修改不覆盖；审批/取消/失败/结算共链；切会话及后台通知不串身份；修改成功但复验失败如实展示。每项分别记录核心、真实 Host/CLI、桌面及产物证据，未实测保持待验。
