# SaCode 移动端扫码配对、可选 Relay 与受控 SSH 隧道方案

> 日期：2026-10-23。状态：设计提案，待评审；不是功能完成记录或部署授权。
> 基线：HEAD `a0b16c38a1147708f2ef75302695092f3d3ed833` 及编写时工作树。移动端、PRD 等已有并发未提交变更；本方案不改这些文件。
> 本轮只新增本方案。不改业务代码、不扩大方法白名单、不安装 SDK、不接入真实凭据、不部署公网服务、不提交或推送。

## 1. 结论与必要纠偏

**可以加入，推荐“扫码统一配对 + HTTPS 直连为默认 + Relay/SSH 为可选传输”，不替换 SaCode 业务协议。**

- 扫码解决输入和可信绑定；Relay 解决跨网可达；SSH 隧道服务已有 SSH 环境的高级用户。三者不是同一个能力，不要求同时上线。
- Relay/SSH 本身不会必然绕过安全控制；错误接到未受保护的本机端口、丢失目标身份或自动重发写请求才会造成绕过。
- 手机最终定位是完整移动工作台，不是永久只读遥控器。当前共享客户端仅开放三个只读方法，是阶段安全边界，不缩减最终产品需求。
- Host 的 `ssh/exec` 与“手机连接 daemon 的 SSH 隧道”是两个独立功能。现有 SSH 执行方案不含端口转发，不等于未来不能独立建设受控隧道。
- 不照搬参考项目的 Relay、AG-UI 或事件复用协议；其代码、许可、SDK 支持及可复用程度本轮未核实。

### 推荐顺序

```text
M04-A 安全只读入口/任务语义/初始化上下文
  → M04-B 直连真实任务、安全授权、取消与恢复闭环
  → M05-0 通道契约与平台能力探针
  → M05-1 扫码配对
  → M05-2 可选 Relay
  → M05-3 可选受控 SSH 隧道
```

M05 的协议设计、离线解析测试和 SDK 探针可以提前准备，但不能据此称移动远程任务已可用；正式通道产品验收依赖 M04 闭环。Relay 优先于 SSH 是面向普通手机用户的推荐顺序，不是两者的技术依赖。

## 3. 目标、非目标与收益

### 目标

1. 用户在电脑显式启用接入，手机扫码完成目标确认及设备登记。
2. 同网/公网 HTTPS 可达时默认直连；家庭 NAT 场景可选择 Relay；已有 SSH 环境可选择受控隧道。
3. 三种通道消费同一 daemon 认证、JSON-RPC、SSE、scope、工作区与会话归属规则。
4. 通道断开不伪报任务终止；断线未知态不自动重放修改/执行/审批。
5. Relay 可选、自建可用；直连不依赖任何云中转服务。

### 非目标

- 不把手机变成 SSH 通用终端，不在此切片加入 PTY、SFTP、跳板链、任意端口转发、SOCKS 或远程安装。
- 不替换 KuiklyMarkdown/ChatPage，不引入另一套 Agent 主循环。
- 不因连接成功而授予 execute、approval 或 management scope。
- 不自动开放路由器端口、修改防火墙、安装系统常驻服务或部署云资源。
- 不承诺手机退后台后永久在线；恢复前台按系统生命周期重连和补读。

### 取舍

| 能力 | 主要收益 | 主要成本/风险 | 定位 |
|---|---|---|---|
| 扫码 | 少输入、减少地址和指纹抄错 | 配对票泄露/替换、相机权限、证书绑定 | 首选增量 |
| Relay | 手机蜂窝网访问 NAT 后电脑，无需入站端口 | 中转运营、流量、延迟、元数据暴露与可用性 | 普通用户可选增强 |
| SSH | 复用用户已有 SSH 服务器和网络路径，不必运营 Relay | 手机密钥托管、主机信任、原生 SDK 与平台适配 | 高级用户可选 |

## 4. 总体架构：业务不变，传输可换

```text
手机：Kuikly 页面 / 账号与目标上下文
  └─ 统一 RemoteDaemonClient / RemoteAuthRepository / 事件恢复
       └─ 拟建通道适配层（不拥有业务授权）
            ├─ Direct：HTTPS ───────────────────────────┐
            ├─ Relay：外层加密连接 → 字节中继 → 反向连接 ┤
            │          内层手机 ↔ daemon TLS 不在 Relay 终止
            └─ SSH：受控直连 SSH → 固定 daemon TLS 端口 ┤
                                                        ↓
                  已启用远程门禁的 daemon → 单一 Host / core
                     认证 → scope/资源 → 幂等 → 沙箱/审批/执行
```

### 不可破坏的不变量

- **同一安全入口**：连接器只允许转发到显式启用远程认证/策略的 daemon TLS 入口。绝不把任意回环服务当安全入口，不连接 Host stdio 或未启用门禁的 daemon。
- **回环不是信任证据**：现有回环配置例外不作为 Relay/SSH 产品默认。新通道要求内层 TLS 与远程门禁同时启用；无法可靠证明配置时连接器拒绝启动。具体内部检查接口在 M05-0 定档，不拿客户端 initialize 成功代替证明。
- **地址不是身份**：绑定经核验的 TLS 身份、instanceId 和 workspaceId；路由 ID 只是定位，不是认证凭据。
- **连接不等于权限**：扫码/SSH/Relay 各自的认证只允许建链；业务仍须设备登记和 daemon token。scope 只从既有可信授权路径取得；该路径缺失则保持 blocked，不新增暗门。
- **不降级**：TLS、SSH host key、实例身份失败时不关闭校验、不换目标、不自动切成本地执行。
- **不跨源重发**：读取可有界恢复；写入/执行/审批发送后丢回执即 unknown，先查状态/事件/已有幂等结果。不通过换 operationId、换通道或重新发一次来“修复”。
- S08/S09/S10 与其他未完成安全审计的结论按当前候选重新验证；本方案不是整仓安全验收。

## 5. 扫码配对方案

### 5.1 提议的离线数据结构

采用版本化、固定类型的紧凑 JSON 配对包；首版只通过应用内扫描入口接收，不依赖浏览器 URL、第三方短链或剪贴板自动识别。以下为字段建议，不是已实现协议：

| 字段 | 含义/规则 |
|---|---|
| type、version | 固定 SaCode 配对类型和 schema 版本；未知版本拒绝 |
| instanceId | 预期 daemon 实例；仅当证书核验及登记回执一致后才可信 |
| workspaceId | 预期工作区，绑定确认时明确展示，不能靠改码提权 |
| displayName | 非可信展示名，长度受限、转义；不参与授权 |
| transport | 首版 direct；后续按类型扩展，不接受可执行配置 |
| endpoint | direct 的 HTTPS 根地址，拒绝 userinfo/path/query/fragment/重定向 |
| daemonTlsBinding | 指定算法及身份绑定值；首版建议 SHA-256 叶证书指纹，格式与轮换策略定档后冻结 |
| enrollmentSecret | 现有一次性登记秘密；敏感字段，仅短时内存使用 |
| expiresAtUnixMs | 和服务端票据一致的到期提示；服务端判定才有权威性 |
| pairingId | 非秘密关联标识，辅助本机撤销/诊断，不充当认证凭据 |

建议配对包解码上限 4 KiB；拒绝重复字段、未知关键字段、深嵌套和超长字符串。不把长期 token、设备 credential、模型 key、SSH 私钥/口令、管理权限写入包。

当前 CLI 只打印票值，不打印完整到期/目标包。需要后续增加受保护本机的结构化出票能力；有效期读取现有票对象，不由客户端伪造。首版显示倒计时并沿用现有 5 分钟服务端票期，是否缩短留待可用性评审。

### 5.2 配对流程

1. 电脑用户显式启用接入、确认可用 TLS/身份/策略/工作区，然后从本机管理入口生成一次性票。
2. 电脑本地显示二维码与目标摘要；默认不写图片文件、不打到普通日志、不调用云端二维码服务。
3. 手机本地解码，只验证结构；此时不自动访问任何端点。用户核对目标、工作区和指纹后确认。
4. 原生网络层先建立受约束 TLS，再发送登记秘密；指纹不符、证书用途/有效期/主机绑定不符时在 HTTP 应用数据发出前拒绝。受信任 CA 仍正常核验；自签名使用显式目标级信任锚，不使用全局 trust-all。
5. 调用现有 /auth/enroll，核对回执 instanceId；凭据只入平台安全存储。申请 token 后 initialize，并按 M04 定档的上下文契约复核实例、协议和目录权限。
6. 清除票的页面值和内存引用，不保存扫描历史；托管语言不能承诺字符串可被可靠物理擦除。失败或回执丢失不自动重发一次性登记，重新出票，电脑检查并撤销可能遗留的设备记录。

二维码是带秘密的带外配对介质，不是天然可信签名。被替换的整张二维码可以同时替换地址和指纹；首版要求从用户本人电脑现场扫描并核对摘要，不支持转发图片的远程静默配对。拦截/拍照也可能在有效期内抢占票；单次消费不等于防抢占。若需更强防护，必须先另定电脑确认/双向配对协议，不声称现有票已具备该能力。

### 5.3 TLS 与轮换

- 证书 pin 必须在登记、token、RPC、SSE 全路径生效，而不是只在页面探测中生效。
- 隧道不能把期望的 daemon SNI/主机身份改成 localhost；网络连接地址与证书逻辑身份分离。
- 证书变化失败关闭；通过受保护电脑入口或已认证旧通道显式再绑定，不因网络错误自动接受新证书。
- SHA-256 证书 pin 与 SSH host-key 指纹为不同类型，不混用格式和信任存储。证书续期造成的再绑定是叶证书 pin 的已知成本；若改 SPKI pin，需单独冻结密钥轮换策略。

## 6. 可选 Relay 方案

### 6.1 推荐形态

- daemon 配套的连接器主动向指定 Relay 建立外连，手机也连同一 Relay，解决 NAT 后电脑不可达。连接器优先随 SaCode 同包交付，不要求用户另装业务桥。
- Relay 是可选基础设施，可自建；不成为直连的必需服务。首批单用户/受控小规模，不宣称多租户安全完成。
- 优先评估成熟的受维护字节通道方案；若自行定义 WebSocket 多路复用，必须先固定有界 framing、streamId、窗口/背压、关闭和版本语义，不自研加密算法。
- Relay 只转发连接字节，不解析/改写 RPC 或 SSE。每条内层连接从手机直达 daemon TLS；外层 WSS/TLS 只保护到 Relay，不冒充端到端加密。
- 连接器内部不解密应用请求，再以裸 HTTP 转到未受保护回环端口；内层 TLS 终点就是受保护 daemon。

### 6.2 路由与安全

- host 路由 ID 不可枚举且不作为通行秘密。连接器身份、手机路由访问许可与 daemon 设备 credential 分开管理，支持过期与撤销。
- 新设备首次配对需要独立短时路由许可，才能在尚未登记时到达 /auth/enroll；不能要求先拿到 daemon credential 才能建链形成循环。许可只开到该目标字节通道，不授予业务权限。
- 机器侧固定 daemon 目的地址和端口；禁止手机/Relay 指定任意 IP、任意端口或 URL，避免变成开放代理/SSRF 通道。
- 不在 URL query、访问日志或普通配置中放许可/票/token。Relay 不记录 payload、TLS 私密材料或应用认证头。
- 内层 TLS 能检测路由劫持/篡改，但不能隐藏时序、流量、IP 等元数据，也不能阻止 Relay 丢包/拒绝服务；这些限制必须披露。
- 同一 NAT 下用户共享 IP 不共享授权。限额至少覆盖路由、连接器、客户端主体、并发流、缓冲区、建连速率和空闲存活。

### 6.3 生命周期与故障

- 首版优先显式选择通道，不做无提示“直连失败自动改 Relay”。后续只允许在已验证同一实例、受用户授权的路线上恢复读取。
- 控制连接、RPC 流和 SSE 流独立管理；慢 SSE 不阻塞其他流，消费者断开及时清理对应缓冲。
- 断网退避并抖动；重连取得新通道代次。恢复先重认证/核验实例，再从可信 generation/游标补读。
- Relay 不持久缓存请求、不补发修改、不将未知执行回包改写成成功或失败。外层路由失效不自动撤销 daemon 设备；两种撤销分别生效并展示。
- 发布前完成容量、带宽费用、日志保留、监控、升级回退与停服策略评审；本方案不报价、不自动购买或部署资源。

## 7. 受控 SSH 隧道方案

### 7.1 首版范围

面向用户本人已管理、已启用 SSH 的服务器/电脑。手机直连该 SSH 服务，通过一个固定目标通道访问受保护 daemon TLS 端口；不自动安装 SSH 服务。

- 优先以受维护原生 SSH 库的 direct-tcpip channel 实现，不把用户输入拼成 shell 命令，不假定 Android 带 OpenSSH 可执行文件。
- 内层 HTTP/SSE/TLS 与 SSH channel 的结合要先探针；可评估原生流式 transport adapter，不先承诺某个 Kuikly/SSH 库 API。
- 即使 SDK 只能提供本机转发，也须仅绑定随机 loopback 端口、限制生命周期并经过单独评审；优先不暴露本地监听器。
- 不连接跳板链，不开远端转发、动态 SOCKS、agent/X11 转发、PTY、SFTP、任意命令或任意目的端口。

### 7.2 信任与最小授权

1. SSH 主机指纹通过可信带外来源核对；不自动接受首次未知 host key，不关闭 StrictHostKeyChecking 的等价约束。
2. SSH 私钥从用户显式导入/选定的专用安全存储引用，不自动遍历手机或电脑私钥；私钥、密码、口令不入二维码、argv、日志、普通偏好或云同步。
3. Keystore/系统安全存储只是候选能力，须核库与算法是否能用不可导出密钥签名；不能实现时如实说明加密存储/解锁边界，不声称硬件密钥支持。
4. 服务端使用专用受限账号/密钥，只允许本次 daemon 目标转发，禁止 shell/PTY及其他目的地。不能只依赖客户端 UI 白名单；服务端如何限制并验证，作为平台探针验收项。
5. SSH 主机验证通过后仍完成 daemon TLS 校验与设备 token 认证。SSH 账号登录不授予 daemon scope，daemon 登记不授权 SSH 任意访问。
6. 首版可只支持明确验证过的公钥方式；交互口令/加密私钥口令能力不具备时明确 auth-method-unavailable，不能偷偷降级。

### 7.3 断线与权限

只关闭本应用持有的 channel、session 或受控子进程，不杀全机 ssh；应用退出/账号切换及时释放。隧道断开不表示远端任务取消，恢复仍按 daemon 的 task/turn/事件事实核验。手机后台挂起作为预期故障测试，不承诺永远连接。

SSH 隧道与现有 Host SSH 执行分别维护凭据引用、连接状态和审批语义；不通过给 ssh/exec 增 options 或 command 拼接来完成本功能。

## 8. 统一身份、状态与缓存

以下为拟建逻辑模型，不代表新增类已存在：

- `TargetIdentity`：账号作用域内的本地目标 ID、已验证 instanceId、workspaceId、daemon TLS 绑定及信任修订。
- `RouteProfile`：direct/relay/ssh、路线 ID、修订号、非秘密定位参数、独立凭据引用；SSH host identity 与 daemon identity 分列。
- `ConnectionContext`：账号会话代次、目标代次、路线代次和当前 sessionId；迟到回调必须全部匹配才可更新页面。
- 连接状态分开记录：路线可达 → TLS 已核验 → 设备已认证 → initialize 已核验 → 可读取/权限受限。任务状态另记，不能把 connected 映射成 done。
- 连接缓存、token 和回调按账号/目标/身份修订/路线代次隔离。持久事件按账号/实例/工作区/会话/generation 隔离；新路线默认不沿用游标，核验同实例同资源后才可显式恢复。合并按持久事件标识去重，不按文本拼接。
- 同实例换路线不迁移任务、不新建 operationId。不同实例即使同名也不能继承凭据、审批票、会话或游标。
- 解绑本地数据、撤销 daemon 设备、撤销 Relay 访问许可、撤销 SSH 密钥是不同动作；只做本地忘记时不得提示“远端已撤销”。

## 9. 威胁模型与关键反例

| 威胁/输入 | 必须结果 |
|---|---|
| 过期票、并发重复扫码、截获票抢先登记 | 服务端拒绝无效/重复消费；抢占须可见并可撤销，不宣称已防住二维码窃取 |
| 二维码超长、重复字段、恶意 endpoint、外部图片上传 | 本地解析拒绝；确认前零网络请求；不使用第三方扫码上传服务 |
| 整码被替换为攻击者地址/指纹 | 不静默配对；提示用户核对本人电脑目标摘要；不冒称仅靠 pin 可防整码替换 |
| TLS/SSH 指纹变化、Relay 置换路由、同名假实例 | 应用秘密发送前拒绝错误 TLS 对端，登记/initialize 身份再核验；不自动再信任 |
| Relay 要求转发任意内网 IP/端口，或连接器接 gate-off loopback | 拒绝启动/建链，不碰业务执行 |
| SSH 账号可任意转发、任意 shell | 未通过服务端限制探针，不进入产品支持范围 |
| 低 scope/越权 workspace/session/未知通知 | 与直连同样拒绝；SSE 补读及直播均无泄露 |
| 修改已执行但回包在 Relay/SSH 丢失 | 保持 unknown，恢复先查事实；后端同键幂等不发生第二次执行 |
| 隧道断开、后台挂起、点“断开” | 不标任务取消/完成；只有真实取消终态才能显示 cancelled |
| 切账号/目标/通道后旧 SSE 回调到达 | 代次检查丢弃，不串数据；停止旧订阅不表示停止旧任务 |
| 撤销设备但旧 SSE/Relay 仍连着 | daemon 拒绝后续请求并终止相应流；Relay 在线不恢复业务权限 |
| 中继流量洪峰、慢消费者、半帧/超大帧 | 有界内存、连接/速率配额和超时，错误隔离到相应流；测试在隔离夹具中进行 |

### 依赖边界

- M05-0 设计/隔离探针可先行；M05-1 正式产品验收依赖 M04 与 M05-0。扫码只读验证可作中间里程碑，不能算完整移动任务通过。

## 12. 验证与证据要求

1. **纯逻辑**：QR schema/重复字段/大小/URL/过期、状态迁移、缓存键和代次、秘密脱敏；先写失败反例再实现。
2. **平台适配**：本机合成 TLS/SSH 服务，验证 pin/SNI/主机名/证书有效性、禁止重定向、RPC 与 SSE 一致、取消/有界缓冲；不得使用真实密钥或外部付费服务。
3. **真实 daemon+Host**：固定构建摘要与依赖来源，跨 direct/relay/ssh 运行同套认证、scope、会话隔离、S08/S09/S10 回归；反例必须确实到达被测防线，不能拿客户端提前拒绝冒充后端通过。
4. **破坏性网络夹具**：在自有隔离环境模拟断包、半关闭、慢流、路由替换、重复扫码、回执丢失；不用公网压测或无授权目标。
5. **真机**：Android 同 Wi-Fi、蜂窝、网络切换、锁屏/前后台；鸿蒙分别测试。拍屏/日志只用脱敏数据，经用户允许，不采集二维码秘密或私人内容。
6. **产品出口**：连接、授权、任务发起、实际修改/测试、拒绝、取消、恢复分别记证；PASS 需列测试名、条数、退出码和构建摘要。源码盘点/可编译/可安装不等于真实任务通过。
7. **记录位置**：一次性产物放 `target/tmp/<用途>-<日期>/`；阶段证据完成后再按明确路径更新根 PRD 台账与索引，避免覆盖当前其他会话的文档改动。

## 13. 发布、停用与待决策项

### 安全发布

所有新通道默认关闭；直连保持独立可用。先在合成数据和显式授权设备上验证，再小范围启用。停用 Relay/SSH 只关闭该应用所有的连接，不隐式终止远端任务。若凭据泄露，分别撤销 daemon 设备、Relay 许可或 SSH 密钥，保留最小脱敏审计；不自动清理整个用户环境。

### 推荐默认值与尚未冻结事项

| 事项 | 本方案推荐 | 定档时机 |
|---|---|---|
| 首发平台 | Android 优先；鸿蒙另列完整验收 | 实施前确认 |
| 配对包 | 应用内扫码、现场确认、一次性票，不用第三方 URL | M05-0 |
| TLS pin | 先评估叶证书 SHA-256，全路径绑定、变化失败关闭 | 原生探针后冻结；自签名策略需安全复审 |
| Relay | 可选自建、字节中转、内层 daemon TLS、单用户受控试点 | 依赖/许可/容量与运维评审后；部署另授权 |
| SSH | 直连、固定 daemon 目标、公钥、无 shell/跳板/任意转发 | 各平台 SDK 和服务端限制探针后 |
| 自动选路 | 首版显式选；后续仅同身份读取可受控恢复 | 故障与幂等验收后再评估 |
| 更强配对 | 首版声明现场扫码的信任边界；不声称防票抢占 | 如要求远程分享配对，单独设计确认协议 |

**建议下一次实施授权范围仅为 M04-A；同时可以批准 M05-0 的文档/离线探针，不同时建设三套传输。** 本方案批准不等于授权扩 scope、安装依赖、连接 SSH、启用云中转、公网部署或提交推送。
