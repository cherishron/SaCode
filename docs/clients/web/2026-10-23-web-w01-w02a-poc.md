## 1. 范围声明（什么做了、什么没做）

**本次交付（按方案 §11/§12/§13.5 的允许面）：**
- 工程骨架：Vue 3.5 + Vite 8 + Fastify 5 + TypeBox + Pinia 3 独立前端 + 同源 BFF。
- BFF 安全面：登录/退出/会话查询、Argon2id（`@node-rs/argon2`）、内存会话（30m idle / 8h absolute 轮换）、CSRF 32 字节定长比较、Origin 精确匹配 + Fetch-Metadata（`same-origin`/`none`）校验、登录 5/15min 滑动限流。
- 只读动作（白名单）：`targets` / `sessions` / `events` 三类，TypeBox 响应 + mapper 逐字段挑选，**绝不 spread 上游**。
- 事件 broker：每 target 单条上游 SSE → 环形缓冲（≤500）→ 多浏览器订阅者 fan-out；不透明游标（base64url 含 target/session/lastEventId/generation）；generation 变化清空环 + 提示补读；慢客户端 30s 断开提示补读。
- 测试：单元测试 6 组 + `inject()` 集成测试 2 组 + Playwright 真实浏览器 E2E 3 条（登录/刷新 + 事件链路 + 刷新后历史仍在，`test/e2e/*.spec.ts`，默认 vitest exclude，需独立 `playwright` 环境运行）。

**硬性纪律（贯穿，未越界）：**
- 未做 `task/start` / `approval/*` / `model/*` / 任意文件路径 / 通用 RPC / 插件终端凭据管理。
- 未提交、未部署；未改动 daemon / CLI / mobile 源码、未改动契约 JSON、未改动根 PRD/台账/索引（本轮仅新增 `docs/plans/*` 与本文档）。
- 真实 daemon 只读链受三道闸门约束（P0-3 S11 资源身份未修、P0-4 SSE 授权未复测、web consumer 未在 `remote-capability-contract.json` 登记），**未闭合前不声称「各端打通」**；默认走 `SimulatedDaemonTransport`（确定性数据，fully tested），真实适配层以 `SACODE_WEB_DAEMON_REAL=1` 门控代码存在、不混入默认构建。

## 4. 安全反例结果（已用例覆盖）

**认证面（auth.test.ts，9 项）：**
- 登录缺 Origin → **403**（缺失 Origin 的非浏览器客户端拒绝）
- 错误密码 → **401**
- 登录成功下发 dev cookie（`sacode_dev_session`）+ CSRF（长度 > 20）
- Cookie 为 `HttpOnly` + `SameSite=Strict`
- 会话查询缺 cookie → **401**
- 会话查询带 cookie → **200** 返回 owner + csrf
- 退出缺 CSRF → **403**
- 退出带 CSRF → **200**，随后同 cookie 查会话 → **401**（会话已销毁）
- 连续 5 次失败登录 → 第 6 次 **429**（滑动窗口限流）

**只读面（readonly.test.ts，10 项）：**
- `GET /api/targets` 缺会话 → **401**
- `GET /api/targets` 仅返 `{id,label}`，payload **不含** `credentialRef` / `baseUrl`（白名单生效）
- `GET /api/targets/sim-1/sessions` 错误 Origin（`https://evil.example`）→ **403**
- sessions 返回字段经白名单，payload **不含** `credential`
- 会话详情 → **200** 含 `workspaceId`
- events 返回 10 帧 + 不透明 base64url 游标（含 target/session/lastEventId/generation）
- 未知 target → **404**
- 未知动作 → **404**（路由层 404，不进 daemon）
- SSE 流缺会话 → **401**
- SSE 流错误 target → **404**

**独立运行冒烟（真实 HTTP，7 项全过）：**
`healthz=200` · `login-no-origin=403` · `login-ok=200(cookie+csrf)` · `session=200` · `targets=200 count=1` · `sessions=200 count=6` · `targets-unauth=401`。

**单元测试面（6 组）：** session（TTL/轮换/销毁）、csrf（定长比较/防时序）、origin（缺失/错误/通过 + Fetch-Metadata）、mapper（只挑白名单字段、丢弃 secret/credentialRef）、policy（只读方法集 + 资源绑定 best-effort）、broker（seed=历史/push=实时环、代际清空+提示补读、环≤500、fan-out 移除）。

**真实浏览器 E2E（`test/e2e/login.spec.ts`，Playwright chromium headless shell 1243）：** 从 `http://127.0.0.1:5173` 加载 SPA → 填用户名/口令提交 → 跳转 `/workbench` → `page.reload()` 后仍停留 `/workbench`。证明同源 cookie（`sacode_dev_session`）+ CSRF token + `GET /api/auth/session` 会话恢复在**真实浏览器安全模型**（Origin/Fetch-Metadata/CSRF/HttpOnly cookie）下成立，而非仅 `inject()` 模拟。BFF 与 Vite 通过 `test/e2e/serve.ts` 同进程引导、同源代理 `/api`。

## 5. 架构与约束践行

- **字段白名单**：`daemon/mapper.ts` 逐字段挑选；上游原始记录（`Record<string, unknown>`）经 mapper 才进响应，新增上游字段（含 secret/credentialRef）不会自动泄露到浏览器。
- **不透明游标**：`broker.makeCursor` 用 base64url 嵌入 target/session/lastEventId/generation，前端原样回传；`parseCursor` 校验 target 一致，跨 target/伪造 → `null` → `refill` 返回 `nextCursor:null` 提示重拉目录。
- **generation 闸门**：上游重建（generation 变化）清空环形并要求客户端补读，避免 stale 帧串台。
- **真实链门控**：`real-transport.ts` 仅在 `SACODE_WEB_DAEMON_REAL=1` + 显式 `SACODE_WEB_REAL_TRANSPORT_PATH` 时启用，文件头标注三道闸门约束，不提升 scope、不编辑身份文件。

## 6. 未验证边界（明确不声称打通）

- **真实 daemon 只读链未验证**：受 P0-3（S11 资源身份未修，按会话读历史不可信）、P0-4（SSE 授权未复测）、web consumer 未在 `remote-capability-contract.json` 登记三道闸门约束。`real-daemon.spec.ts` 以 `describe.skipIf(!ENABLED)` 隔离，默认不跑。
- **不声称「各端打通」**：本轮只证明 BFF 安全面 + 模拟 daemon 只读链路 fully tested；桌面/CLI/移动与 Web 的真实互通、审批/拒绝/取消/失败/隔离等验收场景未做。
- **未做生产部署**：仅回环监听（非回环 bind 直接抛 `ConfigError` 失败不降级）；TLS 头部策略未上线。

### 追加（2026-10-24）：真实浏览器暴露的 2 个功能性缺陷（第 4、5 个）

> 干跑与 curl 验证（手加 Origin 头）**都掩盖了下面第 4 个缺陷**，只有真实浏览器 E2E 才能暴露它。

| # | 缺陷 | 根因 | 修复 |
|---|---|---|---|
| 4 | **整个只读工作台在浏览器不可用**：`/api/auth/session`、`/api/targets`、sessions、events 全部 **403 missing-origin** | **浏览器对同源 GET/HEAD 默认不发送 Origin 头**（仅 POST/跨域才发），而 `checkOrigin` 对所有方法都要求 Origin 必须存在 | `checkOrigin` 增加 `allowMissing`（仅安全方法 GET/HEAD 放行）；缺失 Origin 的跨站读取由 **SameSite=Strict cookie + sec-fetch-site 拒绝 cross-site** 共同防御；POST 等非安全方法仍严格要求 Origin 存在且精确匹配 |
| 5 | **SSE 连接状态卡在「连接中…」**：前端 `onopen` 不触发 | 服务端 hijack 后仅 `writeHead`，环为空且心跳要等 15s，首字节迟迟不出 → 响应头滞留缓冲区，浏览器与前置反代都不认为连接已建立 | 连接建立后立即写出首字节 `': open\n\n'`，让浏览器/反代立刻确认 SSE 连接 |

**同步完善（W03-A 打磨）**
- 前端：会话详情（标题/状态/工作区/创建/更新）展示；历史按不透明游标分页（加载更多）；SSE 连接状态可见（连接中/实时已连接/连接断开正在重连/补读中）；补读与实时事件**按 id 合并去重**（原来 refill 会覆盖已到达的实时事件导致丢失）。
- 新增 `test/e2e/events.spec.ts`：登录 → 选目标 → 选会话 → 断言 10 条历史事件可见 + SSE 显示「实时已连接」；刷新后历史仍在。

### 追加（2026-10-24）：实时链路与 fan-out 验证（此前完全未验证）

合成 transport 原先 `subscribe()` 是空实现（不推送任何帧），因此**实时 fan-out 这条链路此前从未被真正验证过**。补齐方式：

- 注入能力：`TargetGateway` 增加可选 `simFactory`（缺省仍为 `SimulatedDaemonTransport`，行为不变）；`SimulatedDaemonTransport` 增加 `emit(frame)` 用于驱动，`close()` 清理回调。默认不自动推送，保持确定性。
- 驱动方式：e2e 专用 `test/e2e/serve.ts` 起一个**仅回环**的驱动端口 `127.0.0.1:18788`，`POST /emit` 按需推送一帧到 `sess-1`。该端口属测试脚手架，不进产品代码。
- 新增 `test/e2e/realtime.spec.ts`：
  1. 实时事件经 SSE 到达浏览器（先等「实时已连接」再 emit，证明到达的是实时推送而非连接时回放）；
  2. **单上游订阅 fan-out 到多个浏览器订阅者**（两个独立浏览器上下文订阅同一 target/会话，同一帧必须同时到达两者）。

**E2E 结果：6 passed**（login 1 + events 2 + realtime 3）。
代际变化用例证明链路为：**上游代际变化 → broker 清空旧环 → 向订阅者发 `refill` → 前端按不透明游标补读（请求带 `cursor=`）→ 该帧仍到达浏览器**。

> 过程中修正过一次断言：初版按「事件数 == 11」断言失败（实际 12），根因是**SSE 连接建立时会回放环形缓冲中的历史帧**——前面测试 emit 的帧被后续测试回放了。这是正确行为（回放机制生效），改为「连接已建立后再 emit、断言该帧文本出现」，使到达的必为实时推送。

- 引入 `@fontsource-variable/inter` 与 `@fontsource-variable/jetbrains-mono`（variable，仅字重轴 `wght.css`），构建后 woff2 进 `dist/client/assets/`，由同源提供。
