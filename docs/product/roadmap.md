# SaCode 产品路线图

> 更新时间：2026-06-06
> 当前版本：0.1.27
> 配套文档：`docs/product/PRD.md`

本文件只回答三件事：当前处在哪个阶段、下一阶段交付什么、后续能力按什么顺序演进。

## 当前阶段判断

SaCode 当前已经具备可用的终端 AI 编程主线能力，核心优势集中在：

1. CLI / TUI / REPL 多入口
2. 多 Agent 编排
3. 模型智能路由
4. 结构化记忆与项目知识能力

当前代码中已经完成或基本完成的能力包括：

1. provider SSE 增量流式解析
2. `test.run`、`git.commit`、`fs.patch`
3. `code.symbols`、`code.deps`
4. `media.vision`
5. MCP `stdio` server 与 `sacode mcp serve`
6. 插件发现、配置安装、远端元信息搜索

当前版本的主要瓶颈集中在体验闭环和统一运行时两部分：

1. 持久化任务与统一状态机仍在收口
2. AST 级代码理解、语义索引和 LSP 诊断联动仍未完成
3. 插件体系仍停留在发现层和配置层，真实运行时加载尚未落地
4. 跨平台稳定性仍需继续清理，部分工具刚完成去外部命令依赖

## 版本路线

### v0.3：核心体验闭环

目标：让 SaCode 的终端主回路达到“可持续执行、可实时反馈、可精确修改、可形成提交”的完成态。

当前状态：主体能力已具备，剩余重点转向统一状态机、跨入口一致性和边界稳定性。

重点交付：

1. SSE / 实时流式输出
2. 持久化任务存储
3. `apply_patch` / `diff_edit`
4. Git 提交闭环工具

### v0.5：代码智能深度

目标：从文本级辅助进入语义级代码理解与验证。

当前状态：`code.symbols`、`code.deps`、`test.run` 已落地，下一步重点是 AST 和 LSP 诊断联动。

重点交付：

1. AST 解析
2. 符号索引
3. LSP 诊断集成
4. `test.run` 测试运行器

### v0.7：生态与集成

目标：把 SaCode 从本地 CLI 工具扩展为可被集成的能力平台。

当前状态：MCP `stdio`、插件发现与远端元信息搜索已落地，下一步重点是真实插件运行时、检查点增强和 IDE 集成。

重点交付：

1. MCP stdio 接入
2. 插件发现与分发
3. 检查点增强
4. IDE 插件接入

### v1.0+：产品就绪

目标：形成自动化闭环、协作协议和长期平台能力。

重点交付：

1. 自动修复闭环
2. 多模态支持
3. Agent 间协作协议
4. 学习型记忆

## 并行推进主线

除版本交付外，SaCode 还会持续推进一条平台主线：统一运行时。

这条主线的演进顺序是：

1. 统一任务运行时与状态机
2. Sub-agents
3. Daemon + HTTP API
4. Scheduled Tasks
5. Agent Teams
6. Channels

这条顺序决定了高阶能力的落地依赖关系，也决定了方案文档在 `docs/plans/archive/` 中的组织方式。

## 阶段优先级表

| 阶段 | 目标 | 代表能力 |
|------|------|----------|
| `v0.3` | 补齐终端体验闭环 | 持久化任务、统一状态机、跨入口一致性、Git 提交闭环 |
| `v0.5` | 提升代码智能深度 | AST、语义索引、测试运行器、LSP 诊断 |
| `v0.7` | 扩展生态与集成 | MCP stdio、插件运行时、IDE、检查点增强 |
| `v1.0+` | 达到产品就绪 | 自动修复、多模态、协作协议、学习记忆 |
