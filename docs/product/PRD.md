# SaCode 产品需求文档

- 版本：v0.2
- 日期：2026-10-03
- 状态：初稿；承接已确定的产品范围，新增量化目标与待定项需后续确认。
- 产品目标：同一套仓颉核心，分别构建可发布到 npm 的独立 CLI 与 Electron 桌面安装包；两者均纳入裁剪范围内的完整复刻验收，排除官方商业账号及云服务绑定。
- 本文定义目标与验收条件，不代表功能已实现或已经授权对外发布。
- 产品名称统一为 **SaCode**：窗口标题、界面品牌、图标说明和安装包均使用 SaCode；DeepSeek Harness / DSH 仅用于上游出处、兼容协议及复刻证据，不作为本产品显示名称。官方对照实例应明确标注为参考，不能作为 SaCode 预览交付。

### 最新交付顺序与验收要求（2026-10-04）

1. 先以冻结官方桌面的完整页面和真实运行截图复刻前端；使用指定技术栈、中文、SaCode 名称及原图标，排除官方账号体系及 DSH 产品品牌。原生窗口、导航、会话、输入区、右栏、设置、菜单和状态页面均须纳入，不能用自建工作台或局部组件检查替代。
2. 前端复刻完成后逐项接入对应仓颉后端；先核查保留功能的后端实现，对缺失或仅登记/marker 的能力继续以仓颉完善。界面动作、后端协议、核心行为、真实副作用和失败恢复必须形成闭环，不能以示例 provider 或假成功替代产品行为。
3. 接入后执行自动化验收，包括 Electron IPC、真实 Host、共享核心、任务/工具/审批/取消/持久化以及重启恢复；需要模型的测试使用用户授权的 StepFun Step Plan 服务与 `step-5-preview`。测试密钥通过受控运行配置注入，不写入仓库、普通日志或发布产物。模型协议夹具与真实远端调用分别登记，不能互相替代。
4. 最终编译并验收完整可用安装包，同时保留既定独立 npm CLI 交付。安装后不依赖开发环境、手动编译或拼接 DLL/PATH；模型配置须可在产品内完成，错误明确可恢复。安装包必须来自最终源码和已验证后端，验证安装、启动、实际任务、恢复及卸载；旧包存在或构建脚本成功不算交付完成。

以上是完整目标及先后关系，不表示当前实现或安装包已经通过这些门槛。

## 1. 背景与用户

用户需要在终端和桌面中完成同一类 AI 编程任务：选择项目、配置模型、提交任务、观察执行、审批工具、取消任务、恢复会话并检查结果。两个入口应共享业务语义、权限策略和会话事实，避免换一个入口就丢失历史、重新计费或改变工具行为。

| 用户 | 主要需求 |
| --- | --- |
| 终端开发者 | 经 npm 安装 CLI，在项目目录完成任务；支持脚本调用、明确退出码及 Ctrl+C |
| 桌面开发者 | 安装后直接使用，通过可视界面查看流式输出、工具状态、审批与项目改动 |
| 扩展开发者 | 通过稳定扩展点提供工具、模型或界面贡献；卸载后资源和注册自动回收 |
| 验收与维护人员 | 在干净检出和无编译器环境复现构建、安装与双入口行为，追溯差异及证据 |

## 2. 产品范围与成功标准

### 2.1 完整复刻口径

上游基线沿用已冻结快照：`deepseek-ai/deepseek-harness @ 639ed015397290b3745d163aafe02ffee4aa3f84`。范围清单以[能力矩阵](../plans/dsh-capability-matrix.md)的 **63 个模块**为准；README 索引行不计入分母。框架层及交付层义务另由总体方案的 18 条架构不变量承接，不能因不在模块分母中而省略。

完整验收同时覆盖功能行为、架构约束、数据及协议格式兼容、插件源码兼容四个维度。每个维度分别登记证据与差异；自定义 JS 工具能运行，不能据此宣称原生 DSH 插件源码兼容。

每个模块必须记录：上游证据、需求条目、本项目实现位置、CLI 验收、桌面验收、兼容性判定、已知差异和证据版本。纯展示模块在 CLI 可不提供同形视图，但其关联业务动作和数据必须可访问；任何入口不适用项都要说明原因并经范围裁决，不能留空或自行排除。

分阶段交付只改变顺序，不自行缩减范围。全部保留需求验收通过、裁剪边界完成核验、差异完成裁决且没有发布阻塞，才能声明“裁剪范围内完整复刻”；对外须同时注明排除官方商业账号及云服务绑定，不宣称上游全量无差异兼容。

### 能力来源与实现裁决（2026-10-05 用户确定）

逐项先核对冻结 DSH 的实际契约与 SaCode 接入证据，再选择实现路径；以下规则适用于持续目标模式及其他保留能力。

| DSH 与 SaCode 状态 | 实施方式 | 验收要求 |
| --- | --- | --- |
| DSH 已有且满足需求，SaCode 尚未完整接入 | 不重新设计该能力；按指定技术栈复刻并接入 SaCode | 对照上游契约，验证共享核心及 CLI、桌面实际入口 |
| DSH 已有且满足需求，SaCode 已完整接入 | 只补缺失的验收，不另做实现或替换设计 | 补真实行为、失败恢复及交付物证据；仅有核心单测不算完整接入 |
| DSH 有但不足以满足需求 | 保留其可用契约，在此基础上扩展 | 分开记录兼容基线与 SaCode 扩展，分别验证基线回归和新增行为 |
| 经核验 DSH 没有该能力 | 作为 SaCode 新能力单独设计 | 独立需求、设计与双入口验收；不得标为 DSH 已复刻 |

未核实的能力来源保持「待核」，不得据缺少文档、同名模块或本方已经写了实现推断上游不存在。裁决必须登记冻结源码/测试出处、需求缺口、本方接入程度及后续动作；扩展和新增能力不改变既定技术栈、账号裁剪范围或共享核心要求。

### 2.2 两个独立交付物

| 交付物 | 必须满足的条件 |
| --- | --- |
| npm CLI | 主包启动源码与对应平台包可发布；通过 npm 安装后提供 `dsh` 命令；包含仓颉可执行文件及所需运行库；使用时不要求安装 Electron、桌面应用或仓颉 SDK |
| Electron 桌面 | 提供可安装应用，随包带仓颉 Host、所需运行库和前端资产；不要求全局安装 CLI、仓颉 SDK 或额外 Node；扩展宿主需要 Node 时须随包提供运行能力并实测 |

当前平台为 Windows x64。macOS、Linux 及其他架构列为后续平台范围，不在未产出并验收前宣称支持。npm 当前源码包名为 `@dsh/cli`、`@dsh/cli-win32-x64`；正式发布前必须确认 scope 权限及最终名称，不假定这些名称可用。

### 2.3 官方账号及云服务裁剪（2026-10-03 已定产品范围）

两个入口按“本地使用、无需 DSH 官方账号登录、用户自行配置模型或服务凭证”交付。无需登录不免除第三方服务自身的授权或收费要求。

SaCode 不提供官方账号登录、注册、账号绑定、订阅充值或官方余额入口，首次启动直接进入本地工作区/会话界面，不复刻官方账号欢迎页。对照运行官方桌面仅用于核验保留页面的布局，不代表将账号流程纳入实现；模型 API Key 配置属于用户自行选择的服务凭证，保留在模型设置中。

| 编号 | 范围决定 | 上游核验状态 |
| --- | --- | --- |
| C01 | 排除官方注册、登录、账号绑定及其使用门槛；不得作为本地启动、执行任务或恢复会话的前提 | 已核：官方桌面欢迎页存在登录入口（冻结 `apps/desktop/src/welcome-window.ts`、`welcome-api.ts`）；SaCode 不接入。阻断官方账号端点的两入口全流程验收仍待完成 |
| C02 | 若上游存在官方订阅、支付、商业权益或云端额度校验，排除；保留本地 token 用量统计和用户预算约束 | 待核：商业计费与本地计量边界 |
| C03 | 若上游存在官方账号绑定的云同步、云存储或云会话服务，排除绑定；保留本地存储、会话恢复和两入口一致性 | 待核：云服务入口、数据归属及本地替代路径 |
| C04 | 不接入官方账号关联遥测或默认官方上报；遥测默认关闭，后续仅以用户明确启用的可替换服务提供 | 待核：product-telemetry、session-telemetry、otel 的数据、目的地和默认行为 |

以上是已确定的产品裁剪决定，**不是上游确实含有这些功能的事实判定，也不是已完成代码删除的声明**。逐项核验冻结快照的文档、源码、配置与测试后，记录证据路径、调用链、CLI/桌面影响及保留需求；未找到对应实现时登记核验范围和证据，不能直接标成“已移除”。

必须保留模型 API Key 和第三方服务凭证的安全存取、脱敏、轮换；工具审批、沙箱、会话归属与 IPC 校验；远程 HTTP/WebSocket 入口的认证与访问控制；本地用量与预算。不得按 `auth`、`credentials` 或 `token` 名称整模块删除。npm 发布账号和签名证书属于维护者发布条件，不是终端用户登录要求。

63 个模块仍完整保留在矩阵中，裁剪在模块内部需求层登记，不先行删除模块或缩小分母。四个兼容维度分别登记裁剪差异，两个入口采用相同边界；新增排除项需显式裁决。

## 3. 关键用户流程

### 持续目标模式（2026-10-05 用户补充需求）

来源裁决：冻结上游已有 goal 的修订 CAS、active/paused/blocked/complete 状态与编辑/暂停/恢复/完成/清除契约（见[上游逐模块取证](../evidence/upstream-module-reads-2026-10-04.md)的 goal 条目）。这些属于复刻接入范围，不能把整项称为上游没有的新增能力。本轮已核对上游 goal-round-driver 与 tool-goal：自动跨轮、修订围栏、人类输入竞争和模型目标工具属于复刻接入；上游宿主暂停会取消当前轮，用户要求的不打断当前轮作为 SaCode 扩展保留。资源限额及更强证据策略在基线之上扩展；恢复授权、准入计数、模型工具和桌面目标条尚未完整接入。详见[契约裁决与差异](../evidence/goal-upstream-contract-2026-10-05.md)。已有实现按这些契约核对后复用。

用户设定目标后由仓颉共享核心持续驱动模型工具轮次，桌面与独立 CLI 共用 GoalScheduler/GoalDriver/GoalRunner、日志和停止判据。展示目标正文、状态、已完成轮次及累计执行时长；支持建立、编辑、暂停、恢复和删除。控制操作在轮次边界影响后续调度，不强杀当前轮；运行中插话沿用 inbox 步边界或轮次边界送达，不另建前端队列真源。

完成必须有可追溯的真实证据，并绑定开轮时目标修订；模型说「完成了」或工具调用次数增加均不能单独充当完成证明。轮内编辑、暂停或删除后，旧轮证据不得完成新状态。预算、轮数、时长及连续无进展限额由核心停止并落明确阻塞原因，避免无限空转。

验收必须覆盖两个真实入口、跨轮模型执行、轮内插话、控制边界、陈旧证据拒绝、限额停止、崩溃恢复和安装包；真实模型测试在隔离项目内改文件并验证结果。既有 `dsh goal` 断言自测仅证明核心组合，不能作为可操作 CLI 持续执行模式的交付证据。当前核心已有实现及隔离测试，六个目标控制 Host 方法与桌面有限 IPC 已接入（见[目标控制证据](../evidence/goal-control-2026-10-05.md)）；真实宿主/用户 CLI 自动跨轮接线、完成证据与预算通道、桌面目标卡、完整真实模型场景及新安装包仍待完成。

| 流程 | CLI | 桌面 | 共同验收结果 |
| --- | --- | --- | --- |
| 首次使用 | npm 安装后启动，选择项目并配置模型 | 安装启动，选择项目并配置模型 | 无需 DSH 官方账号登录；明确报告缺失模型配置；凭证不出现在普通响应和日志中 |
| 执行任务 | 输入任务，接收流式输出及工具状态 | 在输入区提交，展示流式内容和工具卡片 | 同一核心完成模型、工具与持久化闭环，结果可重放 |
| 审批工具 | 显示目标、参数及风险，作出决定 | 审批卡片显示相同信息并接受决定 | 决定可审计；拒绝、过期或异常都不能执行；一次性授权不能复用 |
| 取消任务 | Ctrl+C 或明确取消动作 | 点击取消或关闭应用 | 回报真实终态；收束执行和扩展子进程，保存应持久化的事实 |
| 恢复与切换入口 | 打开已有会话 | 打开同一会话 | 历史、用量、预算与审批事实一致；同一会话只允许一个有效写者 |
| 检查结果 | 查看摘要、差异、交付文件及失败原因 | 对话和侧栏查看同一组结果 | 摘要来自事实；不将工具失败、落盘失败或中断呈现为成功 |

CLI 的最终命令语法与非交互输出 schema 在接口设计中确定；现有 `seed/stream/tool/...` 自测命令不能替代真实用户任务流程的验收。

## 5. 共享核心与数据要求

1. `core/` 是唯一业务实现来源。CLI 和 Host 调用同一套会话、agent、模型、工具、审批、预算及扩展能力，入口只做交互或协议适配。
2. 会话日志是唯一业务真源。模型可见内容可从日志重建；消息列表、UI 和计量器均为派生状态。
3. `append` 与 `flush` 的可见性不同。对外报告持久化成功前必须完成落盘屏障，失败时不得释放尚未完成提交的写入责任。
4. 所有入口及所有租约获取路径均恢复相同的用量、预算和审批事实；重启与切换入口不能放宽已生效的约束。
5. 用量结算与是否轮询 UI 无关。完成、取消、退出及恢复路径共享明确的结算规则，实际收到的 usage 可追溯，且不重复入账。
6. 文件修改要求先观察、再校验版本、后写入；路径别名不能绕过校验，创建不能覆盖外部新文件，读写结果与控制字符保持无损。
7. 取消必须作用于真实执行链。Host 退出前收束线程、在途调用与扩展子进程，不留下孤儿进程或伪造终态。
8. Electron 渲染层仅访问有限且校验参数的 IPC 面；凭证和本机执行能力留在权威侧。CSP 禁止运行时动态求值，构建产物不得依赖开发环境路径。

完整约束见[总体方案](../plans/plan-deepseek-harness-replication.md)的 18 条架构不变量。存储格式、工具阶段和插件接口须对照冻结上游原文及测试核验；现有自定义实现有差异时登记差异，不倒推修改上游兼容目标。

| A01 | 范围覆盖 | 63 个模块逐项有上游核验；保留需求有实现证据，C01–C04 有裁剪边界证据；四个兼容维度各有结论；没有未经裁决的缺项，排除项不算实现通过 |

| A06 | npm 安装 | 从干净检出打包；检查主包入口和平台依赖版本；在只有声明运行前提、没有仓颉 SDK 的环境安装 tarball 并运行真实任务；参数、退出码与中断正确传播 |
| A07 | 桌面安装 | 从干净检出生成安装包；在目标环境实际安装、启动、执行任务、退出和卸载；宿主及运行库从包内加载，无开发目录依赖和孤儿进程 |
| A08 | 扩展兼容 | 在两入口分别跑代表性的冻结上游插件及卸载、异常、取消用例；明确区分原生源码兼容、适配后兼容与自定义扩展 |
| A09 | 构建可复现 | 记录 commit、工具链、依赖锁、平台和构建命令；必需源码均已跟踪，硬编码本机依赖可通过受控配置替换 |
| A10 | 发布证据 | 记录产物哈希、版本、测试日志与已知差异；签名与发布状态如实标注；npm 与安装包分别有验收记录 |
| A11 | 裁剪边界 | C01–C04 完成上游核验及两入口验证；阻断官方账号/商业/同步端点后本地流程正常，无官方登录或权益门槛；配置有效第三方凭证后可执行任务；遥测默认无上报请求；凭证、审批、沙箱及远程访问控制未被误删 |

每条证据至少包括：需求编号、入口、commit、工作区是否干净、产物哈希（如涉及产物）、环境、步骤、期望、实际结果和日志路径。工作区通过不能替代 HEAD 通过；旧二进制通过不能证明新源码通过。

实现验收状态采用 `未开始 / 部分完成 / 通过 / 阻塞 / 不适用（已裁决）`，上游核验另记 `待核 / 已核`。裁剪决定已定但边界待核时，不能记为验收通过或整模块不适用。阻塞须写明解锁条件；未经实测的速度、稳定性或兼容性不标为通过。

发布前须修复所有 P0/P1 缺陷，P2 逐项裁决；核心、两入口、扩展与包安装测试全部通过。性能目标在代表性基准建立后补充数值，至少取证长会话投影、流式背压、取消响应、启动时间和大内容处理；没有基准前不编造 SLA。

## 8. 当前差距与待确认项

截至 2026-10-03，仓库已有共享核心、CLI 自测入口、Host、Electron 壳及打包链路，但仍处于部分复刻阶段。真实模型接入、完整子系统覆盖和原生插件兼容未完成验收；安装包产出及冒烟不等于实际安装卸载通过。详细状态以[实测证据](../evidence/p0-status-2026-10-02.md)和能力矩阵为准，本文不复制滚动测试计数。

本轮代码 review 已复现三条需要纳入 R0 回归的场景：审批先取得租约导致历史预算失效；完成轮次未经 `turn/poll` 就退出导致漏记用量；收紧到已用额度以下仍启动下一轮。另有控制字符修复与 npm 主包启动源码尚未完整进入已提交版本的问题。以上是当日快照，关闭时应新增对应证据。

R0 更新：上述三条问题和待提交源码已在代码提交 `6e060ff` 收口，新增回归及干净提交验收见 [R0 证据](../evidence/r0-review-closeout-2026-10-03.md)。此结论覆盖核心、CLI 包和桌面 Host 协议，不代表 R0 的全部构建环境差距、真实模型或安装包验收已完成。

待确认项：

- 正式 npm scope、名称和发布账号；本地可打包不代表已取得 npm 发布权限。
- 模型 provider、测试凭证和可接受的真实调用预算；不在文档中写入密钥。
- Windows 安装包签名要求、证书及分发渠道；当前未签名产物不宣称已签名。
- 性能基准与量化阈值；后续平台支持顺序及交付排期。

待核项（产品范围已定）：C01–C04 在冻结上游中的存在性、模块映射与调用依赖；凭证与官方账号的边界；遥测数据及目的地；远程认证和本地 IPC 校验的保留路径。核验结果同步回填能力矩阵，不因产品决定而勾选“上游已核”。
