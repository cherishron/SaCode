## 1. 定位、用户与成功标准

SaCode 的主定位是面向开发者的**可信、可控的 AI 编程工作台**：独立桌面端配套 CLI，内置代码编辑，以中央 Agent 对话、计划、委派和执行详情为主，以右侧可扩展工作台辅助完成开发任务。以自有 Agent 为主，通过 ACP 委派外部 Agent；用户自带 API Key，沿用既定模型池与上游路由机制。核心价值是范围内自主执行、基于证据验收、可核对的权限与数据去向，以及不重复副作用的恢复，而非单纯增加功能数量。

参考 DSH 的成熟能力与交互，不承诺完整行为、数据格式或插件源码兼容。产品目标覆盖 Windows、Linux、macOS 与鸿蒙：前三者的桌面采用 Electron，鸿蒙 CLI 保留、前端后续采用独立 ArkTS/ArkUI 项目。各平台、架构与入口单独验收，不能由工具链文档或 Windows 通过推定其他平台可用，见 [平台与分发矩阵](platform-and-distribution.md)。

| 用户 | 场景与结果 |
| --- | --- |
| 桌面开发者 | 用对话驱动项目任务，直接修改工作区，在编辑器、差异和 Git 提交区审查与修正 |
| CLI 开发者 | 在终端执行同一类任务，获得明确授权、退出结果、用量与恢复语义，不依赖桌面进程 |
| 远程开发与运维使用者 | 明确目标环境后执行 SSH 命令、部署、软件安装和数据库操作 |
| 扩展作者 | 本地编写、安装和管理插件、技能、连接器与智能体，经稳定边界贡献能力 |

成功标准采用可验证的用户结果，不编造商业指标或交付日期：

- 本文 F01–F21 共 21 个能力域全部保留并具备需求追踪；不是 21 个测试，也不据此计算完成率。
- 每域至少完成正向、失败和恢复/越权三类验收，未执行项明确登记。
- 核心链路完成“提出任务→执行→修改文件→验证→审查差异→显式暂存/提交”；失败不能假报成功。
- 凭据明文进入普通日志、布局配置、模型可见提示或发布资产的数量必须为 0。
- 每项最终能力都有实施归属；分批交付只改变顺序，不隐性删除范围。

## 2. 产品边界与已确认约束

1. AI 在授权范围内直接写入工作区，随后审查差异；不强制每次先生成待确认补丁。
2. 手动编辑与 AI 编辑并存，冲突必须可见；撤销不能覆盖用户或其他执行者后续写入。
3. 自有 Agent 组织主任务、委派和验证；外部 Agent 是协作者，其自述成功不是完成证据。
4. 所有列出的功能都是最终必备能力，不以“可选插件”措辞降级产品范围。
5. “一切皆插件”保留为架构要求；内置功能可随包提供，业务能力按契约装配，安全基础机制不能被插件绕过。
6. 用户本机使用不依赖 SaCode 或 DSH 官方账号和订阅；第三方服务仍遵守其认证与收费要求。
7. Git 提交/推送、远程部署、软件安装、数据库写入和电脑操控具有明确的独立授权边界；打开面板或建立连接不等于授权执行。
8. 不承诺外部 CLI、SSH 环境、数据库驱动在各平台能力相同；支持程度和前提逐项呈现，不删最终目标。鸿蒙调试 shell 和普通应用沙箱分别核实。

### 2.2 既定专项功能与方案衔接

- **ACP 必备**：真实委派外部 Agent，逐产品核能力、审批、进展、取消、恢复与冲突；参考 §4.4，不因主定位改变删入口。
- **LSP 必备**：真实语言服务的语义能力与诊断回喂，参考 §4.3；文本工具仅是明确标注的回退，不代替语言服务验收。
- **SSH 必备**：真实连接、主机身份、凭据、远程执行与中断结果管理；执行未知不盲重发，部署/安装独立授权，保留 F15 完整范围。
- **扩展市场**：Skill、MCP、Plugin 的发现与完整生命周期，以及本地导入/自定义来源，见 [扩展市场方案](../plans/sacode-extension-market-2026-10-11.md)。MCP 工具从实际连接动态发现并进入核心授权链，不是独立下载商品。
- **本地 Agent 预设**：内置标准、PTC、极简、创造模式与自定义、AI 辅助创建，见 [Agent 方案](../plans/sacode-local-agent-presets-2026-10-11.md)。Agent 不作为市场第四类；同一运行时下配置工具和工作方式，不能用预设扩大权限。该方向更正 F12 中“智能体”可能被理解为市场商品的歧义。
- **自身性能监控**：监控 SaCode 自身而非目标应用，纳入 F20 的诊断能力，见 [性能监控方案](../plans/sacode-self-performance-monitoring-2026-10-11.md)。平台不支持项明示，不用估算冒充实测。

以上方案保留为专项细节；与本轮明确选择冲突时以本节为准。共享核心、CLI/桌面交互形态与中文交互保留；Windows/Linux/macOS/鸿蒙的平台及前端差异按 2026-10-13 平台决策执行，各平台和各入口独立取证。

### 2.3 完整任务与交付验收

任务主线为：选择项目/预设/模型池→确定目标与验收→确认任务范围→检索并核当前源码→计划和执行→必要审批→修改与验证→差异审查→证据化结算。提交、推送及部署在独立授权后执行，不作为每个任务必然发生的最后一步。

并行/外部任务在隔离目录产出改动，先核归属和冲突、经确认合入，再在最终目标工作区验证；隔离目录的绿灯不能代替合入后的验证。取消、预算耗尽、中断、未通过验收和等待批准均保留真实状态，不混称完成。

完整产品验收需要 F01–F21 的正向、失败、恢复/越权证据，加上上述专项方案；固定源码可构建、依赖齐备，产物可追溯到源码，桌面与 CLI 的适用能力一致。测试、界面、真实服务、安装交付与目标平台证据分别标注；历史产物或工作区未入库实现不替代固定提交验收。此为验收要求，不是当前完成声明。

### 2.4 平台、安装与自动化构建决策（2026-10-13）

- Linux 桌面必须可完成真实开发任务，不以 electron-builder 生成包或 CLI 的帮助输出收口。Host、文件持久化、判活/取消、执行监督/隔离、路径/数据根和运行库加载均须实际适配。
- macOS 保留同一共享核心与 Electron 路线的适配位置；当前无设备，工具链、打包与运行分别登记，不虚构已通过。
- 鸿蒙 CLI 是必备目标，先核 OHOS native SDK、匹配的仓颉编译器/运行库和 stdx，再验证独立可执行文件与项目交叉构建；不把 Linux GNU 产物当 OHOS 产物。鸿蒙前端后续独立 ArkTS/ArkUI 立项。
- CLI 采用 npm 薄启动包与原生平台包的便捷安装路线，同时保留独立原生产物/校验和；其他通用渠道在适用性核实后接入。没有发布记录不能宣称可从 registry 安装。
- GitHub Actions 负责固定提交的多平台构建、打包与产物取证；workflow 实现、产物上传、GitHub Release 和 npm 正式发布分开授权。缺设备不填 PASS，也不从最终支持范围删平台。
- codex 入口/ACP/LSP/当前交付线与平台线先协调公共文件归属；本轮文档更新不授权自动安装 SDK 或发布产物。具体要求与当前限制统一见 [平台支持与分发要求](platform-and-distribution.md)。

## 3. 信息架构与 UI 工作台

### 3.1 左侧导航

顶部为搜索、新建会话；主体为可展开的项目会话树，支持置顶、重命名、归档及状态提示。按工作模式筛选只改变对话列表，工作区始终共享；隐藏会话中的待审批事项仍有提醒。

会话树下方、底部身份区上方固定知识库、自动化、扩展、连接入口。底部固定本机头像与昵称以及独立设置图标；点击头像昵称打开可配置常用入口的快捷菜单。本机资料不等于云账号登录。

管理入口打开中央管理页面，返回时恢复会话、草稿和右侧布局；不销毁进行中的任务。

### 3.2 中央 Agent 区

中央始终是开发主线：Agent 对话、计划、委派、执行详情、审批和结果。头部显示项目、任务、工作模式、主执行者与目标环境，并提供目标入口、Workspace Actions、停止和查看改动。

工具摘要在对话中呈现，完整代码、长输出、文件和网页详情按需打开右侧标签。结果到达不得抢输入焦点或替换正在编辑的标签。

输入区包含草稿引用、附件、语音、提示词增强、模型与权限、上下文状态和发送/停止；消息队列位于输入框上方。计划、目标和待办是不同对象，不能用同一状态替代。

### 3.3 右侧停靠工作台

辅助能力全部归入右侧，不采用编辑器占中央、聊天挤侧栏的 IDE 布局，也不设置独立常驻底部终端。

- 右侧支持添加标签、搜索标签类型、关闭、重排、设为常用、溢出列表、上下拆分及聚焦放大。
- 常用标签是持久入口，不等于实例常驻或后台服务自动启动。
- 文件、查询、终端和网页可有多个实例；相同资源默认聚焦已有实例。
- 关闭标签、断开连接、停止任务分别处理；运行中或未保存内容须给出明确选择。
- 标签默认单组，可上下拆成两组；退出聚焦模式恢复原布局。
- 标签显示项目/任务归属，SSH、数据库、浏览器显示真实目标。切任务不允许迟到结果污染新任务。

| 标签类别 | 必须包含 |
| --- | --- |
| Agent 上下文 | 记忆、子智能体、技能与 MCP、来源、产物 |
| 代码与版本 | 文件结构、文件搜索、多标签编辑、文件预览、差异审查、Git 变更与暂存区 |
| 执行与验证 | 终端、构建与测试输出、安全扫描结果 |
| 网页与操控 | 网页查阅、内置浏览器、电脑操控状态；保留后续设计平台操作的扩展位置，不声称已支持 |
| 数据与远程 | 数据库对象/查询/结果、SSH 会话、部署详情 |

### 3.4 视觉、窄窗与无障碍

亮色、深色、跟随系统共用语义令牌；界面、对话、编辑器、终端字号分别可调。保留 SaCode 品牌与中文固定文案，不另换已指定组件技术栈。

导航与右侧可折叠、可调宽；空间不足时先收导航，再以“对话/工作台”切换保持可操作性，不强挤三列。布局切换不丢草稿、未保存文件或终端会话。具体尺寸由原型验证后冻结，不把建议尺寸当实测。

所有核心流程可键盘完成，焦点可见、标签具可读名称，弹层关闭归还焦点；普通文字对比度至少 4.5:1，运行状态不能只靠颜色表达。

### 4.1 队列与目标状态规则

队列至少区分排队中、编辑中、提交中、已接收、已处理、提交失败和已取消；编辑和消费通过版本/独占规则避免竞态。即时补充在当前轮安全点接收，不等于强制打断；当前执行者不支持时明确拒绝并保留消息。停止是独立控制动作。

目标区分未启用、运行、暂停、受阻、完成和已结束；编辑具有修订，完成证据绑定当前目标修订。轮次/时间/费用阈值、无进展与失败策略可配置但有边界，不允许无限自动重试。自动化触发目标与人工启动采用同一权限规则。

### 4.2 压缩与引用规则

上下文占用、请求用量、累计消耗不能混用；容量与价格来自所选模型可用能力，未知则显示未知。压缩摘要保留目标、未完成计划、审批限制、重要工具结果和来源；原历史可查看，压缩后模型请求实际采用的新上下文须可追踪。安全点外请求压缩先排队，不破坏未结算工具关联。

附件、文件选区、知识、记忆、批注和技能引用在草稿中可查看/移除；采用发送时快照或后续读取的语义明确，版本失效不能静默吞掉。队列编辑和转即时补充保留附件绑定。

### 4.2.1 知识与记忆的代码理解闭环（2026-10-11 补充需求）

知识与记忆必须服务真实开发任务，不以保存文档、生成 Wiki 或展示检索结果作为完成标准。本节定义目标与验收，不宣称已有实现。

- **分工明确**：知识提供可核对的源码、架构资料及设计依据；项目记忆保存经确认的约束与历史决策；个人记忆保存跨项目偏好。记忆不替代实时读代码、检索或 LSP，不缓存密钥。
- **来源可核**：代码知识绑定项目身份、路径/符号及内容修订或摘要；历史决策保留来源与适用范围。源码更新、符号改名、来源删除后，关联索引与派生知识须失效或更新，不能继续以旧知识作当前事实。
- **使用闭环**：任务提出后，在授权范围内检索相关知识、核对当前源码、选择有界上下文并注入实际模型请求；界面能展示引用来源及修订。只显示面板但未影响请求，不算接通。
- **冲突处理**：历史记忆与当前代码不一致时，先核对并说明冲突；当前代码决定实现事实，用户确认的目标约束不能因代码暂未满足而被静默删掉。检索正文中的指令不能改变授权策略。
- **结果验收**：建立冻结仓库任务集，覆盖符号定位、跨文件调用解释、修改影响分析、项目约束遵守及源码变化后的纠错。每题有人工核定的源码/测试依据，分别记录回答正确性、引用有效性、遗漏与错误关联、重复检索及 token/耗时。
- **效果对照**：在同一源码快照、模型与工具条件下，对知识/记忆启用与关闭做配对重复测试，记录模型非确定性；检查实际请求确实使用引用且输出遵守来源约束。只有固定任务集显示代码理解改善、且权限隔离和失效处理无回退，才能声明有效；验收前冻结任务集与判定规则，不编造提升比例或将检索命中率等同任务正确率。
- **反向验收**：注入过期符号、无关高相似文档、跨项目敏感资料及伪造指令，必须分别识别失效、排除无关、阻止泄露和拒绝越权；检索失败时回到实时源码工具并明确说明，不假称已有知识支撑。

### 4.3 LSP 语义工具架构与分阶段实施

SaCode 自有 Agent 通过 LSP 获得语义级代码理解能力，不弱于 OpenCode 等竞品。核心不 spawn 任何 language server——核心只定义 verb 契约，language server 由语言专用插件装配（"一切皆插件"约束）。仓颉 LSP server 缺失只影响"用 SaCode 开发仓颉代码"场景，不影响 TS/Go/Python 等语言。

**七个 verb 契约**（六类语义查询与 rename 变更提案）：查询仅在已授权项目内使用；language server 安装、启动及其可能执行的项目代码另受信任与授权约束，不因查询免审批而获得任意执行权。

| verb | LSP 方法 | 用途 | 审批 |
| --- | --- | --- | --- |

**架构约束**：
- 核心不引用任何具体 language server 的进程名、端口或协议细节

### 4.3.0 LSP 产品子范围与协议边界（2026-10-11）

以下归 F21，并与 F08 编辑、F11 知识及 F12 插件共用项目身份、版本、信任和授权。七个 verb 是 SaCode 内部动作，不是七个服务器必然支持的标准方法；各语言按实际能力验收，文本回退不能冒充语义结果。上文“不弱于竞品”为产品目标，不是本轮对比实测；仓颉服务状态以及 TS/Go/Python/Rust 的具体支持均须逐服务核实，不能由语言名推定可用。

| 服务管理与信任 | 插件配置/启停/健康状态/重启，显示来源、服务版本、语言、项目根与平台 | 安装与启动明确授权；不执行未信任项目配置，不静默下载程序；服务可能加载项目代码/插件，语义查询免审批不代表进程无限权限 |

| 诊断与更新 | 按能力消费推送或拉取诊断、相关文件及完整/未变报告，展示严重度/来源/代码 | 无版本的推送不得伪造版本，保留关联与陈旧/未知状态；空推送清除该来源旧诊断，拉取 unchanged 复用对应 resultId，崩溃或撤服务不能留下“当前”旧诊断 |
| rename 与编辑提案 | prepareRename 支持时先检查，展示跨文件 WorkspaceEdit、版本、资源操作及用户选择 | rename 不直接落盘；未带版本的编辑也需本地观察摘要核验；重叠范围、陈旧版本、越界 URI、未支持资源操作拒绝，不只应用合法子集后报整体成功 |
| 服务反向请求 | 受控处理配置、工作区目录、动态注册、`workspace/applyEdit` 与服务消息 | 只返回授权且必要配置，不泄露密钥/全部环境；applyEdit 同样走审查，未应用不回 applied=true；不支持的请求明确响应，服务请求不能自动执行任意命令 |
| 取消与故障恢复 | 超时与 `$/cancelRequest`，服务崩溃、退出、重启及重新同步 | 取消通知非停止证据；终态仍需响应，部分结果标不完整；旧实例回执丢弃或归旧请求；重启不自动重放编辑/命令，重试只读须核当前文本 |
| 实际模型消费 | 诊断/语义结果经有界选择进入真实请求，提供来源，任务结束验证真实改动 | hover Markdown、诊断正文和源码视为不可信数据，不执行链接/指令；截断明确，无索引/不支持/采样失败不同于零风险或无错误 |
| 双入口与收尾 | 桌面导航/缓冲与 CLI 的语义动作共用契约，明确 CLI 文本来源；按需懒启动与停用清理 | CLI 不假装拥有桌面未保存缓冲；`shutdown` 响应后发送 `exit`，超时仅处理自有实例；服务停用不删除工作区/知识，会话监听和子进程需收尾 |

### 4.3.2 数据库工作台子范围（2026-10-11 需求细化）

F16 必备支持 MySQL、PostgreSQL、达梦，三种引擎各自以真实驱动和服务验收，不能用一种通过推定另外两种。以下为产品要求，不代表现有实现。具体引擎/驱动版本及客户端平台矩阵实施前冻结；方言和事务差异由适配器显式表达，不伪装统一支持。

| 子范围 | 必备动作与结果 | 安全及失败边界 |
| --- | --- | --- |
| 连接管理 | 创建/编辑/测试/连接/断开连接，明确引擎、主机、端口、数据库、用户、TLS 与项目归属；多个实例独立 | 连接不等于写授权；测试不改业务数据；凭据独立保存引用，TLS/证书错误不得通过关闭验证绕过 |

| SQL 编辑与查询 | 手动编辑与 Agent 生成 SQL，执行获准只读查询，展示执行目标、结果集、列类型、耗时、错误及实际统计 | SQL 不靠字符串前缀判断只读；CTE、函数、存储过程与多语句可能有副作用。结合真实只读账户/服务端事务约束限制，无法确认则拒绝或要求写授权，不宣称任意 SQL 静态分类绝对可靠 |
| 可视化数据编辑 | 新增、修改、删除记录，先展示待提交变更；使用键和观察版本定位，值参数化 | 写入单独授权；无可靠唯一定位拒绝逐行编辑；并发改变时拒绝陈旧写，不能覆盖整行未知变化；标识符受验证/正确引用，不当值参数拼接 |
| 写 SQL 与 DDL | 明确目标与影响后执行获准 DML/DDL/过程调用，显示真实影响行数与结果 | destructive 动作单独提示；解释隐式提交和不可回滚 DDL，不能承诺三引擎均可事务撤销；不因 SQL 从 MCP/终端发起绕过授权 |
| 事务 | 明确自动提交状态；显式 begin/commit/rollback，显示事务所属连接与状态，避免连接池切换破坏归属 | 未提交变更可见；关闭前提示；事务固定连接，取消语句后是否事务失败按引擎报告；提交响应丢失标结果未知，不自动重提 |
| 结果导出 | 选择列和范围，CSV/JSON 导出，显示预览、行数、截断及完整性；用户确认本地保存路径 | 导出独立于查询授权说明数据去向，不覆盖未知文件；取消/失败不报完成；CSV 默认防公式注入并说明转换，敏感字段按权限处理，非靠日志脱敏代替数据访问控制 |
| 执行取消与资源 | 有界超时、用户取消、分页游标及连接清理；可观察锁等待/取消结果时如实呈现 | 点击取消不是服务端停止证据；无法确认显示未知；断连不自动重放写入；不为清理杀死无关会话 |
| 项目/任务隔离 | 查询、结果、待编辑缓冲和事务绑定连接实例与任务；切换项目不会串结果 | 撤权后后续动作被拒，已有副作用单列；旧任务回执不显示到新目标；应用重启不恢复活事务或自动执行 SQL |
| 历史与审计 | 保存必要操作身份、引擎、目标、权限、结果和事务关联；提供脱敏历史与用户主动保存的 SQL | 默认不记录凭据、结果正文和含敏感字面值的完整 SQL；详细取证单独开启仍不记录密钥；错误信息也需脱敏 |

手动 SQL 与 Agent 工具共用目标和授权规则；只读是默认模式，不是永久禁止写入。通过独立授权开放可视化编辑、写 SQL 与结构变更。SSH 隧道若另行配置，隧道身份与数据库 TLS/认证分别核验，不能因 SSH 已信任自动信任数据库。

本范围不自动包含 DBA 全套运维、备份恢复、数据复制、集群管理或自动迁移执行；这些不能用“数据库支持”笼统宣传为已具备。数据库写入验收只在自有测试实例/数据进行，不在生产库注入破坏夹具。

### 4.4 ACP 协作架构与分阶段实施

SaCode 自有 Agent 作为 ACP Client，委派任务给外部 Agent（OpenCode、CodeBuddy CLI、Qoder CLI）。SaCode 经 JSON-RPC 2.0 与外部 Agent 进程通信——SaCode 是 Client 侧，外部 Agent 是 Agent 侧。核心定义委派契约与生命周期管理，不实现任何外部 Agent 的内部逻辑。

**协议版本与方法边界（2026-10-11 官方文档核对）**：以本次读取的 v1 文档定义基础接入，按连接协商版本；v2 整体仍标为草案，不能将其方法、字段或完成语义混入 v1。具体实现前还须冻结官方 Schema 修订与各外部产品版本，本节不是运行通过记录。缺失的可选能力视为不支持，SaCode 只声明实际可执行且已受控的客户端能力。

| 方向/用途 | v1 文档方法与边界 | v2 迁移文档差异 | SaCode 要求 |
| --- | --- | --- | --- |
| 双方初始化 | `initialize`；`protocolVersion`、`clientCapabilities`、`agentCapabilities` | 能力统一为 `capabilities`，实现信息统一为必填 `info` | 协商结果绑定连接实例；不支持返回版本时关闭连接并提示，不静默混用 |
| Client→Agent 认证 | `authenticate`；使用公布的 `methodId`，终端认证另走交互流程；`logout` 须声明支持 | 改为 `auth/login`、`auth/logout` | 按认证类型处理，不假设无认证或统一环境变量；不采集凭据后任意转发 |
| Client→Agent 会话创建 | `session/new`；绝对 `cwd` 与明确的 MCP 配置 | 会话字段调整，MCP 列表可省略 | 委派目录、授权和外部 `sessionId` 显式绑定；MCP 配置不自动获准启动 |
| Client→Agent 历史与恢复 | `session/load` 须支持 `loadSession`，响应前重放历史；`session/resume` 须支持 `sessionCapabilities.resume`，不补播历史 | 移除 load；resume 可用 `replayFrom` 请求重放 | 恢复能力按版本核验，重放不再次执行工具或重复计量；重启继续仍需确认 |
| Client→Agent 列表与关闭 | `session/list`、`session/close` 按对应支持条件调用；close 不等于删除历史 | 声明会话能力时 list/resume/close 等成为基线要求 | 未声明方法不尝试；关闭标签、取消轮次、关闭会话、退出进程及删除历史分开 |
| Client→Agent 任务与取消 | `session/prompt` 返回 `stopReason`；`session/cancel` 为通知 | prompt 返回仅确认消息接纳；前台状态/停止原因由 `state_update` 报告 | 发送成功不等于完成；v2 的 idle 不证明后台全部停止；未知副作用不重放 |
| Agent→Client 授权 | `session/request_permission`；按提供的 `optionId` 返回选择或取消 | 方法同名，权限描述字段调整 | 权限请求不是执行代理；不认识的结果不视为批准，记忆式允许不能扩大全局授权 |
| Agent→Client 进展 | `session/update`；消息、工具调用、计划等分别投影 | 更新按身份合并，缺省/空值/追加语义改变 | 工具和消息按委派身份关联，保留版本差异，不将未知类型当成功 |
| Agent→Client 文件 | `fs/read_text_file`、`fs/write_text_file`；分别声明能力，读取可含未保存缓冲 | 移除客户端文件方法；客户端工具改由明确配置的 MCP 提供 | v1 请求仍核目录、观察版本与缓冲冲突；v2 MCP 路径遵守同一核心授权 |
| Agent→Client 终端 | `terminal/create`、`terminal/output`、`terminal/wait_for_exit`、`terminal/kill`、`terminal/release`；须声明终端能力 | 移除执行接口；Agent 自有终端通知仅用于显示 | kill 与 release 分开；显示终端不等于有输入、resize 或终止能力，不能照搬 F09 控制承诺 |
| 会话配置 | `session/set_config_option` 与 `config_option_update`；只消费真实提供的选项 | 专用模式 API 移除，模式经配置表达 | 外部模式/模型选择不改变 SaCode 权限；外部模型及费用不伪装为本机模型池结算 |
| Agent→Client 信息征询 | `elicitation/create` 按已声明 form/url 模式处理，URL 完成可用 `elicitation/complete` | 按所冻结版本另核字段 | 拒绝与取消分开；表单不得收集密码/密钥，打开 URL 的同意不等于认证已完成 |

**进展投影要求**：消息、工具状态与结果、计划、可用命令、配置和实际可获得的终端输出分别路由至中央委派卡片及右侧对应标签。外部命令带执行者命名空间，不能覆盖本机斜杠命令；未知更新保留有限诊断并提示兼容问题。正文、链接、路径、终端控制序列和厂商元信息均是不可信输入，不执行其中的指令，不将外部状态直接写成 SaCode 任务完成。

**逐产品接入核验**：OpenCode、CodeBuddy CLI、Qoder CLI 都保留为必备接入目标，但本轮只核官方 ACP 通用契约，未核三者的当前发行版与真实运行。

| 产品 | 接入前必须冻结 | 本轮证据边界 |
| --- | --- | --- |
| OpenCode | 官方安装/启动入口、产品版本、协商版本、认证方式、会话与工具能力、许可及平台要求 | 待产品官方文档/源码与真实实例核验；撤销旧表笼统“标准”与未经复核的启动命令作为既定契约 |
| CodeBuddy CLI | 同上，并逐项核 `_meta`、团队/多任务、配置与权限扩展的实际 Schema | 旧表的启动参数、认证端点、`multitaskSupport` 和团队字段仅是历史候选，本轮不背书，不能据此生成适配器 |
| Qoder CLI | 同上，确认实际 ACP 入口、支持版本、认证及取消/恢复行为 | 待产品官方证据和真实实例核验；不得复用当前工具会话的私有连接或登录凭据 |

各产品分别建立“官方出处/修订→安装版本→初始化实测→真实任务”的支持矩阵；缺某方法不代表整个产品不支持 ACP。最终必备用户动作未闭合时登记 BLOCKED 与解锁条件，可选协议方法缺席不伪造支持，也不能借适配差异删除既定产品目标。

**分阶段实施**：

| 阶段 | 内容 | 依赖 |
| --- | --- | --- |
| A1 契约与进程管理 | 核心定义 ACP Client 侧接口（`AcpClient`：spawn、initialize、session lifecycle、prompt、cancel）；定义 `AcpDelegate` 投影（委派卡片渲染数据源）；处理 `session/update` 内容块路由；审批转发（`request_permission` → SaCode 审批面） | F02 Agent 闭环 + F12 插件架构 |
| A2 首个 Agent 接入 | 核官方入口并固定 OpenCode 版本；按协商版本验证创建、prompt、进展、审批、取消、支持的恢复与关闭；真实改码和结果验证 | A1 + 已授权且可用的 OpenCode 实例 |
| A3 多产品扩展 | CodeBuddy CLI 与 Qoder CLI 逐产品核官方入口和能力；厂商扩展仅在证据与支持条件成立时接入，不假定团队/多任务或工具代理必然存在 | A2 + 各产品独立前提 |
| A4 并发与冲突治理 | 多委派会话并发、隔离目录、取消恢复、资源收尾与合入后复验；按 §7.5 完成双入口及打包态验收 | A3 |

**架构约束**：
- SaCode 是 Client 侧，不实现任何外部 Agent 的内部逻辑
- 外部 Agent 进程由 SaCode spawn 并管理生命周期（启动/重启/关闭）；默认绑定独立 worktree，所有客户端文件请求和终端请求按委派目录解析，禁止隐式指向主工作区。非 Git 项目使用明确副本或禁止并行写入；准备依赖、复制上下文和合入均保留范围与来源，不能复制凭据或覆盖未知改动
- 委派会话归属绑定到 SaCode 会话；切任务时迟到结果不污染新任务
- `session/request_permission` 进入 SaCode 统一授权策略：已授范围内普通改码按任务授权处理，范围外、高影响或无法判定的动作需确认；服务端权限请求不能自行扩大授权。外部直接操作无法完整拦截时明确披露，不能承诺策略已覆盖全部行为
- 外部 Agent 自述成功不是完成证据；SaCode 验证真实副作用（文件变更、终端输出）后才标记完成
- 外部 Agent 无法被完整拦截的动作（如直接网络请求）明确披露，不能声称统一审批已覆盖
- `session/update` 内容块按类型路由到不同 UI 位置，不全部塞进对话气泡
- 外部 Agent 的 `_meta` 扩展字段按产品逐个适配，不混用不猜
- **委派失败兜底**：外部 Agent 返回错误（额度耗尽、认证失败、进程崩溃、超时、能力不支持）时，SaCode 不自动切换执行者，标明失败原因并向用户提供退路：换其他已配置外部 Agent、本机 Agent 接管或排队等待
- **接管续工作区不续对话**：本机 Agent 接管时，从磁盘当前文件状态作为基线重新读、重新建索引、重新规划，不继承外部 Agent 的会话上下文与中间工具调用记录；外部 Agent 已成功落盘的副作用不回滚，但其自述的"已执行未落盘"步骤不采信。接管后向用户展示"已识别的外部副作用 + 本机 Agent 的新规划"两栏，由用户决定是否继续

### 4.4.1 ACP 委派产品子范围

下列完整范围归 F10，并与 F02/F08/F09/F12 共用授权、隔离、审查与生命周期规则。ACP 协议声明不是系统沙箱，worktree 也不是安全隔离；外部进程直接访问磁盘、网络或启动子进程时，只有实际限制并验证过的边界才可称为强制约束。

| 子范围 | 必备用户动作与结果 | 授权及失败边界 |
| --- | --- | --- |
| Agent 配置与就绪 | 新建/编辑/测试/停用外部 Agent，展示来源、程序版本、平台、启动参数、认证和能力 | 测试会启动程序，须明确授权；不自动运行项目提供的启动配置，不为连接测试隐式安装或调用浮动版本下载命令 |
| 协商与传输 | 本地 stdio 双向 JSON-RPC，按请求 ID 配对；stdout 只接协议，stderr 有限脱敏诊断 | 帧大小、队列、并发与等待有界；畸形帧、错误 ID、EOF、超时分开；远程传输待具体官方契约验证，不冒充标准远程已支持 |
| 认证与数据去向 | 依实际认证类型完成登录/失败重试/支持的退出；展示外部服务、模型及可能发送的项目内容 | SaCode 无账号门槛不免除第三方认证；只传授权且必要的凭据引用/环境变量，不继承全部环境，不把终端认证当 authenticate |
| 委派创建与上下文 | 选择执行者、任务、验收条件、预算和隔离目录；发送有界任务描述与明确引用 | MCP/附件/额外目录逐项获准；只复制明确上下文，不复制凭据或未知未提交内容；外部缺图像等能力时拒绝该输入并保留草稿 |
| 会话与进展 | 委派卡显示排队/执行/待用户/取消中/失败/结果未知/待验证/完成；支持继续对话及实际可用历史恢复 | SaCode 状态是投影而非线上的同名枚举；按版本判终态，能力缺失不静默新建会话冒充恢复，重放与实时更新不重复结算 |
| 授权与信息征询 | 请求绑定会话/轮次/动作，展示目标与风险，支持允许/拒绝/取消及合法信息输入 | 超时、关闭审批、撤权均不得批准；“始终允许”需落到限定作用域，不升级全局策略；敏感 URL 显式打开，不预取或回传秘密 |
| 客户端工具执行 | v1 文件/终端仅在真实可用时声明；v2 通过明确 MCP 工具桥接；展示实际执行责任 | 读写、cwd、链接和终端环境受范围控制；未保存缓冲与磁盘版本分别核；请求权限不等于执行；不可拦截的外部直执行须披露 |
| 取消与资源收尾 | 主任务或单委派停止；在途权限取消，接收合法收尾更新，核真实进程和工具状态 | 发送通知不是已停止；超时后仅按获准策略终止自有进程；关闭会话不删除历史，释放终端不清理无关实例，未知副作用不重发 |
| 失败与恢复/接管 | 认证、额度、进程退出、协议错误、断连分别说明；提供换执行者、本机接管、等待的选择 | 不自动切换执行者；恢复先确认现场和权限；接管从当前磁盘重新规划，保留外部事实用于审查，不伪装继承对话或回滚外部副作用 |
| 并发与合入 | 每个委派独立实例/会话/目录/权限/预算归属，展示产物和冲突，确认合入后再验证 | 不默认同一外部 session 支持并发 prompt；非 Git 用明确副本或拒并行写；不覆盖主目录脏改动，取消某委派不影响其他任务 |
| 完成与费用证据 | 核真实文件差异、测试/运行、验收条件；实际可得用量注明提供方与口径 | 正常 stopReason/idle/外部“完成”均不足以完成任务；费用缺失显示未知，不填零、不与本机模型池重复入账 |
| 双入口与配置清理 | 桌面和 CLI 提供相同配置、委派、批准、停止、查看结果、恢复及接管语义；停用/删除前说明在途影响 | 非交互无批准渠道时拒绝或等待明确输入，不自动批准；删除配置不杀无关进程、不删除项目、会话或供应商凭据 |

## 6. 架构边界约束

这是产品强约束而非详细实现选型：

- 延续仓颉共享业务核心、既定桌面技术栈与独立 CLI；此文不授权另换框架。业务能力、桌面表现与平台适配拆开。
- 工作台框架拥有导航、布局、标签生命周期、焦点与主题；插件拥有其内容，通过规定的页面/工具/命令/设置贡献契约接入，不直接改别的模块状态。
- 生命周期、作用域、任务身份、取消、授权执行、审计和持久化基础机制稳定；内置 Agent、模型、文件、Git、终端、数据库、知识能力按可替换契约装配。
- 会话记录是对话与执行事实真源；文件、Git、数据库、知识及配置各自有明确权威源，不把所有数据塞入会话日志。布局是偏好，不是执行状态。
- 本机/SSH/数据库/电脑操控使用明确目标身份；建立连接不是授权。外部 Agent 无法被完整拦截的动作明确披露，不能声称统一审批已覆盖。
- 桌面和 CLI 共用业务语义，纯视觉功能在 CLI 提供对应数据/动作，不要求同形 UI；按入口记录适用性与测试。
- 常用标签保存用户偏好，项目布局保存资源标识，任务保存执行关联；恢复布局不自动运行命令、连接敏感目标或加载任意第三方代码。

### 7.2 待细化而非重新选型的验收参数

- 固定任务集的题目、答案依据、重复次数、通过规则与知识效果总体判据，在执行前冻结；本轮没有数据支持，不预设提升百分比。
- 必要会话事实、详细模型载荷、性能异常、crash dump 分别规定容量/期限/访问/删除策略；诊断关闭不等于停止必要会话持久化。
- Windows/Linux/鸿蒙逐入口建立适用矩阵；源码可移植、平台接口存在和目标应用实际可用不是同一证据。最终必备能力的未支持项登记 BLOCKED 与解锁条件，不能仅显示不支持就算完整交付。
- SSH 子范围已在 §4.3.1 细化；具体传输/认证适配器及平台支持在实施前冻结，按 §7.3 取证，不将需求存在当作实现支持。

上述参数未定不妨碍其他已明确能力继续设计，但对应验收不能宣称闭合。

### 7.3 SSH 专项验收项

使用自有受控测试主机和测试目录，禁止在生产主机上注入破坏夹具。全部为待执行要求，必须记录客户端/服务端版本、平台、认证/传输方式、实际目标身份及操作结果。桌面和 CLI 对适用动作分别验收，缺真实远端时标 BLOCKED，不用本机模拟替代真实连接证据。

| 标识 | 场景 | 必须结果 |
| --- | --- | --- |
| SSH01 | 创建/编辑连接、测试认证、多实例切换 | 正确主机/用户/端口，测试不执行业务动作；配置重启保留，旧实例回执不覆盖新配置 |
| SSH02 | 首次连接、指纹变化、用户拒绝 | 首次等待确认；变化拒绝继续；拒绝不写为已信任，不关闭校验凑绿 |
| SSH03 | 密钥、口令、密钥口令及认证失败 | 支持项实际认证；失败可解释；秘密不进入 argv、日志、配置导出和错误正文；不支持方式不假成功 |
| SSH04 | 受控远端命令成功/非零退出/大输出 | cwd、环境和执行身份正确；stdout/stderr 与真实退出码准确，截断明确；特殊字符参数不改变命令结构 |
| SSH05 | PTY 输入、resize、Ctrl+C、退出与面板关闭 | 真正交互程序收到输入/尺寸；中断验证远端状态而非只查客户端发送成功；关闭面板不虚报进程结束 |
| SSH06 | 浏览/读取/下载、越界路径和链接 | 文件内容与受控夹具一致；获准根外访问拒绝；超限有说明；已有本地改动不被无提示覆盖 |
| SSH07 | 上传/修改/覆盖及同时远端修改 | 完成后实际字节与源一致；陈旧版本覆盖拒绝；破坏动作等待独立确认；非法权限请求被拒 |
| SSH08 | 传输中取消、断连、续传与源变化 | 展示已传和部分状态，不报完成；临时残留可辨认；源/目标改变后不盲续传；续传不支持时明确拒绝 |
| SSH09 | 受控服务部署、安装失败、健康检查失败 | 独立批准前无副作用；批准后检查真实文件与服务健康；失败报告已做动作和可用恢复措施，不捏造回滚 |
| SSH10 | 命令在执行时断网、客户端超时/崩溃后重启 | 未确认远端结果标未知，不自动重发；应用重启等待用户继续；重连核身份，旧批准失效时重新授权 |
| SSH11 | 并发任务、切项目与撤销授权 | 连接/输出/文件操作按任务身份隔离；撤权后不发起后续动作；已开始动作单独报告停止结果，不声称撤权能撤回已有副作用 |
| SSH12 | 停用/退出与审计导出 | 自有连接、进程、定时器和凭据引用收尾，不清理无关连接；记录可对账且导出不含标记秘密 |

只有上述适用项与实际用户流程都通过，才可认定 F15 SSH 子范围闭合；SshRegistry 状态、命令退出 0 或单条连接测试均不足以证明文件传输、交互终端和部署可用。

### 7.4 数据库专项验收项

DB01–DB12 对 MySQL、PostgreSQL、达梦逐引擎执行，注明引擎/驱动版本、平台、连接身份、授权、事务状态及实际服务端结果。使用隔离测试数据库、测试账户和受控夹具；无法获得某引擎环境时该引擎标 BLOCKED，不借其他引擎或 mock 结果顶替。三引擎方言不要求同一 SQL 原样运行，但用户动作与权限语义须一致。

| 标识 | 场景 | 必须结果 |
| --- | --- | --- |
| DB01 | 配置/测试/连接、TLS 与认证失败 | 正确引擎/目标/用户；测试无业务写入；证书异常不关闭校验；凭据标记不进入 argv、日志、导出和错误响应 |
| DB02 | 对象树、元数据刷新及权限不足 | 表/列/键/约束与真实 schema 一致；权限不足不误报不存在；结构改变后旧缓存不继续作为事实 |
| DB03 | 分页、过滤、排序、NULL、长文本/二进制 | 参数不构造注入；类型/空值/截断准确；行数/字节/时间限额生效，分页不稳定明确提示 |
| DB04 | 普通读取、CTE/函数/过程/多语句等副作用入口 | 真实只读权限拒绝写副作用；未知语义不自动放行；Agent、手动 SQL、MCP 和终端路径不能以调用方式规避授权边界，无法覆盖的外部路径披露 |
| DB05 | 查询成功、语法错误、多结果和长查询 | 正确结果与耗时，错误可读脱敏；结果容量有限，支持的多结果逐一标识，不吞结果后假称完整 |
| DB06 | 可视化新增/修改/删除及无唯一键 | 未批准写不落盘；批准后只改变目标记录；无可靠定位拒绝；NULL 与空串区分，值正确参数化 |
| DB07 | 两个连接并发修改同一记录 | 陈旧观察版本被拒；不静默覆盖新值；显示冲突并重新读取，刷新不擅自提交草稿 |
| DB08 | 自动提交、显式事务、回滚和连接池 | begin/commit/rollback 对实际服务端生效；事务固定连接，未提交状态可见；语句失败后事务状态按引擎真实表达 |
| DB09 | DDL、过程副作用与提交回复丢失 | 操作前明确隐式提交/不可回滚风险；响应丢失标未知，通过状态核对而非盲重试；不承诺未发生的回滚 |
| DB10 | 超时/取消、断连及应用重启 | 核服务端执行是否停止；不确定时明确未知；连接/游标清理不误杀无关会话；重启等待确认，不复活事务或重复写入 |
| DB11 | CSV/JSON 导出、取消、超限与公式内容 | 导出范围/行数/完整性与结果一致；CSV 防公式执行，转换明确；取消不留伪完成文件，不无提示覆盖，不泄露无权限字段 |
| DB12 | 多项目/多连接切换、撤权与审计 | 迟到结果不串目标；撤权阻止后续写入；操作/事务可对账；普通记录无密钥、结果正文或敏感 SQL 字面量 |

按实际最终写入与服务端事务结果验收，界面“提交成功”、驱动调用返回或数据库面板可打开均不能独立证明 F16 完成。

### 7.5 ACP 专项验收项

ACP01–ACP16 对 OpenCode、CodeBuddy CLI、Qoder CLI 逐产品、逐适用入口与平台执行，记录产品/协议/Schema 修订、程序来源、外部认证/模型前提、实例/会话/轮次身份、目录、实际批准、产物及结果。仅在用户授权的隔离项目和自有测试进程中注入故障，不影响另一会话或生产环境；需要第三方付费/账号/程序但未获授权时标 BLOCKED。受控协议夹具检错与真实外部 Agent 委派分层记录，不能互相代替。全部为未执行要求，不是通过记录。

| 标识 | 场景 | 必须结果 |
| --- | --- | --- |
| ACP01 | 配置/测试启动、版本协商及能力缺省 | 实际启动入口可追溯；未信任项目配置不执行；不支持版本断开，缺失能力不调用；v1/v2 方法和字段不混用 |
| ACP02 | 正常帧、分片/合并、交错 ID、畸形/超大帧和 EOF | 正确配对请求与通知，无丢帧串线；协议错误明确终止受影响连接，限制有效；stdout 诊断污染不静默吞成成功 |
| ACP03 | 各认证类型、失败、用户取消及退出 | 正确认证流程，不向终端类型发送 authenticate；秘密不进 argv/普通日志/模型提示/导出；退出后现有任务状态另核，不推断已停止 |
| ACP04 | 创建委派、cwd、额外目录、附件和 MCP 配置 | 真实 session 与隔离目录绑定；超限或不支持内容明确拒绝；未经批准不启动 MCP，不继承多余凭据/环境，不暗指主目录 |
| ACP05 | 真实改码任务、消息/计划/工具流和未知更新 | 改动确由选定外部执行者产生；更新身份/顺序/截断正确；未知内容不执行、不变完成；链接/终端序列不能触发隐式操作 |
| ACP06 | 权限允许/拒绝/取消/超时/撤权、记忆式选项 | 请求绑定正确动作；仅选合法 optionId；未知结果不批准；范围外/高影响独立确认；过期票据不复用，外部直执行限制与披露可核 |
| ACP07 | v1 客户端文件读写、未保存缓冲、陈旧修改与路径逃逸 | 读取来源版本明确；修改前核观察和缓冲冲突，陈旧写拒绝；绝对路径/链接越界拒绝；创建不覆盖外部新文件 |
| ACP08 | v1 终端创建、输出、退出、kill/release 与异常清理 | 真实 cwd/参数/环境正确；输出有限且字符不破坏；真实退出码/信号与未知分开；kill 后可读，release 后 ID 失效，无自有进程残留 |
| ACP09 | 启用 v2 的客户端工具与终端显示适配 | 不发送已移除文件/终端执行方法；MCP 子调用遵守同样审批；终端显示不假报输入/resize/kill 支持；无 v2 实例时仅记录夹具结果和真实验证阻塞 |
| ACP10 | 配置/命令更新及信息征询拒绝/取消/恶意 URL | 选项与命令只属对应执行者；更改不放宽权限；表单拒收秘密，URL 展示完整目标并显式打开，不预取；同意打开不等于认证完成 |
| ACP11 | 运行中取消、等待权限时取消及迟到更新 | 在途权限返回 cancelled，不误批准；v1 等 prompt 取消终态，v2 核相应状态通知；合法收尾更新保留，超时无终态显示未知而非已停止 |
| ACP12 | 进程崩溃、额度不足、断连、重启与历史重放 | 分类准确，无自动重发 prompt/副作用或切执行者；继续前确认现场；load/resume 按版本和能力执行，重放不重复工具/消息/计量，旧批准不复活 |
| ACP13 | 并发委派、切项目、撤权与实例重建 | 会话/工具/终端/预算/结果不串线；单 session 的并发能力未经证据不假定；仅停止目标任务，迟到旧实例更新不能改变新任务 |
| ACP14 | 隔离改动合入、用户并发修改及本机接管 | 冲突不覆盖；合入显式确认并在目标目录复验；接管重新读当前磁盘，不继承外部对话或自动回滚，待执行计划由用户确认 |
| ACP15 | 外部报告成功、预算/费用缺失和实际验收失败 | 正常轮次结束不是任务完成；测试/实际运行失败不能报成功；未知用量/费用不填零、不重复入本机池账；不可强制的外部预算限制明确展示 |
| ACP16 | 桌面/CLI、非交互、停用/关闭/删除与新包运行 | 两入口同授权/归属/恢复语义；无人批准不自动放行；关闭与删除不误删历史/项目/共享凭据；自有资源收尾，固定源码新产物中完成真实委派流程 |

对只存在于某协议版本或能力分支的项目，注明协商版本和能力条件；不适用需有冻结协议/产品证据并说明替代用户路径，不得把必备动作失败改成不适用。关键反证包括：移除目录守卫、允许未知权限结果、把 v2 prompt 接纳当完成、取消发送后直接标停止、重放再次计费、按到达顺序而非 ID 归属结果；对应指定用例必须转红，随后还原复验。反证只针对自有受控适配器/夹具，不改第三方运行实例。

完成 F10 需同时满足真实委派、授权边界、失败/取消/恢复、隔离合入、结果验证及双入口交付；连接成功、initialize 返回、卡片显示或外部自述成功均不能单独作为完成证据。

### 7.6 LSP 专项验收项

LSP01–LSP16 按语言/服务版本、平台和桌面/CLI 适用动作分别执行，记录规范修订、初始化能力、项目/worktree 根、文件 URI、文本/磁盘版本、位置编码、请求及实例身份、真实结果和实际模型消费。使用自有隔离项目；协议夹具验证错误与竞态，真实语言服务验证语义，两层证据不互相替代。无对应服务/平台环境时标 BLOCKED 并列解锁动作，不借另一语言或文本匹配凑绿；全部为待执行要求。

| 标识 | 场景 | 必须结果 |
| --- | --- | --- |
| LSP01 | 插件安装/启动、未信任项目与能力协商 | 未获授权不启动/下载或加载项目插件；来源/版本可核；仅声明真实支持能力，缺能力拒绝对应动作，不假报就绪 |
| LSP02 | 分片头/正文、连续帧、Unicode 字节长度、交错 ID、畸形/超大帧 | Content-Length 按 UTF-8 字节准确解析；无丢帧串请求，错误有界结算；不把 ACP 按行解析器用于 LSP |
| LSP03 | 多根/嵌套项目、同语言主树与 worktree、URI/路径别名和越界链接 | 正确服务/根/文件归属；不同目录索引和缓冲不串线；无权根拒绝，返回根外路径不自动读取 |
| LSP04 | 打开/增量或全量修改/保存/关闭、外部磁盘修改 | 服务看到真实当前缓冲，增量顺序和版本正确；关闭/重开重新核磁盘；未保存内容不被外部旧版本覆写 |
| LSP05 | 中文/emoji/组合字符、UTF-16 及协商编码、CRLF 与跨行范围 | 定义、诊断、编辑位置与实际字符一致，零基/编码转换准确；不以 ASCII 用例代 Unicode 验收 |
| LSP06 | 同名不同作用域、定义多结果及 LocationLink、hover | 真实语义目标和类型正确，不能只按字符串匹配；多结果可选择，空结果不同于服务失败；hover 正文不执行 HTML/链接指令 |
| LSP07 | 跨文件引用/实现、未索引与不支持能力 | 服务输出与受控源码依据一致；范围/声明包含策略明确；缺能力或索引不全不宣称“全部引用”，文本回退单列 |

| C01 | 排除官方注册、登录、账号绑定及其使用门槛；不得作为本地启动、执行任务或恢复会话的前提 | 已核：官方桌面欢迎页存在登录入口（冻结 `apps/desktop/src/welcome-window.ts`、`welcome-api.ts`）；SaCode 不接入。阻断官方账号端点的两入口全流程验收仍待完成 |
| C02 | 若上游存在官方订阅、支付、商业权益或云端额度校验，排除；保留本地 token 用量统计和用户预算约束 | 待核：商业计费与本地计量边界 |
| C03 | 若上游存在官方账号绑定的云同步、云存储或云会话服务，排除绑定；保留本地存储、会话恢复和两入口一致性 | 待核：云服务入口、数据归属及本地替代路径 |
| C04 | 不接入官方账号关联遥测或默认官方上报；遥测默认关闭，后续仅以用户明确启用的可替换服务提供 | 待核：product-telemetry、session-telemetry、otel 的数据、目的地和默认行为 |

以上是已确定的产品裁剪决定，**不是上游确实含有这些功能的事实判定，也不是已完成代码删除的声明**。逐项核验冻结快照的文档、源码、配置与测试后，记录证据路径、调用链、CLI/桌面影响及保留需求；未找到对应实现时登记核验范围和证据，不能直接标成“已移除”。

必须保留模型 API Key 和第三方服务凭证的安全存取、脱敏、轮换；工具审批、沙箱、会话归属与 IPC 校验；远程 HTTP/WebSocket 入口的认证与访问控制；本地用量与预算。不得按 `auth`、`credentials` 或 `token` 名称整模块删除。npm 发布账号和签名证书属于维护者发布条件，不是终端用户登录要求。

63 个模块仍完整保留在矩阵中，裁剪在模块内部需求层登记，不先行删除模块或缩小分母。四个兼容维度分别登记裁剪差异，两个入口采用相同边界；新增排除项需显式裁决。

### 2.4 用户自写插件与本地装配（2026-10-05 用户确定）

用户能够自己编写插件，也能够让 SaCode 协助编写插件，供本人在本地安装和使用；无需发布到 npm、进入插件市场或登录产品账号。市场是可选发现来源，不是插件使用的前提。本能力承接冻结 DSH 的本地包安装、profile 装配与 Creator 路线，不另起仅支持工具回调的替代契约。

| 使用流程 | 必须满足 |
| --- | --- |
| 开始编写 | 提供插件模板、接口说明和可运行示例；说明 Host/Client/MCP 三种接入及实际支持程度 |
| 本地安装 | 桌面选择本地插件目录或包，CLI 提供等价入口；读取身份、版本、依赖和兼容性，不要求上传源码 |
| 配置与装配 | 配置、启停及依赖装配由共享核心管理；区分已安装、已启用与实际运行成功；失败显示原因 |
| 修改与验证 | 用户或模型可修改本人插件；修改后可以测试并重新加载，失败保留可用配置，不伪造成功；启用新代码和安装脚本遵守既定授权契约 |
| 使用与卸载 | 工具、服务及前端贡献经明确扩展点接入；卸载停止接纳新调用、结算在途调用并撤销所属资源；重启后按保存的装配恢复 |
| 发布（可选） | 本地使用不依赖发布。以后发布到公共源沿用相同包契约，市场仅附加发现和分发信息 |

技术栈保持仓颉共享核心 + 既定 Vue/TinyVue/TinyRobot/Next SDK/Electron。JS/TS 插件通过扩展宿主与有限桥接承接，不改变核心技术栈；Client 代码必须满足单 Vue runtime 和 CSP，不以允许 eval 绕过限制。DSH 原生源码兼容、适配后兼容、SaCode 自定义插件三类分别登记，不能把本地回调示例可用称为官方插件已兼容。

当前状态：extjs 已有本地 CJS 工具加载/调用/卸载与取消切片，插件管理页面也已有前端；完整本地包安装、DSH 装配契约、Client 贡献与双入口产品接线仍未验收。交付必须在无开发 SDK 的安装环境完成「写插件→本地安装→实际调用→修改重载→重启恢复→卸载」，并验证失败、取消、重复工具名和资源清理。模型协助写插件还需真实模型取证，不拿内存适配器或示例回显代替。

## 3. 关键用户流程

### 持续目标模式（2026-10-05 用户补充需求）

来源裁决：冻结上游已有 goal 的修订 CAS、active/paused/blocked/complete 状态与编辑/暂停/恢复/完成/清除契约（见[上游逐模块取证](../evidence/upstream-module-reads-2026-10-04.md)的 goal 条目）。这些属于复刻接入范围，不能把整项称为上游没有的新增能力。本轮已核对上游 goal-round-driver 与 tool-goal：自动跨轮、修订围栏、人类输入竞争和模型目标工具属于复刻接入；上游宿主暂停会取消当前轮，用户要求的不打断当前轮作为 SaCode 扩展保留。资源限额及更强证据策略在基线之上扩展；恢复授权、准入计数、模型工具和桌面目标条尚未完整接入。详见[契约裁决与差异](../evidence/goal-upstream-contract-2026-10-05.md)。已有实现按这些契约核对后复用。

用户设定目标后由仓颉共享核心持续驱动模型工具轮次，桌面与独立 CLI 共用 GoalScheduler/GoalDriver/GoalRunner、日志和停止判据。展示目标正文、状态、已完成轮次及累计执行时长；支持建立、编辑、暂停、恢复和删除。控制操作在轮次边界影响后续调度，不强杀当前轮；运行中插话沿用 inbox 步边界或轮次边界送达，不另建前端队列真源。

完成必须有可追溯的真实证据，并绑定开轮时目标修订；模型说「完成了」或工具调用次数增加均不能单独充当完成证明。轮内编辑、暂停或删除后，旧轮证据不得完成新状态。预算、轮数、时长及连续无进展限额由核心停止并落明确阻塞原因，避免无限空转。

验收必须覆盖两个真实入口、跨轮模型执行、轮内插话、控制边界、陈旧证据拒绝、限额停止、崩溃恢复和安装包；真实模型测试在隔离项目内改文件并验证结果。既有 `dsh goal` 断言自测仅证明核心组合，不能作为可操作 CLI 持续执行模式的交付证据。当前核心已有实现及隔离测试，六个目标控制 Host 方法与桌面有限 IPC 已接入（见[目标控制证据](../evidence/goal-control-2026-10-05.md)）；真实宿主/用户 CLI 自动跨轮接线、完成证据与预算通道、桌面目标卡、完整真实模型场景及新安装包仍待完成。

| 流程 | CLI | 桌面 | 共同验收结果 |
| --- | --- | --- | --- |
| 首次使用 | npm 安装后启动，选择项目并配置模型 | 安装启动，选择项目并配置模型 | 无需 DSH 官方账号登录；明确报告缺失模型配置；凭证不出现在普通响应和日志中 |
| 执行任务 | 输入任务，接收流式输出及工具状态 | 在输入区提交，展示流式内容和工具卡片 | 同一核心完成模型、工具与持久化闭环，结果可重放 |
| 审批工具 | 显示目标、参数及风险，作出决定 | 审批卡片显示相同信息并接受决定 | 决定可审计；拒绝、过期或异常都不能执行；一次性授权不能复用 |
| 取消任务 | Ctrl+C 或明确取消动作 | 点击取消或关闭应用 | 回报真实终态；收束执行和扩展子进程，保存应持久化的事实 |

| 检查结果 | 查看摘要、差异、交付文件及失败原因 | 对话和侧栏查看同一组结果 | 摘要来自事实；不将工具失败、落盘失败或中断呈现为成功 |

CLI 的最终命令语法与非交互输出 schema 在接口设计中确定；现有 `seed/stream/tool/...` 自测命令不能替代真实用户任务流程的验收。

## 5. 共享核心与数据要求

1. `core/` 是唯一业务实现来源。CLI 和 Host 调用同一套会话、agent、模型、工具、审批、预算及扩展能力，入口只做交互或协议适配。
2. 会话日志是唯一业务真源。模型可见内容可从日志重建；消息列表、UI 和计量器均为派生状态。
3. `append` 与 `flush` 的可见性不同。对外报告持久化成功前必须完成落盘屏障，失败时不得释放尚未完成提交的写入责任。
4. 所有入口及所有租约获取路径均恢复相同的用量、预算和审批事实；重启与切换入口不能放宽已生效的约束。
5. 用量结算与是否轮询 UI 无关。完成、取消、退出及恢复路径共享明确的结算规则，实际收到的 usage 可追溯，且不重复入账。
6. 文件修改要求先观察、再校验版本、后写入；路径别名不能绕过校验，创建不能覆盖外部新文件，读写结果与控制字符保持无损。
7. 取消必须作用于真实执行链。Host 退出前收束线程、在途调用与扩展子进程，不留下孤儿进程或伪造终态。
8. Electron 渲染层仅访问有限且校验参数的 IPC 面；凭证和本机执行能力留在权威侧。CSP 禁止运行时动态求值，构建产物不得依赖开发环境路径。

完整约束见[总体方案](../plans/plan-deepseek-harness-replication.md)的 18 条架构不变量。存储格式、工具阶段和插件接口须对照冻结上游原文及测试核验；现有自定义实现有差异时登记差异，不倒推修改上游兼容目标。

### 一切皆插件（2026-10-05 用户明确架构要求）

SaCode 必须复刻 DSH 的插件装配架构，不止提供第三方工具安装。模型提供方、工具、目标/待办等业务能力、浏览器/电脑/Office 接入、前端页面与设置贡献、交付预设均通过插件契约组合；框架提供注册、依赖、作用域、配置、通信与生命期机制。默认产品由已装配的内置插件构成，用户无需先去市场寻找必需能力。

- 插件声明身份、版本、依赖与配置，通过框架扩展点贡献服务、工具、远程方法、页面和槽位；依赖决定激活顺序，缺失与冲突显式失败。
- 安装、保存启用配置、依赖满足、实际运行成功是不同事实；CLI 和桌面读取同一核心装配状态，不能各自硬编码不同能力清单。
- 每项注册和资源绑定插件作用域；初始化失败回滚已取得的框架资源；停用或卸载停止接纳调用、结算在途工作、撤销所属贡献。取消通知与物理停止分别取证，不能据撤销目录声称副作用已停止。
- 新插件按契约接入不要求修改 agent loop、Host 方法分派或页面主干；动态扩展通路也必须保持身份、参数及权限校验，不能用任意方法 IPC 代替类型化契约。
- 仓颉共享核心与既定前端技术栈不变。内置仓颉插件可随产品构建，外部 JS/TS 或 MCP 提供方由适配宿主承接；“插件化”不等于所有二进制必须热加载，也不等于无需适配即可运行 Cordis 插件。

现有固定分派、自定义工具回调、状态 marker 和直接挂载页面不构成完整插件架构证明。按冻结 Loader/Scope/Service/effect/Client Modules 契约逐项补齐并验收；不能因暂时实现了普通注册表而把该架构要求降为可选。

## 12. 微信 Channels 绑定（后续规划，2026-10-09 加入）

**来源**：Spike 调查 Qwen Code `channels/weixin` 功能（iLink Bot 双向通道）。
**产品裁决**：作为低优先级（Later）后续功能计入路线图；不纳入当前 MVP 范围，待产品进一步决策后再启动设计与实现。
**技术可行性**：extjs 宿主 + Node iLink Bot SDK 可实现；核心会话日志可作为消息面持久化来源。

### 12.1 功能概述
支持通过微信 iLink Bot 官方 API 将 SaCode 注册为机器人，实现双向私聊通道：
- 用户可发送**文本、图片（需 vision 模型，如 qwen3.5-plus）、文件**给机器人。
- 机器人仅回复**纯文本**（不支持富媒体出站）。
- 仅支持**私聊**，不支持群聊。
- 提供输入状态提示（"..."）与媒体 AES-128-ECB 解密。

### 12.2 绑定与认证流程
1. 用户在 CLI 或桌面设置中执行 `sacode channel configure-weixin`（或对应菜单入口）。
2. 终端/界面展示二维码 URL。
3. 用户用手机微信扫码登录。
4. 登录凭据持久化到独立目录 `~/.sacode/channels/weixin/account.json`（不混入主配置或会话日志）。
5. 会话可能因 errcode -14 过期，需重新扫码。

### 12.3 配置与作用域
- 配置项位于 `settings.json` 的 `"channels"` 数组下，type 为 `"weixin"`。
- 支持 `privatePolicy`（如 `"pairing"`）、`sessionScope` 等策略。
- 绑定与会话解耦：一个微信账号可绑定多个 SaCode 会话；一个 SaCode 会话可绑定多个外部通道。

### 12.4 验收标准（Given-When-Then）
| 编号 | 场景 | Given | When | Then |
|------|------|-------|------|------|
| AC1 | 首次绑定 | 用户未绑定微信 | 执行 configure-weixin 命令 | 展示二维码，扫码后 account.json 生成，状态为已连接 |
| AC2 | 入站文本 | 机器人已绑定且在线 | 用户在微信私聊发送文本 | SaCode 收到消息，写入会话日志，Agent 产生回复 |
| AC3 | 入站图片 | 绑定在线且配置了 vision 模型 | 用户发送图片 | 图片被解密并传递给 vision 模型，Agent 产生文本回复 |
| AC4 | 出站回复 | Agent 产生回复 | 通道在线 | 机器人回复纯文本到微信私聊 |
| AC5 | 会话过期 | 凭据已过期（errcode -14） | 用户尝试发送消息 | 提示重新扫码，旧凭据被清理 |
| AC6 | 群聊拒绝 | 用户尝试在群聊中@机器人 | — | 机器人不响应或明确拒绝（不进入会话） |

### 12.5 非功能要求
- 安全：凭据文件权限 0600（或等效），不在普通日志中出现明文。
- 兼容性：仅 Windows/Linux 桌面端与 CLI 入口；鸿蒙平台暂不纳入。
- 性能：扫码绑定流程 < 30 秒完成；消息往返延迟与普通工具调用相当。

### 12.6 依赖与风险
| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| iLink Bot API 变更或下线 | 中 | 通道失效 | 抽象通道接口，易于切换其他 Bot 平台 |
| 微信审核政策收紧 | 低 | 机器人被封 | 遵守官方使用条款，不做高频/营销行为 |
| 用户混淆「绑定」与「登录」 | 中 | 支持成本上升 | 清晰的 onboarding 文案与错误提示 |
| 群聊误用 | 低 | 体验下降 | 明确文档说明仅支持私聊 |

### 12.7 实施顺序建议（若产品批准启动）
1. 抽象「外部通道」接口（ChannelProvider、bind、send、receive、status）。
2. extjs 宿主实现 iLink Bot 适配器（扫码、凭据管理、消息收发）。
3. CLI 命令 `channel configure-weixin` + 状态查询。
4. 桌面设置页「连接的 Channels」列表与解绑入口。
5. 核心会话日志投影支持 `channel` 元数据与消息来源标记。
6. 端到端集成测试（绑定→消息往返→过期恢复）。

**当前状态**：仅记录需求与 Spike 结论；无实现代码、无设计稿、无排期。待产品明确「是否纳入自有 Agent 入口」后再推进。
